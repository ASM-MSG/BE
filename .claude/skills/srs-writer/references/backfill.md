# 초판 역산 절차

`docs/srs.md`가 없을 때 기존 구현 전체에서 요구사항을 소급 추출하는 1회성 절차. 등재·갱신
모드에서는 읽지 않아도 된다.

## 왜 병렬 추출인가

레포에 스펙이 80건 넘게 쌓여 있어 한 컨텍스트로 전부 읽으면 뒤로 갈수록 앞을 잊는다. 영역별로
나눠 동시에 추출하면 각 에이전트가 자기 영역만 깊게 보고, 리더는 합치기와 정합만 맡는다.
영역 경계가 명확해서(패키지 = 영역) 분할 손실도 적다.

## 소스 4종

| 소스 | 무엇의 정본인가 |
|------|----------------|
| `.claude/docs/status.md` | 구현 현황과 티켓 번호 → **상태 값** |
| `.claude/rules/glossary.md` | 용어 정의와 "정책 결정 이력" 절 → **확정일** |
| `docs/prd/*.md`, `docs/spec/*.md` | 요구사항 문장의 원천 |
| `../LLM-WIKI`의 `02-planning`·`04-decisions`·`03-specs` | 위키에만 있는 확정과 기각 근거 |

## 절차

### 1. 영역 분할

패키지 경계를 그대로 쓰되 한 에이전트가 관련 영역 2~5개를 묶어 맡는다. 검증된 분할:

| 담당 | 영역 |
|------|------|
| 지도 인프라 | GRID · ZONE · REGION · SEARCH · HOTZONE |
| 영상·도감 | VIDEO · MEDIA · COLLECT |
| 게임화·소셜 | BADGE · STREAK · MISSION · NOTI · FRIEND · MOD |
| 인증·비기능 | AUTH · USER · NFR |
| 위키 대조 | (영역 무관, 레포에 없는 확정만) |

### 2. 추출 에이전트 스폰

`general-purpose` 에이전트를 영역 묶음마다 하나씩 백그라운드로 띄운다. 프롬프트에 반드시 넣을 것:

- **소스 읽는 순서** — status.md로 티켓 파악 → glossary로 용어·확정일 → 해당 스펙·PRD.
  전부 정독하지 말고 요구사항이 담긴 절 위주로 읽으라고 명시한다.
- **요구사항 판정 기준** — SKILL.md의 "무엇이 요구사항인가" 표를 프롬프트에 요약해 넣는다.
  이걸 빼면 에이전트가 테이블 구조와 클래스명을 요구사항으로 올린다.
- **수치 보존**과 **폐기 정책 제외** — 구 정책(위경도 등간격 격자, 삭제 24시간 제한, 5초 고정)은
  별도 항목으로 만들지 말고 현행 항목의 근거에 "구 정책 대체"로만 남기라고 지시한다.
- **출력 형식 고정** — 아래 형식 그대로 반환하게 한다. 인사말·설명을 붙이지 말라고 명시해야
  파싱 없이 바로 합칠 수 있다.

```text
### {영역코드}: {영역명}
- {요구 문장} | 상태: 구현됨|진행 중|계획 | 근거: MSG-XXX[, MSG-YYY] ({확정일 YYYY-MM-DD})
```

영역당 5~15개를 목표로 하고 사소한 세부는 상위 요구에 흡수하라고 일러둔다. 안 그러면 스펙의
결정 항목을 그대로 옮겨 100개짜리 목록이 나온다.

**위키 담당은 프롬프트가 다르다.** glossary "정책 결정 이력"에 이미 있는 확정은 중복이니 빼고,
위키에만 있는 것과 레포와 어긋나 보이는 것만 뽑게 한다. 파일명에 공백이 있어 `find -print0`이나
따옴표가 필요하다는 것도 알려준다.

### 3. 병합

에이전트 결과를 모아 하나로 합칠 때 리더가 판단할 것:

- **영역 간 중복** — 같은 요구가 두 영역에서 나온다(친구 도감 레이어가 COLLECT와 FRIEND 양쪽,
  뱃지 지급 훅이 BADGE와 COLLECT 양쪽). 주 소유 영역 하나를 골라 남기고 다른 쪽은 지운다.
  판정 기준은 "이 요구가 바뀌면 어느 영역의 코드가 바뀌나"다.
- **위키 대조 결과** — 어긋남으로 보고된 항목은 CLAUDE.md 충돌 규칙으로 가른다. 검증 가능한
  사실이면 코드가 이기고, 정책이면 확정일이 최신인 쪽이 이긴다. 못 가리면 양쪽을 병기해
  사용자에게 올린다.
- **ID 부여** — 영역별로 01부터 매긴다. 이 시점 이후 ID는 불변이다.
- **상태 검증** — `구현됨`으로 온 항목이 실제로 status.md에 있는지 표본 확인한다. 에이전트가
  스펙 문장을 보고 구현됐다고 단정하는 경우가 있다.

### 4. 검수 요청

초판은 규모가 커서 사용자 검수 없이 확정하지 않는다. 보고할 것:

- 영역별 항목 수와 총계
- 위키 대조에서 나온 어긋남과 처리 방식
- 판정이 애매해 뺀 항목 (뺐다는 사실을 알려야 사용자가 되살릴 수 있다)

커밋은 사용자 몫이다.
