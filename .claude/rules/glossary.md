# Glossary — 도메인 용어 정의

FillMap 프로젝트에서 사용하는 도메인 용어의 공식 정의. 코드·문서·기획·발표에서 동일하게 사용한다.

**범위 명시**:
- ✅ **MVP 확정 용어** — 지금 즉시 강제 통일
- 🛠 **백엔드 전용 개념** — 사용자에게 노출되지 않음
- 🚧 **Phase 2+ 미확정** — 향후 논의 필요

---

## ✅ MVP 확정 용어

### 격자 (Grid)

**정의**: 국토 평면 좌표계 EPSG:5179 위에서 100m 간격으로 나눈 하나의 셀. **전국 어디서나 100m × 100m**다
(투영 오차 수준 제외 — 아래 "격자 계산 규칙" 참조).

- 5179 평면 상 `(grid_y, grid_x)` 인덱스로 유일하게 식별
- `grid_id` 문자열 포맷: `"{grid_y}_{grid_x}"` (예: 강남역 `"19443_9582"`) — **개념/코드 레벨의 논리 식별자**
- 물리적으로는 항상 존재하는 논리적 개념
- DB 저장 여부는 별개 → **grids 테이블에 row가 있음 = "누군가 영상을 올린 격자"**

**DB 저장 키 = `grid_id` 컬럼 (MSG-78 확정)**: 실제 스키마(`V1__init.sql`)에서 격자 키는
`grids.grid_id VARCHAR(20)`(PK)이며 `videos` · `user_grids` · `sponsor_ads`가 이 컬럼을 FK로 참조한다.
저장되는 값은 **표준 geohash가 아니라 자체 100×100m 양자화 키** `"{grid_y}_{grid_x}"`다 — 논리 식별자와
저장 키가 동일하다. 인코딩 규칙의 단일 진실 원천은 코드의 `GridEncoder` / `GridConstants`
(`com.msg.fillmap.grid`)이며, `geohash`라는 명칭은 코드 심볼·DB 컬럼에 새로 쓰지 않는다.

### 점령 (Occupation)

**정의**: 사용자가 특정 격자에 **첫 영상을 업로드한 상태**.

- `user_grids` 테이블에 (user_id, grid_id) row가 생성됨 (UNIQUE 제약 `uq_user_grids`)
- 도감에 격자가 색으로 표시되는 시점 = 점령 시점
- `first_collected_at` 컬럼에 최초 점령 시각 기록
- **MVP에는 개인 점령 하나만 존재.** (전역/친구 점령 개념은 백엔드 내부용)

### 방문 (Visit)

**정의**: 사용자가 특정 격자에 영상을 업로드한 **이벤트 하나**.

- DB 테이블: `videos` (1 row = 1 방문)
- **첫 방문 = 점령**: `user_grids` row가 생성되는 방문
- **재방문**: 이미 점령한 격자에 다시 업로드하는 방문 → `video_count++`, `last_uploaded_at` 갱신

### 영상 (Video)

**정의**: 방문 시 업로드되는 짧은 영상 하나.

- **길이**: 자유 길이, **최대 30초 제한** (초기엔 "5초 고정"이었으나 자유 길이·30초 상한으로 변경)
- **입력 소스 2종**:
  - **갤러리 선택 업로드** — 기존 영상 선택 (위치 제약 없음, 메타데이터 좌표로 격자 매핑)
  - **카메라 촬영 업로드** — 앱 내 현장 촬영, **사용자가 실제로 그 격자에 있을 때만 가능** (GPS 검증)
- 업로드 후 **수정·삭제 자유** (삭제 시 점령 롤백 규칙 적용)

### 친구 공개 (FRIENDS)

**정의**: 영상 공개범위(`videos.visibility`) 3값 중 하나 — 소유자 본인과 **ACCEPTED 친구(방향 무관)** 만
재생할 수 있는 상태. 나머지 두 값은 PUBLIC(전원 공개)·PRIVATE(본인만).

- 지정: 업로드 확정·공개범위 변경에서 선택 (미지정 업로드는 PUBLIC)
- 비친구가 재생을 요청하면 **PRIVATE 비소유자와 완전히 같은 403 "비공개 영상입니다"** — 별도 에러코드 없이
  실패 응답이 동일하다. 재생 URL은 발급되지 않는다
- 판정은 **요청 시점 실시간** — 친구 삭제 즉시 다음 요청부터 막힌다 (캐시·비정규화 없음)
- 전역 노출 경로(격자 대표 영상·전역 목록·탐색 집계)는 PUBLIC 한정이라 FRIENDS 영상이 잡히지 않는다.
  친구에게 보여주는 노출 경로는 **친구 격자 영상 목록**(친구 도감 레이어에서 친구 격자 선택 시
  그 친구의 PUBLIC+FRIENDS 영상만) — 2026-08-04 확정, MSG-187에서 구현

### 도감 (Collection)

**정의**: 사용자가 점령한 격자들의 집합.

- DB 테이블: `user_grids`
- UI 표시: 지도 위에 자기 색상(`users.grid_color`)으로 채워진 격자들
- **MVP는 개인 도감만 존재**

### 도감 색상 (grid_color)

**정의**: 사용자가 점령한 격자를 지도에 표시할 때 쓰는 색상.

- DB 컬럼: `users.grid_color` (ENUM: BLUE, GREEN, PURPLE, ORANGE, PINK, YELLOW, RED, TEAL)
- 기본값: BLUE
- 프로필에서 변경 가능
- ~~Phase 2+에서 친구 색상 구분에 사용 예정~~ → 친구 도감 레이어는 **단일색**으로 확정
  (2026-08-04)이라 친구 격자 색칠에는 미사용 — 내 도감 표시·프로필 노출 용도

### 점령 롤백 (Occupation Rollback)

**정의**: 영상 삭제 시 점령이 취소되는 규칙.

- 특정 격자의 사용자 영상이 모두 삭제되면 `user_grids` row도 삭제
- `video_count`가 0이 되는 시점
- **시간 제한 없음** — 업로드 후 얼마가 지났든 삭제하면 즉시 롤백된다 (2026-07-16 확정).
  교체도 마찬가지로 언제든 가능하다. glossary "영상"의 "업로드 후 수정·삭제 자유"와 일관

### 미점령 격자 (Unclaimed Grid)

**정의**: 사용자가 아직 영상을 올리지 않은 격자.

- **UI 정책: 격자망(점선 테두리)은 상시 표시, 채움색 없음** — 지도는 항상 뷰포트 전체에 점선
  격자망을 깔고, 점령한 격자만 채움색이 올라간다 (2026-08-04 확정, 피그마 ver8 지도 홈
  노드 14094:3981 실측. 기존 "표시하지 않음·격자망 오버레이 없음" 정책 대체)
- 격자망은 **FE-local 렌더** — 격자 계산 규칙 산술로 클라이언트가 그린다. 서버 API는 지금처럼
  점령 격자만 응답에 담는다 (미점령 미포함 — MSG-73/90 계약 불변)

### 친구 도감 레이어 (Friend Collection Layer)

**정의**: 특정 친구 1명이 점령한 격자를 지도 뷰포트에서 보는 화면/기능 (2026-08-04 확정, MSG-187).

- **대상·진입**: 친구 목록/프로필에서 "도감 보기" — 항상 **특정 친구 1명**의 레이어만
  (전체 친구 합산은 Phase 2+)
- **색상**: 친구 격자는 **단일색 통일** — 색값은 FE/디자인 몫, 서버는 색 정보를 내려주지 않는다
  (친구별 `grid_color` 미사용)
- **겹침**: 나와 친구가 같은 격자를 점령했으면 친구 레이어 열람 중에는 **친구 색 우선**
  (FE 그리기 순서로 해결)
- **미점령**: 격자망 상시 표시 정책 그대로 — 친구가 안 채운 격자는 점선 테두리만
- **영상 노출**: 친구 격자 선택 시 **그 친구의 PUBLIC+FRIENDS 영상 목록** (PRIVATE 절대 제외).
  판정은 요청 시점 실시간 — 친구 삭제 즉시 레이어·목록 접근이 거부된다
- 비친구의 조회는 관계·계정 존재를 은닉하는 단일 실패 응답 (MSG-186 프로필과 동일 정책)

### 스트릭 (Streak)

**정의**: 매일 영상을 업로드한 날이 이어진 연속 일수. **재방문 업로드도 인정** — 신규 격자 점령 불요 (2026-07-29 확정).

- **일 경계 = KST(Asia/Seoul) 자정 고정** — 사용자별 타임존 없음(users에 타임존 컬럼 없음, MVP 한국 대상).
  DB TIMESTAMP는 UTC 저장이므로 판정 시 KST 변환 후 날짜 비교
- DB 테이블: `streaks` (1 user = 1 row, current_count · max_count · last_recorded_date)
- 갱신: 업로드 이벤트 시 (MSG-200), 뱃지 "꾸준함" 축(STREAK_DAYS)이 소비 (MSG-239)
- 끊김 유예(freeze)는 미확정 — MVP 미도입 제안

### 구역 (Zone)

**정의**: "서면"·"홍대입구"·"황리단길"처럼 **행정동으로 표현되지 않는 유명 통칭**(상권·명소)의 범위를 나타내는
격자 정수 사각형 (MSG-234/259).

- DB 테이블: `zones` — `zone_key`(자연키, 예 `seomyeon`) · `min/max_grid_y/x` 정수 사각형 · `priority` ·
  남북 26행(≈2.6km) 캡 CHECK. 격자별 저장 없음 — 소속 판정은 정수 부등식 산술
- **등재 기준 = 유명하거나 특별한 통칭 하나** — 지역 제한 없음 (2026-07-31 확정, 초기 데이터는
  소진공 공공데이터 부트스트랩 + 통칭 수동 작도 하이브리드)
- 시딩: `seed/zones.json` → 기동 시 멱등 UPSERT (`fillmap.zone.seed.enabled`, prod/dev 상시 on — MSG-259 D-8)
- 사각형끼리 겹치지 않게 관리 (겹침 시 `priority DESC → zone_key ASC` 보험 규칙이 하나로 결정)

### 표시명 (Display Name)

**정의**: 격자를 사람이 읽는 이름. zone 안이면 **"{zone명} {행}-{열}"** (행 A=사각형 북단부터, 열 1=서단부터 —
예 `"서면 A-14"`), zone 밖이면 **행정동 이름 폴백**(번호 없음), 행정동도 없으면(해상 등) 표시명 없음.

- 계산은 **서버** — 격자를 담는 조회 응답 9종에 `zoneName`·`zoneCell` 필드로 실려 온다 (MSG-341, 2026-08-07
  결정 변경 — 기존 FE-local 산술(MSG-234 §D3)을 대체). FE는 조립(`zoneName + " " + zoneCell`)과 행정동
  폴백 표시만 하고, zones 캐시는 검색바 구역 이동(MSG-234 §D6)용으로만 남는다
- 명명 규칙의 실행형 정본: `src/test/resources/fixtures/zone-naming.json` (언어 중립 픽스처, MSG-259 D-4) —
  MSG-341부터 계산 구현은 서버 한 곳이라 서버 테스트가 분리 기대값(expectedZoneName·expectedZoneCell)으로
  검증한다. 클라이언트는 명명 구현이 없어 검증 대상이 아니다
### 핫구역 (Hot Zone)

**정의**: 최근 48시간 업로드 신호(핫스코어)가 **상위 K(50) 안이면서 최소 임계(3) 이상**인 격자.
**재방문 업로드도 전부 신호로 인정** — 도배 방어 없음 (2026-07-31 확정).

- 신호는 업로드(방문 이벤트)만 — 좋아요는 MSG-275 구현 후 확장 지점
- 저장: Redis Sorted Set 6시간 버킷(`hotzone:{bucketId}`), DB 테이블 없음
- 핫스코어는 근사값 — 영상 삭제 시 차감 없음(윈도우 만료로 자연 소멸), Redis 유실 허용
- 진입: 지도 홈 상단 "핫구역" 칩 (2026-07-25 지도 홈 개편 확정)
- 설계 정본: `docs/MSG-233.md` — 구현은 MSG-183(집계)·MSG-184(조회)
- UI 정책(색상·애니메이션·빈 상태)은 FE·디자인 몫 미확정

## 🛠 백엔드 전용 개념 (사용자 노출 X)

### 전역 격자 등록 (Global Grid Registration)

**정의**: `grids` 테이블에 격자 row가 생성되는 것.

- Lazy insert의 트리거 지점
- 어떤 사용자의 첫 영상 업로드 시 자동 발생
- 이 개념을 **사용자 UI/기획서에서 절대 노출하지 않음**
- 코드/설계 논의에서만 사용

### Lazy Insert

**정의**: 격자를 미리 저장하지 않고, 실제로 영상이 올라오는 순간에만 grids 테이블에 등록하는 전략.

### 격자 계산 규칙 (Grid Encoding Rule)

**정의**: 좌표를 격자 ID로 변환하는 수학 규칙 (2026-08-08 MSG-347에서 개정).

1. 위경도(WGS84)를 EPSG:5179 미터 좌표 `(x, y)`로 변환한다.
2. `gridX = floor(x / 100)`, `gridY = floor(y / 100)` — 경계는 반열림 구간 `[n·100m, (n+1)·100m)`이라
   경계선 위 좌표는 정확히 한 셀에만 속한다.
3. `grid_id = "{gridY}_{gridX}"`.

- 셀 크기 상수 `CELL_SIZE_METERS = 100`
- 좌표계 정의는 proj4 문자열 하나가 계약이다 — `GridConstants.CRS_DEF_EPSG5179`. BE(Proj4J)·
  FE(proj4js)·이행 SQL(ST_Transform)이 **글자 단위로 같은 문자열**을 써야 경계 근처 셀이 어긋나지 않는다.
  정합성 검증 자료는 `src/test/resources/fixtures/grid-epsg5179-samples.json`(전국 200건).

**전국 어디서나 100m다.** 5179는 미터 단위 평면이라 100으로 나누면 100m 셀이 정확히 성립한다.
- 지상 실거리는 축척계수(0.9996) 때문에 한 변이 100.0m에서 수 cm 벗어난다 (실측: 서울 100.038m ·
  부산 100.015m · 제주 100.030m). 지역별로 1~5% 달랐던 구 방식과 달리 전국이 균일하다.
- 대신 셀은 위경도 지도 위에서 자오선 수렴만큼 살짝 기울어져 보인다 — 셀 경계를 위경도로 표현하려면
  꼭짓점 4점이 모두 필요하다(남서·북동 2점으로 복원 불가).
- 구 규칙(`GRID_LAT_STEP = 0.0009`, `GRID_LNG_STEP = 0.00115`)의 마지막 사용처는 V28 이행 SQL이다.
