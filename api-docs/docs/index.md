# 시작하기

FillMap 백엔드 API를 붙이는 FE, 모바일, 백엔드 팀원을 위한 문서다. 엔드포인트별 요청과 응답 스키마는
[API 레퍼런스](reference.md)가 OpenAPI 스냅샷 그대로 담고 있고, 이 가이드 페이지들은 그 스키마만
봐서는 알 수 없는 약속(응답 봉투, 토큰 흐름, 격자 표시명 조립, 업로드 순서)을 설명한다.
레퍼런스와 이 문서가 어긋나면 레퍼런스가 맞다.

## 환경과 베이스 URL

| 환경 | 베이스 URL | 상태 |
|---|---|---|
| dev | `https://api.fillmap.kr` | 가동 중 |
| prod | 미정 | 앱 미가동 |

모든 경로는 `/api`로 시작한다. 예를 들어 dev에서 내 프로필을 부르면
`https://api.fillmap.kr/api/users/me`가 된다.

## 공통 응답 포맷

성공이든 실패든 응답 본문은 항상 같은 세 필드로 감싼다.

| 필드 | 타입 | 의미 |
|---|---|---|
| `developCode` | integer | 앱 내부 코드. 성공은 200, 실패는 도메인별 4자리 코드 |
| `message` | string | 사용자와 개발자용 메시지 |
| `data` | object 또는 null | 실제 데이터. 실패 응답과 반환값 없는 성공에서는 null |

`data` 키는 값이 null이어도 언제나 직렬화되므로 클라이언트가 키 존재를 분기 조건으로 쓸 필요가 없다.

성공은 HTTP 200에 `developCode` 200, `message` "성공"이 고정으로 실린다.

```json
{
  "developCode": 200,
  "message": "성공",
  "data": {
    "gridId": "19422_9582",
    "occupied": true,
    "videoCount": 3
  }
}
```

HTTP 상태 코드는 본문에 넣지 않는다. 상태 줄에 이미 들어 있어 중복이고, 문서 생성기가 실제와 다른
예시를 만들어내는 원인이 되기도 했다. 분기는 HTTP 상태와 `developCode` 두 값으로 한다.

## 에러 응답

실패도 같은 봉투를 쓴다. HTTP 상태는 의미에 맞는 값이 오고, `developCode`가 어떤 실패인지 좁힌다.

```json
{
  "developCode": 3404,
  "message": "영상을 찾을 수 없습니다",
  "data": null
}
```

`developCode` 대역은 도메인별로 갈라져 있다. 400, 401, 403, 404, 500은 도메인을 특정하지 않는 공통
코드이고, 네 자리 이상은 앞자리가 도메인을 가리킨다(예: `2xxx` 인증, `3xxx` 영상, `4xxx` 격자).
전체 대역표와 도메인별 상수 목록은 [에러 코드](error-codes.md)에 있다.

`@Valid` 검증에 걸리면 필드별 메시지를 이어 붙인 400이 온다. 이때 `developCode`는 공통 400이고
`message`가 `email: must not be blank` 형태로 어느 필드가 문제인지 알려준다.

## 시각 표기

JSON에 실리는 시각은 전부 UTC `Z` 표기다. 서버는 전역 코덱 하나로 직렬화와 역직렬화를 처리하므로
필드마다 표기가 다를 일이 없다.

```json
{ "recordedAt": "2026-07-17T14:30:00Z" }
```

KST가 필요한 화면은 클라이언트가 변환한다. 예외는 날짜 라벨인데, "며칠에 올렸나"처럼 시각이 아니라
날짜만 뜻하는 값은 `YYYY-MM-DD` 문자열로 내려간다(예: 업로드 기록의 `uploadDate`). 시각을 쿼리
파라미터로 받는 API는 없다. 시각 입력은 요청 본문으로 보낸다.

## 인증

인증이 필요한 API는 액세스 토큰을 헤더에 담아 부른다.

```bash
curl https://api.fillmap.kr/api/users/me \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."
```

토큰이 없거나 만료면 401에 `developCode` 2401(유효하지 않은 토큰) 또는 2402(만료된 토큰)가 온다.
2402를 받으면 재로그인이 아니라 재발급을 먼저 시도한다.

지도 조회 계열(격자 커버, 격자 전역 영상 목록, 핫구역, 미션, 행사 조회, 장소 검색, 역지오코딩,
단건 영상 재생)은 비로그인으로도 부를 수 있다. 다만 로그인 상태에서만 값이 달라지는 응답이 있어
(내 점령 여부, 친구 공개 영상 접근) 토큰이 있으면 함께 보내는 편이 낫다. 업로드와 개인 도감 계열은
로그인이 필수다.

!!! note "역할"
    토큰에는 `USER`, `ORG`, `ADMIN` 역할이 실린다. `/api/admin/**`은 ADMIN, 행사 등재 콘솔인
    `/api/org/**`은 ORG만 통과한다. ORG 토큰으로 일반 사용자 API(업로드, 친구)를 부르면 403이다.

토큰 발급과 재발급, 소셜 로그인 흐름은 [인증](auth.md)에서 다룬다.
