# 격자와 표시명 계약

지도 화면 전체가 격자 위에 올라간다. 격자 ID를 만드는 규칙과 격자에 이름을 붙이는 규칙은 서버와
클라이언트가 같은 값을 내야 하는 계약이라 이 페이지에 모아 둔다.

## 격자란

국토 평면 좌표계 EPSG:5179 위에서 100m 간격으로 나눈 셀 하나가 격자다. 5179가 미터 평면이라
전국 어디서나 한 변이 100m이고, 지역에 따라 크기가 달라지지 않는다.

좌표를 격자로 바꾸는 절차는 세 단계다.

1. WGS84 위경도를 EPSG:5179 미터 좌표 `(x, y)`로 변환한다.
2. `gridX = floor(x / 100)`, `gridY = floor(y / 100)`.
3. `gridId = "{gridY}_{gridX}"` (예: `"19422_9582"`).

경계는 반열림 구간 `[n*100m, (n+1)*100m)`이라 경계선 위의 좌표도 정확히 한 셀에만 속한다. 같은
셀 안의 어떤 좌표를 넣어도 같은 `gridId`가 나온다.

응답의 `gridY`, `gridX`는 위도와 경도가 아니라 5179 평면 인덱스다. 지도에 그릴 때 위경도로 착각해
쓰면 엉뚱한 자리에 셀이 선다.

!!! warning "좌표계 정의 문자열이 계약이다"
    서버(Proj4J)와 프론트(proj4js)는 아래 proj4 문자열을 글자 단위로 같이 써야 한다. 한 글자만
    달라도 경계 근처 셀이 서로 어긋난다. 서버 쪽 원본은 `GridConstants.CRS_DEF_EPSG5179`다.

```text
+proj=tmerc +lat_0=38 +lon_0=127.5 +k=0.9996 +x_0=1000000 +y_0=2000000 +ellps=GRS80 +towgs84=0,0,0,0,0,0,0 +units=m +no_defs
```

셀이 위경도 지도 위에서는 자오선 수렴만큼 살짝 기울어 보인다. 셀 경계를 위경도로 표현하려면
꼭짓점 네 점이 다 필요하고, 남서와 북동 두 점으로는 복원되지 않는다.

## 표시명 세 필드

격자를 담는 응답에는 이름 재료 세 필드가 함께 온다. 이름 하나를 얻으려고 API를 더 부를 일이
없도록 한 응답 안에서 조립이 끝나게 설계돼 있다.

| 필드 | 의미 | null이 되는 때 |
|---|---|---|
| `zoneName` | 격자가 속한 구역 이름(예: `"서면"`) | 구역 밖 격자 |
| `zoneCell` | 구역 안 위치 코드 `"{행}-{열}"` (행 A가 북단, 열 1이 서단) | `zoneName`과 항상 쌍이라 함께 null |
| `regionName` | 격자 중심점이 속한 행정동 전체 이름 | 어느 행정동에도 안 속할 때(해상 등) |

구역은 "서면", "홍대입구"처럼 행정동으로 표현되지 않는 유명 통칭의 범위다.

조립 규칙은 한 줄이다.

```js
const label = zoneName ? `${zoneName} ${zoneCell}` : regionName;
```

폴백인 행정동 이름에는 칸 번호를 붙이지 않는다. `regionName`은 구역 안 격자에도 항상 실리는데,
화면 위치줄의 시와 구가 이 값에서 나오기 때문이다(예: `"부산광역시 부산진구 부전1동"`).
`regionName`은 아직 아무도 영상을 올리지 않은 격자에도 실린다.

```json
{
  "gridId": "19422_9582",
  "gridY": 19422,
  "gridX": 9582,
  "zoneName": "서면",
  "zoneCell": "I-6",
  "regionName": "부산광역시 부산진구 부전1동"
}
```

세 필드가 다 null이면 이름 없는 격자다. 에러가 아니라 정상 응답이니 빈 라벨로 그린다.

### 예외: 코스 포토스팟

코스 미션의 경유 지점만 서버가 문자열을 미리 조립해 `name` 하나로 내려준다. 스팟 항목에는 재료
셋을 실을 자리가 없어서, 시더가 적재 시점에 명소 이름, 구역 표시명, 행정동 이름 순으로 사다리를
타 이름을 정해 저장한다. 행정동에도 안 걸리는 해안 지점은 가장 가까운 행정동 이름을 쓰고, 그때
마지막 토큰만 남긴다(`"부산광역시 사하구 다대2동"`이면 `"다대2동"`).

이 조립은 코스 미션 응답에만 있다. 지도 응답은 종전대로 재료 세 필드만 내려주므로 다른 화면에서
이 규칙을 흉내내지 않는다.

## 미점령 격자

서버는 점령한 격자만 응답에 담는다. 미점령 격자는 목록에 들어가지 않으며, 화면의 점선 격자망은
클라이언트가 위 계산 규칙을 직접 돌려 그린다. 격자망은 상시 표시하고 점령한 격자에만 채움색을
올린다.

목록이 아니라 단일 격자 조회는 다르다. `GET /api/grids/{gridId}`는 미점령 격자에도 404가 아니라
`occupied: false`로 답한다. 격자는 저장 여부와 무관하게 항상 존재하는 논리 개념이기 때문이다.

## 관련 API

| 엔드포인트 | 하는 일 | 비로그인 |
|---|---|---|
| `GET /api/grids` | 뷰포트 안에서 내가 점령한 격자 목록(커서 페이지네이션) | 불가 |
| `GET /api/grids/{gridId}` | 단일 격자의 점령 여부와 내 영상 수 | 불가 |
| `GET /api/grids/aggregation` | 뷰포트 안 점령 격자를 행정 단위로 묶은 집계(줌아웃용) | 불가 |
| `GET /api/grids/{gridId}/videos` | 그 격자의 전역 공개 영상 목록 | 가능 |
| `GET /api/grids/{gridId}/cover` | 그 격자를 대표하는 영상 1건 | 가능 |
| `GET /api/grids/{gridId}/my-videos` | 그 격자에 올린 내 영상 목록 | 불가 |
| `GET /api/grids/{gridId}/hourly-uploads` | 그 격자 공개 영상의 24구간 시간대 분포(KST 기준) | 가능 |
| `GET /api/regions/reverse-geocode` | 좌표를 포함하는 행정동 1건 | 가능 |

### 뷰포트 조회의 제약

`GET /api/grids`는 bbox를 남서와 북동 좌표 네 개로 받는다. 한 변의 span 상한은 0.5도이고 위도와
경도에 따로 적용된다. 정확히 0.5도는 통과하고, 넘으면 잘라서 응답하지 않고 400 + `developCode`
4402로 거절한다. 응답의 `nextCursor`를 다음 요청 `cursor`에 넣어 이어 받고, null이면 마지막
페이지다. `size` 기본값은 1000, 최대 5000이다.

`GET /api/grids/aggregation`은 `unit`이 필수이고 `DONG`, `SIGUNGU`, `SIDO` 중 하나다. 단위를
언제 바꿀지는 서버가 정하지 않으므로 클라이언트가 화면 축척에 맞춰 `unit`만 바꿔 부른다. span
상한도 단위별로 달라 DONG 1도, SIGUNGU 4도, SIDO 10도다. 좌표가 WGS84 범위를 벗어나거나 bbox가
뒤집히면 4401, `unit`이 없거나 미지원 값이면 4405다.

행정동이 판정되지 않은 격자는 집계에서 빠지지 않고 `regionCode`와 `name`이 null인 항목 하나로
묶여 온다. 어느 단위로 묶든 항목을 다 합하면 같은 bbox의 개별 격자 조회 총 개수와 일치한다.

### 역지오코딩

`GET /api/regions/reverse-geocode?lat=&lng=`는 좌표를 포함하는 행정동 하나를 반환한다. 포함
행정동이 없으면(바다, 국외) 404가 아니라 200에 `data: null`이다. 서비스 좌표 범위인 한국을
벗어나면 400 + `developCode` 6400이다.

응답 스키마 전문은 [API 레퍼런스](reference.md)에 있다.
