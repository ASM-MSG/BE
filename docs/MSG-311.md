# MSG-311: 공통 응답 필드명 body → data 변경 — API 계약 정비

**Owner**: 공동 — 대상이 도메인 소유가 아닌 공통 패키지(`com.msg.fillmap.response.*`)이고,
테스트 치환이 Owner A(grid·region·search·hotzone·zone)·Owner B(user·video·auth·usergrid·badge·mission)
양쪽 도메인 16파일에 걸침. 리뷰 시 양측 확인 필요.

> **PRD 게이트: 면제** — 제품 기능·비기능 요구 불변. 공통 응답 봉투(envelope)의 계약 표면
> 명명 정비라 PRD에 담을 신규 요구사항이 없음 (CLAUDE.md 면제 기준 "요구사항 불변 → 면제" 충족,
> 오케스트레이터 판정 2026-08-03).

## 개요

모든 API 응답을 감싸는 공통 봉투 `ApiResponseDto<T>`의 실데이터 필드명을 `body`에서 `data`로
변경한다. 직렬화 JSON 키가 바뀌는 **breaking change**이므로 FE(웹) 파싱 코드와 동시 배포가 전제다.

## 배경 · 목표

- 현재 응답 `{ "developCode": 200, "message": "성공", "body": {...} }`에서 `body`는 HTTP 응답
  본문(response body) 용어와 겹쳐 혼동을 유발한다.
- 업계 관례는 `data` (Google JSON Style Guide, JSON:API).
- 정식 오픈 전이라 지금이 마지막으로 싼 변경 시점 (2026-08-03 팀 결정).
- 명명 이력: MSG-99(공통 응답 최초 설계) → MSG-265(httpStatus 필드 제거) → MSG-308(@Schema
  required 명시, PR #97) — 본 티켓은 이 계보의 명명 정비 단계.

## 성공 기준

1. 모든 API 응답(성공·에러)의 실데이터 키가 `data`이고, `body` 키는 어떤 응답에도 나타나지 않는다.
2. 키 이름 외 와이어 동작 불변 — `developCode`·`message` 필드, HTTP 상태 처리(MSG-265),
   에러 시 실데이터 null 직렬화 모두 기존과 동일.
3. 전체 테스트 green (`./gradlew test`) — 기존 179개 jsonPath 단언이 `$.data`로 치환된 상태로 통과.
4. Swagger(springdoc) 스키마에 `data` 키가 자동 반영됨을 확인.

## 결정 사항

| # | 결정 | 근거 |
|---|---|---|
| D-1 | rename 방식 = **필드명 자체 변경** (`private T body` → `private T data`). `@JsonProperty` 미사용 | 프로젝트 main 소스에 `@JsonProperty` 사용처 0건(실측) — Jackson 키가 Lombok `@Getter` 기반 필드명에서 나오는 구조. 필드명=JSON 키 일치를 유지하는 쪽이 단순하고, 어노테이션으로 이름을 갈라놓으면 코드-와이어 불일치가 영구 잔존 |
| D-2 | Lombok `@Builder` 메서드도 필드명을 따라 `.data(...)`로 바뀜 — 조립부 수정은 `SuccessResponse` 생성자의 `.body(data)` **1곳뿐** | `GlobalExceptionHandler`의 `.body(...)` 6곳은 전부 `ResponseEntity` 빌더 호출(HTTP 응답 본문 세팅)이며 DTO의 `body` 필드를 만지지 않음(실측) — 에러 응답은 실데이터 필드를 아예 세팅하지 않으므로 수정 불요 |
| D-3 | 에러 응답의 `"data": null` 직렬화는 현행 유지 (키 이름만 변경, `@JsonInclude(NON_NULL)` 도입 안 함) | 본 티켓은 rename만 — null 생략은 별도 계약 변경이라 범위 밖 |
| D-4 | `@Schema(requiredProperties = {"developCode", "message"})`는 그대로 — `data`는 required에 넣지 않음 | MSG-308 결정 계승: 에러 응답에서 null이므로 required 아님. 클래스 상단 주석의 "body" 표기만 "data"로 갱신 |
| D-5 | 호환 기간(구·신 키 동시 내려주기) 없이 한 번에 컷오버 | 정식 오픈 전 + FE 동시 배포 전제(티켓 제약) — 이중 키는 코드·계약 양쪽에 잔재만 남김 |

## API 명세

endpoint 추가·변경 없음. **전 API 공통 응답 봉투의 JSON 키 1개 변경**:

```json
// AS-IS
{ "developCode": 200, "message": "성공", "body": { ... } }
// TO-BE
{ "developCode": 200, "message": "성공", "data": { ... } }
```

- 성공: `developCode` 200 + `data`에 실데이터 (기존 `body` 위치 그대로)
- 에러: `developCode` 도메인/공통 코드 + `data": null` (기존 `body: null` 동작 유지, D-3)
- HTTP 상태는 status line으로만 — MSG-265 계약 불변

## 배포 순서 (FE 동시 배포 — 필수 제약)

1. **착수 전**: FE(웹) 팀과 변경 시점 합의 확인 (티켓 제약 — 합의 없이 merge 금지).
2. FE가 파싱 코드 `body` → `data` 변경을 준비하고, BE·FE를 **같은 릴리스 윈도우에 동시 배포**한다.
   호환 기간 없음(D-5) — 한쪽만 배포된 상태에서는 실데이터 파싱이 전면 실패한다.
3. 롤백 시에도 양쪽 동시 롤백.

### 모듈 1 — response 공통 계약 (`ApiResponseContractTest`, 본 변경의 TDD 앵커)

  / When Jackson 직렬화 / Then `"data"` 포함 + **`"body"` 미포함**(rename 누락 회귀 방지) +
