## 개요

팝가 수집본(`popups.jsonl`, 전국 2,593건 검증 완료 스냅샷)의 **진행 중·예정 팝업 343건**을
`missions`(**type=POPUP** 신설, source='POPGA') + `mission_grids`(중심 9×9 격자 81행,
target_count=1)로 적재한다(FR-1·2·7). 러너는 플래그 게이트 ApplicationRunner **1개**
(FestivalMissionSeeder/MSG-224 미러)로, 초기 시드와 주 1회 수동 갱신이 같은 코드 경로다.
멱등 키는 **팝가 id**(FR-3) — 축제의 좌표+기간 dedupe와 달리 외부 안정 id가 있으므로 신규 컬럼
`missions.source_key`(V14)에 저장해 대조한다. reader는 코스(MSG-225 D7)의 **전량 거부** 계약을
따른다 — 크롤 완성 산출물이라 결함 하나 = 산출물 재생성 대상이지 부분 적재 대상이 아니다(FR-6).
갱신은 종료 정리 + 신규 추가를 단일 트랜잭션으로(FR-4·5), **상시 스케줄러 금지**. 신규 API 없음.
DDL은 **V14 1건**(CHECK에 'POPUP' + `source_key` 컬럼).

## 배경 · 목표

지도 홈 개편(2026-07-25)으로 상단 칩 4종에 "팝업 스토어"가 확정됐는데 미션 3종 축 중
축제(MSG-224)·코스(MSG-225)만 적재돼 팝업 칩이 빈 상태다. 이 티켓으로 미션 3종 축이 완결된다.
설계검토(2026-07-20)의 "팝업=EVENT 통합" 결정은 칩 4종 확정으로 뒤집혀 **type=POPUP이 새 정본**
이다(PRD 비목표 절, 2026-07-31 성민 확정).

## 성공 기준

아래 "테스트 시나리오"가 이 기준의 검증 수단이다.

1. 플래그 off(기본) 기동·통합 테스트에서 러너가 아무것도 하지 않는다 — 평시 기동 무영향
2. 시드 실행 시 진행 중·예정 팝업만 POPUP 미션으로 적재된다 — 미션당 mission_grids 81행
   (중심±4, seq NULL)·target_count=1·region_code NULL·path NULL·**source='POPGA'**·
   **source_key=팝가 id** (FR-1·2·7)
3. 같은 파일로 재실행하면 신규 적재 0건 — 팝가 id 멱등 (FR-3)
4. 갱신 실행 시 종료 팝업(end_at < 현재 UTC)이 삭제되고 mission_grids가 CASCADE로 정리된다.
   스탬프 걸린 미션은 잔존, **source ≠ 'POPGA'(FESTIVAL·DURUNUBI·NULL 수동)는 불가침** (FR-4·8)
5. 산출물 검증 위반(좌표 범위·날짜 역전·id 비정수·name 비문자열·필수 필드 누락) 시 예외로
   전량 거부 — 부분 적재 없이 기존 미션 데이터 무변경 (FR-5·6)
6. 활성 미션 조회가 POPUP 미션을 BOX shape로 합성해 반환한다 — 판정 엔진(MSG-223)은 무수정으로
   POPUP 완료·스탬프를 처리한다 (PRD 목표 3)
7. `./gradlew test` green

### D3. 멱등 — `missions.source_key` = 팝가 id (FR-3, V14)

**D-결정: V14로 `missions.source_key VARCHAR(30) NULL` 컬럼 추가.** missions에 외부 id 저장
수단이 없는데 FR-3이 팝가 id 멱등을 명령한다 — V14는 어차피 CHECK 'POPUP' 추가로 필요하므로
같은 마이그레이션에 싣는다. 축제식 좌표+기간 키 유용은 배제 — 팝업은 같은 건물(같은 격자)에서
연속 개최가 일상이라 좌표+기간이 서로 다른 팝업을 흡수하고, PRD FR-3 문언이 이미 팝가 id를
지정했다.

- **소스 내 dedupe**: 같은 id는 전량 거부(D6) — 크롤러가 id 유일을 보장하므로 중복 = 산출물 결함.
- **DB 대조**: `findBySource('POPGA')`(MSG-224 기존 메서드 재사용)의 source_key 집합에 있으면
  skip — INSERT-only 멱등. 축제의 중심 복원(min+4) 불요 — 안정 외부 id가 있어서다.
- **부분 유니크 인덱스**로 구조 보증: `(source, source_key) WHERE source_key IS NOT NULL` —
  앱 dedupe의 DB 백스톱(제약이 앱 코드보다 싸다). NULL(수동·축제·코스)은 인덱스 밖이라 무영향.
- **INSERT-only, 기존 행 UPDATE 없음**: 날짜·이름이 소스에서 바뀌어도 기존 미션을 고치지 않는다
  (FR-3·4 문언은 추가·정리뿐). 연장 팝업의 공백은 D4의 정리-선행 순서가 흡수한다.
- 수용 한계: **스탬프 걸린 + 종료 경과 + 연장** 팝업은 정리가 못 지우고(스탬프 보호) 적재가
  skip해(키 잔존) 낡은 end_at으로 숨는다 — 삼중 교집합의 희귀 사례라 수용, 주 1회 수동 실행이라
  운영자 눈으로 걸린다.

### D4. 갱신 러너 — 러너 1개, **정리 → 적재** 순, 단일 트랜잭션 (FR-4·5)

시드와 갱신은 같은 러너다: ① 파일 파싱·전량 검증(D6) → ② **종료 팝업 정리** → ③ 기존
source_key 로드(D3) → ④ dedupe 통과분 INSERT(D1·D2). 빈 DB면 ②가 0건인 시드가 된다.

**축제(적재→정리)와 순서가 반대인 이유(D-결정)**: 팝업 키는 id뿐이라, DB상 종료(연장 전
closeDate 경과)인데 소스에서 연장으로 살아있는 팝업이 적재-선행이면 skip(키 잔존) 후
정리돼 다음 주까지 노출 공백이 난다. 정리-선행이면 같은 실행에서 구 행 삭제 → 신 날짜로
재적재돼 공백이 없다. 축제는 기간이 키에 포함돼 순서 무의미했다 — 팝업만 순서가 의미를 갖는다.

**② 정리 SQL** — MSG-224 D4 미러, `AT TIME ZONE 'UTC'` 규칙(MSG-223 §D2) 준수 필수:

```sql
DELETE FROM missions m
WHERE m.source = :source              -- 'POPGA' 한정 (FR-8)
  AND m.end_at IS NOT NULL
  AND m.end_at < statement_timestamp() AT TIME ZONE 'UTC'
  AND NOT EXISTS (SELECT 1 FROM user_missions um WHERE um.mission_id = m.id)
```

- **D-결정: 삭제(비활성 아님)** — 축제와 대칭. `findActive`가 종료를 이미 숨기므로 정리는
  위생이지 노출 제어가 아니고, 비활성 플래그는 새 컬럼·새 상태 기계라 근거 요구사항이 없다.
- **D-결정: 리포지토리 메서드는 `:source` 파라미터화** — `deleteEndedBySourceWithoutStamps(String)`
  신설, 기존 `deleteEndedFestivalsWithoutStamps()`는 이 메서드의 'FESTIVAL' 호출로 대체(축제 시더
  1줄 전환 + 구 메서드 제거). 동일 SQL 2벌 복제를 남기지 않는다 — 축제 통합 테스트(불가침·스큐
  케이스)가 그대로 green이면 회귀 무결.
- 스탬프 걸린 미션 건너뜀(`NOT EXISTS`) — V6 FK `user_missions.mission_id NO ACTION`이 하드삭제를
  차단하므로 시도 자체가 롤백 유발. 스탬프 영속은 PRD 비기능(MSG-219 FR-15) 그대로.
- `mission_grids`는 `ON DELETE CASCADE`(V6)로 함께 정리. `@Modifying(flushAutomatically,
  clearAutomatically)` — MSG-224 실측 파생 규칙 승계.
- 소스에서 사라졌지만 안 끝난 팝업은 삭제하지 않는다 — 정리 대상은 "종료"뿐(FR-4 문언).

**원자성(FR-5)**: 러너 실행 메서드 `@Transactional` — 검증 예외·중간 실패 시 전체 롤백, 기존
데이터 무변경. 파일 부재·유효 0건(종료 필터 후)은 명확한 예외로 조기 실패(RegionSeeder 선례).

**플래그 게이트**: `@Value("${fillmap.mission.popup.seed.enabled:false}")` off면 early return.
경로 `@Value("${fillmap.mission.popup.seed.path:data/mission/popups.jsonl}")`. **yml 무수정**
(기본값이 곧 설정, 켤 때만 env/인자 override — 축제·코스 패턴. PRD 변경 파일 표의
"application.yml 수정"은 이 방식으로 이행된다). `@Order(50)` — Region 10 · Zone 20 ·
Festival 30 · Course 40 이후, 의존은 없지만 결정적 순서.

### D5. POPUP 렌더 shape — BOX 재사용 (D-결정)

**`MissionType.POPUP` 추가 + `MissionQueryServiceImpl.buildShape`에 `case EVENT, POPUP ->
boxShape(grids)`** — 신규 shape를 만들지 않는다. 근거:

- 팝업 FE는 마커·카드(MSG-228)라 중심 좌표만 필요하고, BOX 폴리곤(min/max 5점 링)에서 중심은
  산술 평균으로 즉시 나온다 — 신규 POINT shape는 `MissionShape` sealed 계약·FE 렌더러 계약을
  둘 다 넓히는 비용 대비 이득이 없다(마커냐 면이냐는 FE 렌더 선택).
- 격자도 9×9로 축제와 동일(FR-2)이라 BOX 의미가 그대로 성립한다.
- switch는 enum 완전 분기(default 없음)라 POPUP 추가 시 **컴파일 에러로 분기 누락이 강제 차단**
  된다 — MissionType javadoc(유형 6종·POPUP→BOX)과 MissionResponseDto `allowableValues`만 갱신.

참고: MSG-224 D7·MissionRepository 주석의 "팝업=EVENT 공유·1격자" 서술은 type=POPUP 신설
(PRD FR-7)·9×9(FR-2)로 낡았지만, source 소유권 설계는 격자 수·타입과 무관하게 유효하다 —
역사 기록이므로 주석 무수정(수술적 변경 원칙).

### D6. 검증 계약 — 전량 거부 reader (FR-6, MSG-225 D7 계약 승계)

`PopupJsonlReader` — 축제 파서의 행 스킵·집계와 달리 **위반 즉시 `IllegalStateException`**
(CourseSeedReader 미러): 크롤 완성 산출물이라 결함 하나 = 재크롤 대상이다. 검증 목록:

- 행 JSON 파싱 실패 → 전량 거부 (축제의 skip+집계와 다름 — 의도적)
- `id`: JSON 정수(`isIntegralNumber`)만 — 문자열 "8151" 등 관용 변환 차단(코스 requireText 원칙).
  파일 내 중복 id → 전량 거부(멱등 키 보전, 코스 crsIdx 중복 거부 미러)
- `name`: 문자열(`isTextual`)·비공백 — 200자 절단은 검증 아닌 방어
- `latitude`/`longitude`: 쌍 존재·유한 숫자·한국 범위 **33~39 / 124~132(경계 포함)** — 좌표는
  크롤 산출이라 축제("병합 단계 보장 신뢰")와 달리 reader가 재검증한다
- `openDate`/`closeDate`: 문자열 존재·ISO `YYYY-MM-DD` 파싱 성공·`openDate ≤ closeDate`
- `periodType`·`operationTime` 등 미사용 필드는 검증하지 않는다 — 안 읽는 필드의 형식을
  강제하면 크롤러 변경마다 적재가 깨진다

**종료 필터는 검증이 아니다**: `closeDate < 오늘(KST 달력)` 행은 skip+집계 — 산출물에 종료
2,250건이 정상 포함되므로(FR-1) 거부 사유가 아니다. `periodType`은 필터에도 쓰지 않는다
(D-결정): 주 1회 갱신 스냅샷이라 최대 7일 낡는데 날짜는 낡지 않는다 — READY(미래 시작)는
적재하고 노출은 `findActive`가 숨긴다(축제 D1과 동일). "오늘"은 todayKst 주입(클럭 테스트 가능,
축제 미러).

### D7. 판정·뱃지 무수정 확인 (코드 0줄)

`findAwardCandidateIds`·`findCompleted`(MSG-223)는 type을 조건에 쓰지 않는 유형 무관 단일
