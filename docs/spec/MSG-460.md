# MSG-460: 행정동 전체 보기 개인 격자 커서 페이지 조회

**Owner**: B (`usergrid` 내부 조회 계약 확장, Owner A 엔티티 의존 없음)

> 요구사항 정본: `docs/prd/MSG-460-prd.md` (상태: 검토됨, 2026-08-22 사용자 승인)

## 개요

지도 홈의 행정동별 개인 격자 "전체 보기"가 모든 카드를 한 번에 반환하는 MSG-388 계약을 폐기한다.
전체 보기 전용 API는 최근 업로드 시각, 영상 수, 격자 식별자 순의 키셋 커서[^1]로 최대 20개씩
반환한다. 기존 전국 도감 갤러리의 무파라미터 호출과 목록 응답은 그대로 두어 이미 연동된 화면을
깨지 않는다.

## 배경 · 목표

기존 `GET /api/collections/grids`는 `regionCode`를 주고 `limit`을 생략하면 `LIMIT NULL`로 해당
행정동의 개인 격자를 전부 읽고, 모든 카드의 썸네일 임시 URL까지 발급한다. 운영 QA에서 이 경로의
지연이 확인됐다. 한 요청의 데이터베이스 결과, URL 발급 횟수, 응답 카드 수를 20개로 제한하고도
사용자가 다음 묶음을 빠짐없이 이어 볼 수 있게 하는 것이 목표다.

## 성공 기준

1. `GET /api/collections/regions/{regionCode}/grids`의 첫 호출은 로그인 사용자의 해당 행정동 격자를
   `last_uploaded_at DESC, video_count DESC, grid_id DESC`로 최대 20개 반환한다.
2. 21번째 후보가 있을 때만 `hasNext=true`와 불투명 `nextCursor`를 반환한다. 마지막 페이지는
   `hasNext=false`, `nextCursor=null`이다.
3. 응답의 `nextCursor`를 다음 요청의 `cursor`에 그대로 넘기면 마지막 카드 다음부터 이어진다.
   데이터가 바뀌지 않는 동안 중복과 누락이 없다.
4. 다른 행정동에서 발급한 커서, 깨진 커서, 저장 범위 밖 시각, 음수 영상 수는 400으로 거절한다.
5. 개인 격자가 없거나 존재하지 않는 행정동 코드는 200과 빈 `items`, `hasNext=false`,
   `nextCursor=null`을 반환한다.
6. 파라미터 없는 기존 `GET /api/collections/grids`는 최근 수집순 최대 30개와 기존 배열 응답을
   유지한다. 기존 행정동 호출에서 `limit`을 생략한 경우만 무제한 대신 최대 20개로 바뀐다.
7. 한 페이지에서는 잘라낸 21번째 후보의 썸네일 URL을 발급하지 않는다. URL 발급은 반환할 최대
   20개에만 수행한다.
8. 신규 Flyway 마이그레이션과 저장 데이터 변경이 없고, 관련 타깃 테스트와 전체 빌드가 통과한다.

## API 명세

### 1. GET /api/collections/regions/{regionCode}/grids

행정동 전체 보기 전용 신규 API다. 인증 토큰이 필요하며 로그인 사용자의 개인 격자만 반환한다.

| 입력 | 위치 | 타입 | 필수 | 의미 |
|---|---|---|---|---|
| `regionCode` | path | String | O | 격자가 속한 행정동 코드. 귀속 기준은 `grids.region_code` |
| `cursor` | query | String | X | 직전 응답의 `nextCursor`. 첫 페이지는 생략 |

페이지 크기는 서버 상수 20으로 고정한다. 클라이언트가 크기를 바꾸는 파라미터는 두지 않는다.
서비스는 리포지토리에 21개를 요청하고 한 건을 앞서 읽어 다음 페이지 존재 여부를 판정한다[^2].

성공 응답은 `SuccessResponse<CollectionGridPageResponseDto>`다.

```json
{
  "developCode": 200,
  "message": "성공",
  "data": {
    "items": [
      {
        "gridId": "19422_9582",
        "gridY": 19422,
        "gridX": 9582,
        "firstCollectedAt": "2026-08-20T12:00:00Z",
        "lastUploadedAt": "2026-08-22T09:30:00Z",
        "videoCount": 3,
        "coverVideoId": 1042,
        "coverThumbnailUrl": "https://...",
        "coverDurationSec": 12,
        "regionName": "서울특별시 강남구 역삼1동",
        "zoneName": null,
        "zoneCell": null
      }
    ],
    "hasNext": true,
    "nextCursor": "MTE2ODA1MTUwMDoxNzg3Mzc3ODAwMDAwMDAwOjM6MTk0MjJfOTU4Mg"
  }
}
```

`items`의 항목 형상과 필드 의미는 기존 `CollectionGridResponseDto`를 재사용한다. 커버가 없거나
인코딩 준비 전이면 기존과 같이 썸네일 URL만 null일 수 있으며, 해당 격자 카드는 빠지지 않는다.
총건수는 세지 않고 응답에도 넣지 않는다. 화면은 다음 묶음 존재 여부만 필요하므로 전체 COUNT를
추가하면 이 티켓의 비용 제한 목적과 어긋난다.

| 케이스 | HTTP | developCode | 응답 |
|---|---:|---:|---|
| 정상 페이지 | 200 | 200 | `items`, `hasNext`, `nextCursor` |
| 격자 없음 또는 미존재 regionCode | 200 | 200 | 빈 페이지 |
| 무효 커서 | 400 | 400 | 공통 `BAD_REQUEST` |
| 미인증 | 401 | 2403 | 기존 인증 진입점 |

usergrid는 배정된 도메인 에러 코드 대역이 없고, 커서는 요청 형식 오류이므로 신규 대역이나
`UserGridErrorCode`를 만들지 않는다. 디코드와 바인딩 실패는 `ApiException(ErrorCode.BAD_REQUEST)`로
통일한다.

### 2. GET /api/collections/grids (기존 호환 변경)

응답은 계속 `SuccessResponse<List<CollectionGridResponseDto>>`다. 파라미터와 정렬 축도 그대로다.

| regionCode | limit | 동작 |
|---|---|---|
| 없음 | 없음 | 최근 수집순 최대 30개. 기존 계약 불변 |
| 없음 | 지정 | 지정한 상한. 기존 계약 불변 |
| 지정 | 지정 | 지정한 상한. 지도 홈 패널의 `limit=20` 호출 불변 |
| 지정 | 없음 | 최신 정렬 요청 결과 최대 20개. MSG-388의 무제한 동작 폐기 |

이 API는 배열 응답이라 다음 페이지를 제공하지 않는다. 전체 보기 화면은 API 1로 전환하고,
기본 패널과 전국 도감 갤러리는 이 호환 API를 계속 쓸 수 있다.

## 도메인 로직

### D1. 대상과 귀속

- 조회 시작점은 `user_grids`이며 `ug.user_id = :userId`를 항상 적용한다. 타인의 점령과 영상은
  결과에 포함되지 않는다.
- 행정동은 영상 좌표가 아니라 격자의 `grids.region_code`로 판정한다. MSG-388의 격자 축 귀속을
  그대로 유지한다.
- `video_count`는 `user_grids`의 저장값을 사용한다. 삭제만 차감되고 비공개나 인코딩 중 영상은
  본인 도감 수에 포함되는 기존 기준을 바꾸지 않는다.

### D2. 정렬과 키셋 조건

정렬은 다음 세 기준을 모두 내림차순으로 적용한다.

1. `ug.last_uploaded_at`
2. `ug.video_count`
3. `ug.grid_id`

다음 페이지는 직전 페이지 마지막 항목보다 사전식으로 작은 행만 조회한다.

```sql
AND (
    ug.last_uploaded_at < :cursorLastUploadedAt
    OR (
        ug.last_uploaded_at = :cursorLastUploadedAt
        AND ug.video_count < :cursorVideoCount
    )
    OR (
        ug.last_uploaded_at = :cursorLastUploadedAt
        AND ug.video_count = :cursorVideoCount
        AND ug.grid_id < :cursorGridId
    )
)
ORDER BY ug.last_uploaded_at DESC, ug.video_count DESC, ug.grid_id DESC
LIMIT 21
```

첫 페이지는 커서 조건이 없는 SQL을, 다음 페이지는 위 조건이 있는 SQL을 각각 실행한다. nullable
커서 파라미터를 만들지 않아 PostgreSQL의 null 타입 추론 문제와 복합 OR의 첫 페이지 분기를 없앤다.
`last_uploaded_at`과 `grid_id`는 `user_grids`의 필수값이라 정렬의 null 처리 규칙은 추가하지 않는다.

### D3. 커서 형식과 검증

`CollectionGridCursor`는 요청 행정동 바인딩 값과 마지막 카드의 정렬값을 담는다.

```text
Base64URL("{regionCode}:{lastUploadedAtEpochMicros}:{videoCount}:{gridId}")
```

- 시각은 PostgreSQL timestamp의 마이크로초 정밀도를 보존하도록 UTC 기준 epoch 마이크로초로
  인코딩한다. encode와 decode가 같은 기준을 쓰므로 JVM 기본 시간대의 영향을 받지 않는다.
- `regionCode`는 커서를 발급한 행정동과 다음 요청의 행정동이 같은지 확인하는 바인딩 값이다.
  정렬에는 참여하지 않는다. 다른 행정동에 재사용하면 조용히 잘린 결과를 주지 않고 400을 반환한다.
- 디코드한 영상 수는 0 이상이어야 한다. 시각은 PostgreSQL이 저장할 수 있는 하한보다 이른 값을
  거절한다. `gridId`는 `GridEncoder.decode`로 형식을 검증한다.
- Base64 오류, 필드 수 오류, 숫자 변환 오류와 위 범위 오류는 모두 서비스가 공통 400으로 바꾼다.
- 클라이언트는 커서 내부 형식에 의존하지 않고 받은 문자열을 그대로 돌려준다[^3].

### D4. 페이지 조립

1. 커서가 없으면 첫 페이지 쿼리, 있으면 디코드와 행정동 바인딩 검증 후 다음 페이지 쿼리를 실행한다.
2. 리포지토리가 반환한 최대 21개 행으로 `hasNext = rows.size() > 20`을 판정한다.
3. `hasNext`이면 앞의 20개만 페이지 행으로 삼는다.
4. 페이지 행만 `CollectionGridView`로 바꾸면서 썸네일 URL을 발급한다. lookahead 한 건은 변환하지 않는다.
5. `hasNext`일 때만 20번째 행의 원시 프로젝션 값으로 `nextCursor`를 만든다. 마지막 페이지와 빈
   페이지의 `nextCursor`는 null이다.

커서는 URL 발급 전 프로젝션 값으로 만든다. 응답용 변환이 정렬 키를 바꾸지 않으므로 커서와 카드
순서는 같은 경계를 가리킨다.

## 데이터 모델

엔티티, 테이블, 컬럼 변경은 없다. Flyway 마이그레이션도 없다. 쿼리는 기존과 같이
`user_grids`의 사용자 범위를 먼저 읽고 `grids`와 `regions`를 PK 기준으로 조인한다. Owner B의
정렬값과 Owner A의 행정동 라벨을 한 문장에서 비교해야 정확한 키셋 경계가 만들어지므로, 네이티브
SQL은 `CollectionGridPageRepository` 한 곳에 격리한다. 한 페이지의 결과와 URL 발급은 20개로
제한되며, 별도 COUNT 쿼리를 실행하지 않는다.

## 계약 변경

`UserGridQueryService`에 B 내부 read 메서드를 하나 추가한다.

```java
CollectionGridPage getCollectionGridPage(long userId, String regionCode, String cursor);
```

`CollectionGridPage`는 `List<CollectionGridView> items`, `boolean hasNext`, `String nextCursor`를
가진 서비스 계층 record다. 기존 `getCollectionGrids` 시그니처는 유지하고, 내부 기본 상한 결정만
바꾼다. 신규 메서드 소비자는 `CollectionController`뿐이다. Owner A 패키지의 호출부, 타입,
엔티티는 바뀌지 않는다.

- 데이터 저장 변경은 없다. Flyway, 신규 테이블·컬럼, Redis 키, S3 키 변경도 없다.
- 핵심 SQL은 `user_grids ug JOIN grids g`에서 `ug.user_id`와 `g.region_code`를 고정하고,
  다음 페이지에만 `(last_uploaded_at, video_count, grid_id)`의 내림차순 키셋 조건을 적용한다.
  `ORDER BY ug.last_uploaded_at DESC, ug.video_count DESC, ug.grid_id DESC LIMIT 21`로 한 건을
  앞서 읽으며 COUNT 쿼리는 실행하지 않는다.
- 커서 디코드 실패, 범위 오류, 다른 행정동 커서 재사용은
  `UserGridQueryServiceImpl.decodeCursor`에서 `ApiException(ErrorCode.BAD_REQUEST)`로 바뀐다.
  `GlobalExceptionHandler.handleApiException`이 HTTP 400, developCode 400으로 응답한다.
- 신규 빈, 생명주기 콜백, 스케줄러, executor는 없다. 조회는 기존 서비스의 read-only 트랜잭션
  프록시 안에서 실행되며 자체 호출이나 afterCommit 훅도 없다.
- 대상 테스트, 테스트 제외 빌드, 전체 `./gradlew build`가 통과했고 Codex 교차 리뷰는 신규 지적
  없이 수렴했다.
