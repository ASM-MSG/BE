# MSG-460: 전체 지역 목록 개인화 커서 페이지 조회

**Owner**: B (`video` 전역 탐색 조회 변경)

> 요구사항 정본: `docs/prd/MSG-460-prd.md` (상태: 검토됨, 사용자 정정 승인)

## 개요

검색 화면의 `전체 지역` API `GET /api/regions/explore`를 고정 20개 커서 페이지로 바꾼다. 로그인 사용자가 직접 최근 업로드한 지역을 먼저 보여 주고, 나머지는 기존처럼 전역 공개 격자 수가 많은 순으로 보여 준다. 잘못 구현된 개인 도감 페이지 API와 그로 인한 기존 조회 절단은 제거한다.

## 배경 · 목표

현재 API는 콘텐츠가 있는 모든 행정동을 배열 한 번에 반환한다. 사용자 활동이 늘어도 한 요청은 20개로 제한하고, 사용자에게 익숙한 최근 업로드 지역부터 빠르게 노출하는 것이 목표다.

## 성공 기준

1. 첫 요청은 최대 20개 지역을 반환하고 21번째 후보가 있을 때만 `hasNext=true`와 `nextCursor`를 준다.
2. 사용자 개인 점령이 남은 지역은 `MAX(user_grids.last_uploaded_at) DESC`로 먼저 나온다.
3. 개인 우선 지역의 동률은 `gridCount DESC, regionCode ASC`, 나머지 지역은 `gridCount DESC, regionCode ASC`다.
4. 개인 업로드 지역이 없으면 전체 결과가 기존 `gridCount DESC, regionCode ASC` 순서다.
5. 다음 커서는 같은 로그인 사용자만 사용할 수 있다. 깨진 커서와 다른 사용자 커서는 400이다.
6. 전역 노출 대상과 `gridCount` 정의는 기존 MSG-238의 ACTIVE, PUBLIC, READY 기준을 유지한다.
7. 콘텐츠가 없으면 빈 페이지를 반환한다.
8. 기존 잘못 추가된 `/api/collections/regions/{regionCode}/grids`는 제거하고, `GET /api/collections/grids`에서 `regionCode`만 지정하고 `limit`을 생략한 기존 무제한 동작을 복원한다.

## API 명세

### GET /api/regions/explore

인증 토큰이 필요하다. `cursor`는 선택이며 첫 페이지에서는 생략한다. 페이지 크기는 서버 상수 20이다.

```json
{
  "developCode": 200,
  "message": "성공",
  "data": {
    "items": [
      {
        "regionCode": "5011062000",
        "regionName": "제주특별자치도 제주시 아라동",
        "gridCount": 1302
      }
    ],
    "hasNext": true,
    "nextCursor": "..."
  }
}
```

| 케이스 | HTTP | 결과 |
|---|---:|---|
| 첫 페이지 또는 정상 커서 | 200 | `items`, `hasNext`, `nextCursor` |
| 콘텐츠 없음 | 200 | 빈 `items`, `hasNext=false`, `nextCursor=null` |
| 깨진 커서 또는 다른 사용자 커서 | 400 | `INVALID_CURSOR` (developCode 3423) |
| 미인증 | 401 | 기존 인증 오류 |

## 도메인 로직

### 조회 집합

`content_regions`는 기존 전역 노출 게이트를 통과한 영상이 하나 이상 있는 격자를 행정동별로 센다. `personal_regions`는 현재 사용자의 `user_grids`를 `grids.region_code`로 묶고 `MAX(last_uploaded_at)`을 구한다. 개인 비공개 영상이나 처리 중 영상도 직접 업로드 이력에는 포함되지만, 화면에 노출할 행정동 집합과 `gridCount`에는 기존 전역 게이트를 그대로 적용한다.

### 정렬과 페이지 경계

정렬은 다음 순서다.

1. `personalLastUploadedAt IS NOT NULL DESC`
2. `personalLastUploadedAt DESC NULLS LAST`
3. `gridCount DESC`
4. `regionCode ASC`

개인 지역 커서 뒤에서는 더 오래된 개인 지역과 모든 비개인 지역이 후보다. 비개인 지역 커서 뒤에서는 비개인 지역 중 `gridCount`가 더 작거나, 같은 수에서 `regionCode`가 더 큰 행만 후보다. 집계 쿼리의 최종 결과는 21행으로 제한하고 20행까지만 응답한다. `content_regions`와 `personal_regions` 집계 비용은 페이지마다 발생하므로 실행 계획을 배포 전 확인한다.[^1]

### 커서

`RegionExploreCursor`는 `userId`, nullable `personalLastUploadedAt`, `gridCount`, `regionCode`를 Base64URL로 인코딩한다. 시각은 UTC epoch microseconds로 보존한다. 사용자 ID, 양수 격자 수, 10자리 숫자 행정동 코드, 필드 수와 숫자 형식을 검증한다. 클라이언트는 내부 형식에 의존하지 않는다.[^2]

## 데이터 모델

테이블, 컬럼, Flyway 마이그레이션 변경은 없다. `videos`, `grids`, `regions`, `user_grids`를 읽는다. 공간 연산은 하지 않는다.

## 계약 변경

Owner A 계약 인터페이스 변경은 없다. `RegionExploreService`의 B 내부 메서드는 다음으로 교체한다.

```java
RegionExplorePage getExploreRegions(long userId, String cursor);
```

## 작업 로그

### 2026-08-22

- 검색 무입력 `GET /api/regions/explore`를 현재 사용자 기준 개인화 커서 페이지로 변경했다. 응답은 `items`, `hasNext`, `nextCursor`이며 항목은 최대 20개다.
- 전역 노출 집합은 기존과 동일하게 ACTIVE, PUBLIC, READY 영상을 가진 격자만 센다. 별도 `personal_regions` 집계는 `user_grids.last_uploaded_at`의 행정동별 최댓값을 구한다.
- 핵심 SQL은 `content_regions`와 `personal_regions` CTE를 `region_code`로 결합하고, 개인 업로드 시각 존재 여부, 업로드 시각 내림차순, 격자 수 내림차순, 행정동 코드 오름차순으로 정렬한 뒤 21행으로 제한한다. 공간 연산과 전체 COUNT 쿼리는 없다.
- 커서의 사용자 ID가 현재 인증 사용자와 다르거나 Base64URL, 숫자, 행정동 코드 형식이 잘못되면 `RegionExploreServiceImpl`이 `ApiException(VideoErrorCode.INVALID_CURSOR)`로 바꾼다. `GlobalExceptionHandler`가 HTTP 400과 developCode 3423으로 응답한다.
- 테이블, 컬럼, Redis 키, S3 경로 변경은 없다. 신규 생명주기 콜백, 스케줄러, executor도 없다. 조회는 기존 read-only 서비스 트랜잭션에서 실행한다.
- 잘못 추가됐던 개인 도감 페이지 API와 관련 커서, 저장소, 응답 타입을 제거했다. `GET /api/collections/grids`의 행정동 `limit` 생략은 MSG-388 계약대로 다시 무제한이다.
- 실 PostgreSQL에서 개인 지역 우선 정렬, 개인 지역에서 비개인 지역으로 넘어가는 커서 경계, 전역 게이트와 개인 도감 회귀를 검증했다. 전체 `./gradlew build`가 통과했다.
- 기존 전체 지역 배열 응답을 페이지 객체로 바꾸는 배포 계약이므로 FE가 같은 배포 순서에서 응답 형상을 함께 전환해야 한다.

[^1]: 미리보기 조회: 요청 크기보다 한 행 더 읽어 전체 개수 조회 없이 다음 페이지 존재 여부를 판단하는 방식이다.
[^2]: 키셋 커서: 마지막 행의 정렬값을 다음 조회 경계로 사용하는 방식이다. OFFSET과 달리 뒤 페이지로 갈수록 건너뛰기 비용이 커지지 않는다.
