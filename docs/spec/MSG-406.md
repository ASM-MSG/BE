# MSG-406: 도감·프로필 헤더의 탐험률 요약 제공 (전국 비율과 행정동 진행바)

**Owner**: A (region 패키지, 지도 인프라 도메인)
**요구사항 정본**: `docs/prd/MSG-406-prd.md` (상태: 검토됨, 2026-08-19 행정동 축 정정 반영) /
SRS `FR-REGION-14` (계획)

## 개요

웹 ver 13 개인 도감 헤더의 탐험률 두 값 중, 진행바(현재 위치 행정동 기준 탐험률)는 기존
`GET /api/regions/stats/by-point`(FR-REGION-07)가 분자, 분모, 비율, 이름을 이미 반환하므로 신규
개발이 없다. 이 티켓의 신규 범위는 "전체 지도 0.012% 탐험"(전국 비율)의 재료 하나다. 신규
엔드포인트 `GET /api/regions/stats/national`이 전국 분자(점령 격자 수)와 분모(전국 격자 총수)를
원값 정수 2개로 반환한다. 계산은 쓰기 시점에 물질화[^1]된 `region_stats`와 시딩 시점에 확정된
`regions.total_grid_count`의 합산만으로 하고, 이 경로에서 공간 연산은 하지 않는다(FR-REGION-12
축 유지). 마이그레이션과 신규 인덱스는 없다.

## 배경과 목표

헤더의 나머지 요소(수집 격자 수, 획득 뱃지, 스트릭, 뱃지 진열장, 행정동 진행바)는 기존 API로
성립하는데 전국 비율만 재료가 없다. 전국 격자 총수가 어느 API에도 노출되지 않아 클라이언트가
계산할 수 없다. 이 티켓은 그 값을 기존 행정동 수집률과 같은 재료에서 합산해 제공한다
(PRD FR-1, FR-4, FR-5).

시군구와 시/도 상위 집계(2026-07-22 유예, FR-REGION-13), 행정동 진행바용 신규 API, 타인의
탐험률, `region_stats` 저장 구조 변경은 범위 밖이다. 초안이 담았던 시군구 집계 부활은 진행바
축이 행정동으로 정정되며 철회됐다(PRD 1장).

## 성공 기준

1. 로그인 사용자가 요청 한 번으로 전국 분자/분모를 받는다 (FR-1).
2. 수집이 0인 사용자도 오류가 아니라 분자 0을 받는다 (FR-3).
3. 응답의 분자와 분모는 반올림도 잘라냄도 없는 원값 정수다 (FR-4). 비율 계산, 표시 자릿수,
   100% 상한은 화면 계산 규약 `min(100, 분자/분모 × 100)` 몫이다 (D-3).
4. 전국 분자가 그 사용자의 `region_stats.collected_count` 전체 합과 항상 같다 (FR-5, 정합 검증).
5. 이 엔드포인트의 실행 쿼리에 공간 연산이 없다 (비기능, FR-REGION-12).
6. 행정동 진행바는 이 티켓에서 코드 변경 없이 기존 by-point 계약으로 성립한다 (FR-2, FR-6).

아래 "테스트 시나리오"가 이 기준의 검증 수단이다. 테스트에는 `// 검증: FR-REGION-14` 주석을 단다.

## 결정 사항 (D-항목)

### D-1. 엔드포인트는 신규 `GET /api/regions/stats/national`, 파라미터 없음

전국 전용 조회 하나를 신설한다. 인증 사용자 기준이라 파라미터가 없다.

- **경로 선정**: 기존 `/api/regions/stats` 계열의 접미사는 조회 축을 말한다(`by-point`는 좌표 축,
  `by-grid`는 격자 축). 같은 규약으로 축 이름을 붙여 `national`이다. 초안의 `summary`는 전국과
  시군구 두 값을 묶던 시절의 이름이라, 단일 축이 된 지금은 내용을 말하지 못해 버린다.
- **기존 `GET /api/regions/stats` 확장 기각**: 그 응답은 행정동 행 리스트다. 전국 스칼라를 얹으면
  파라미터에 따라 응답 형태가 갈라져 계약이 흐려진다.
- **by-point 응답 확장 기각**: 전국 블록을 얹는 안은 FE가 이미 소비 중인 응답 계약을 바꾸고,
  전국 값은 위치와 무관해 좌표 입력 엔드포인트에 얹을 이유가 없다. 위치 권한이 거부된 헤더에서도
  전국 비율은 그려야 한다.

### D-2. 응답은 분자/분모 정수만, 비율 필드 없음

FR-4가 반올림하지 않은 원값을 요구한다. 기존 `progress_rate`처럼 소수 2자리로 반올림하면
전국 비율 "0.012%"를 표현할 수 없다(0.01로 뭉개진다). 분자와 분모를 그대로 주고 나눗셈과 표시
자릿수는 화면이 정한다. 비율 필드를 병기하면 FE가 두 재료를 섞어 쓸 위험만 생기므로 넣지 않는다.

### D-3. 100% 상한은 화면의 비율 계산 규약으로 충족

이 API는 비율 필드가 없으므로(D-2) 100% 상한(FR-4)은 비율을 계산하는 지점, 즉 화면의 계산 규약
`min(100, 분자/분모 × 100)`으로 충족한다. `regions.total_grid_count`가 면적 근사값이라 이론상
실제 점령 수가 분모를 넘을 수 있는데, 그때 서버가 분자를 분모로 잘라(clamp[^2]) 내려보내면
실제 수집 개수를 거짓으로 보고하게 되고 원값 요구(FR-4)와 모순되며, FR-5 검증(행정동
`collected_count` 합과의 대조)도 깨진다. 그래서 서버는 분자/분모를 원값 그대로 주고 상한은
비율이 태어나는 곳에서 건다. 행정동 수집률의 서버 측 `LEAST(progress_rate, 100)`(MSG-156 D4)은
서버가 비율 필드를 직접 주는 경우의 처리라 이 결정과 선례 충돌이 아니다. 분모가 0이면 이 나눗셈
자체가 성립하지 않으므로, 화면 규약은 분모 0일 때 비율을 표시하지 않는 것까지 포함해야 완결된다
(API 명세의 분모 0 처리 참조).

### D-4. 전국 분자는 `region_stats.collected_count`의 합

`user_grids` 직접 COUNT 기각. `user_grids`에는 무귀속 격자(해상 등, `grids.region_code`가 빈 격자)의
점령도 실리는데, 전국 분모가 "행정동 귀속 육지 격자 총수"(2026-08-19 확정)라서 그걸 세면 분자와
분모의 축이 어긋난다. `region_stats`는 recompute(MSG-155)가 라벨 있는 격자만 세므로 무귀속 격자가
자연히 빠지고, 행정동 수집률과 재료가 같아 FR-5의 무모순이 구조적으로 성립한다.
전국 분모는 `SUM(regions.total_grid_count)`다.

## API 명세

### GET /api/regions/stats/national

내 전국 탐험률 재료. 토큰 필수(SecurityConfig anyRequest, 자신의 값만 조회 가능). 파라미터 없음.

**성공 200** (`ApiResponseDto` 래핑, `data`):

```json
{
	"collectedCount": 1223,
	"totalCount": 10193482
}
```

- `collectedCount` / `totalCount`: 전국 분자/분모 (Long). 반올림도 잘라냄도 없는 원값이다
  (FR-4, D-3). 근사 분모 탓에 드물게 분자가 분모를 넘을 수 있다.
- FE 조립(계약): 헤더는 두 호출로 그린다. 기존 by-point 1회가 행정동 진행바(분자, 분모,
  progressRate)와 위치줄 재료(regionName)를 주고, 이 신규 조회 1회가 전국 비율 재료를 준다.
  전국 비율은 `min(100, 분자/분모 × 100)`으로 계산하고 표시 자릿수("0.012%")는 화면이 정한다
  (D-3). 진행바 라벨은 by-point의 `regionName`으로 조립한다. 디자인 시안의 라벨 "부산진구
  탐험률"(시군구 이름)과 확정 축(행정동)의 갭은 값 계약과 무관한 디자인 확인 사항으로
  PRD 8장 미해결 항목에 있다.
- FE 계약, 분모 0: 전국 분모 0은 "수집 없음"이 아니라 **기준 데이터 미적재 상태**(regions
  미시딩)다. 나눗셈이 성립하지 않으므로 화면은 그때 비율을 표시하지 않는다(0%로 그리지 않는다).
  서버 동작 변경은 없다(원값 그대로 반환).
- FE 계약, 무귀속 위치(FR-6): 현재 위치가 바다면 by-point가 200 + data null, 국외면
  6400(서비스 범위 밖, FR-REGION-02)을 준다. 그 경우 행정동 진행바만 빠지고, 이 전국 조회는
  위치와 무관하므로 항상 성립해 전국 비율은 그대로 그려진다. 오류 신설 없음.

**에러**:

| 케이스 | HTTP | developCode | 비고 |
|---|---|---|---|
| 미인증 | 401 | 공통 UNAUTHORIZED | 시큐리티 공통 |

새 에러 코드 없음. 좌표도 코드도 받지 않으므로 region 도메인 에러(6400, 6404)와 무관하다.

### DTO

`region/dto/RegionNationalStatResponseDto` (record, 신규). 필드는 위 JSON 그대로 2개, Long 타입
(합산이 bigint, 전국 격자 총수 약 천만 규모). 시각 필드 없음이라 시각 컨벤션 이슈 없음.

## 도메인 로직

- 분자는 점령(첫 영상 업로드로 `user_grids` row가 생긴 상태) 격자 수다. 방문 횟수(videos)가 아니라
  격자 단위라 재방문이 분자를 늘리지 않는다. recompute가 이미 그렇게 세고 있고 이 스펙은 그 합만 읽는다.
- `RegionStatsQueryService`에 메서드 추가 (region 패키지 내부 서비스, 크로스오너 계약 아님):

  ```java
  /** 전국 탐험률 재료 (MSG-406). 분자/분모 원값 2개, 수집 0 이어도 항상 present. */
  RegionNationalStatView findNationalStat(long userId);
  ```

- 구현(`RegionStatsQueryServiceImpl`): 검증할 입력이 없으므로 리포지토리 단건 조회 후 뷰 변환만
  한다. Optional이 아니다. 합산은 행이 없어도 0으로 나오므로 반환값은 항상 present다.
- 리포지토리(`RegionRepository`)에 native 조회 1건 추가. 스칼라 서브쿼리[^3] 2개를 한 문장으로
  묶는다:

  ```sql
  SELECT
  	(SELECT COALESCE(SUM(collected_count), 0) FROM region_stats WHERE user_id = :userId) AS "collectedCount",
  	(SELECT COALESCE(SUM(total_grid_count), 0) FROM regions)                             AS "totalCount"
  ```

  프로젝션 인터페이스 `RegionNationalStatProjection`(getter 2개, Long), 내부 뷰
  `RegionNationalStatView`(record, RegionStatView 선례대로 서비스가 감싸고 DTO 변환은 컨트롤러
  책임). 최종 SQL 형태는 구현에서 다듬어도 되지만, 공간 연산 0과 분자/분모 원값 유지(D-3)는
  불변 조건이다.
- 정합: 운영 중 쓰기 경로에서는 별도 장치 없이 성립한다. 첫 점령과 점령 롤백이 `region_stats`를 같은
  트랜잭션에서 갱신하므로(MSG-155) 이 합산 값도 즉시 반영되고, 롤백이 남긴 0-row는 SUM에 영향이 없다.
  단 기왕의 한계가 하나 있다. `regions` 시딩 전에 발생한 점령은 recompute가 무라벨로 건너뛰어
  `region_stats`에 없고(RegionSeeder는 `grids.region_code` 라벨만 백필하고 `region_stats`는
  재구축하지 않는다), 따라서 이 합산에서도 빠진다. 이는 기존 수집률 조회(`GET /api/regions/stats`)와
  동일한 한계라 이 티켓에서 보정 장치를 새로 만들지 않는다. 보정(라벨 백필 후 `region_stats` 재구축)은
  후속 티켓 후보로 남긴다.

## 데이터 모델

변경 없음. 마이그레이션 없음.

- 신규 인덱스 불요 판단 근거: 분자는 `region_stats` PK `(user_id, region_code)`의 user_id
  프리픽스 스캔(사용자당 최대 3,558행), 분모는 `regions` 전체 스캔이지만 3,558행이라 무시할
  수준이다. p95 300ms(비기능)에 충분할 것으로 예상하며, 구현 단계에서 EXPLAIN ANALYZE 실측을
  작업 로그에 남겨 확정한다 (PRD 7장의 "실행 계획으로 확인" 이행).

## 계약 변경

없음. `RegionStatsQueryService`는 region 패키지 내부 서비스라(MSG-156 §계약 변경 판정 그대로)
크로스오너 계약이 아니고, `GridQueryService` 등 접점 인터페이스는 건드리지 않는다.

기존 테스트(MSG-153)가 그 계약을 이미 검증한다.

## 참고 (구현 착수 시)

- 변경 파일은 PRD 7장 후보 그대로 확정: `RegionRepository`, `RegionStatsQueryService`(+Impl),
  `RegionController`, dto 신규 1건, 테스트. 전부 Owner A.
- SRS FR-REGION-14는 현재 `계획`이다. 구현 완료 시 finalize 절차에서 상태 갱신과 rtm 재생성을
  같은 브랜치에서 함께 커밋한다.

[^1]: 물질화: 조회 때마다 계산하지 않고 쓰기 시점에 결과를 미리 계산해 저장해 두는 방식. region_stats가 그 저장소이고, 이 스펙의 조회는 저장된 값을 더하기만 한다.
[^2]: clamp: 값이 정해진 범위를 넘으면 경계값으로 잘라내는 처리. 이 스펙에서는 서버가 아니라 화면이 비율을 계산하는 지점에서 100 상한으로 적용한다(D-3).
[^3]: 스칼라 서브쿼리: SELECT 목록 안에서 값 하나를 반환하는 하위 쿼리. 분자와 분모 합산을 왕복 한 번의 문장 하나로 묶기 위해 쓴다.
