# MSG-438: 행사 도메인 데이터 모델, 시드, 대표 격자

**Owner**: B. `com.msg.fillmap.event.*`는 신규 패키지라 CLAUDE.md 협업 원칙 목록에 아직 없다.
행사방은 위치별 영상, 댓글, 알림으로 이어지는 콘텐츠 도메인이고 기존 `videos` 테이블을 참조하는
확장 모델(아래 데이터 모델 참조)이므로 Owner B가 맞다. MSG-439 스펙의 Owner B 제안에 동의하며,
CLAUDE.md Owner B 목록에 `com.msg.fillmap.event.*`를 추가하는 커밋은 스키마를 확정하는 이
티켓이 수행한다(439가 편승을 기대하고 있는 지점). grid 도메인 코드는 건드리지 않는다. 이 티켓이
grid에서 가져다 쓰는 것은 격자 계산 규칙의 산술뿐이고, 그마저 아래에서 보듯 투영 호출 없이
인덱스 정수 연산으로 끝난다.

> 요구사항 정본: `docs/prd/event-room-location-videos.md` (확정, 2026-08-20 정민 승인),
> `docs/srs.md` FR-EVENT-07(시리즈와 회차 분리), FR-EVENT-08(격자 영역과 대표 격자 하나).
> 구 PRD `docs/prd/event-room.md`는 제보와 참여 모델이 폐기된 이전 정본이며, 뷰포트 칩 노출,
> 시 칩 묶음, 수동 시드 등재, 미션 축 비연계 결정만 승계된다(SRS FR-EVENT-01 근거란과 일치
> 확인함). 이 스펙은 그중 저장 계층의 "어떻게"만 정한다.

## 개요

행사방의 저장 기반을 만든다. 테이블 다섯 개(`event_series`, `event_occurrences`,
`event_locations`, `event_location_grids`, `event_videos`)와 대응 엔티티, 수동 시드 파일과
기동 시더, 그리고 대표 격자 3단 결정 로직까지가 범위다. API 노출은 MSG-439(조회)와
MSG-440(업로드) 몫이라 이 티켓에는 컨트롤러가 없다.

## 배경, 목표

행사 영상은 행사 위치의 대표 격자[^1] 하나에만 연결하고 영역 전체에 복제하지 않는다는 것이
정본 PRD의 핵심 결정이다(FR-EVENT-08). 그 결정이 성립하려면 저장 계층이 세 가지를 보장해야
한다. 첫째, 같은 행사가 다시 열려도 회차 간 데이터가 섞이지 않는 시리즈와 회차 분리
구조(FR-EVENT-07). 둘째, 영역 내 어느 격자를 눌러도 같은 위치로 해석되는 격자 귀속의
유일성(한 격자는 한 회차 안에서 위치 하나에만 속한다). 셋째, 모든 위치가 항상 유효한 대표
격자 하나를 갖는다는 불변식이다. 이 스펙은 세 보장을 가능한 한 DDL 제약으로 내리고, 제약으로
못 내리는 것만 시더 검증으로 막는다.

## 성공 기준

- 홀수 행과 홀수 열의 직사각형 영역을 시드하면 정중앙 격자가 대표로 저장된다 (PRD 테스트 1).
  판정은 시드 표현이 아니라 전개된 격자 집합의 기하 기준이라, 같은 영역을 사각형 몇 개로
  그렸든 결과가 같다.
- 비직사각형 영역에서는 운영자 지정값이, 지정도 없으면 영역 중심 최근접 포함 격자가 계산되어
  저장된다 (PRD 테스트 2, 3). 세 경로 모두 결과가 결정적이다(같은 입력이면 항상 같은 격자).
- 시드를 반복 실행해도 결과가 같다(멱등[^2]). 영역이 바뀐 재시드는 격자 행을 증분 반영하고
  대표 격자를 다시 계산하며, 격자를 한 위치에서 다른 위치로 옮기는 재시드도 한 트랜잭션에서
  성공한다. 단 영상이 이미 붙은 위치의 대표 격자 변경은 거부된다(아래 시드 참조).
- 한 회차 안에서 두 위치에 같은 격자를 넣은 시드는 DB 제약 위반으로 기동에 실패한다.
  다른 회차끼리는 같은 격자를 각자 가질 수 있다.
- 영상 연결 행의 회차와 위치의 회차가 어긋난 저장은 DDL이 거절한다 (FR-EVENT-07의 미혼합을
  쓰기 시점에 보장, MSG-439가 이 무결성 소유를 438 DDL로 지목한 항목).

아래 "테스트 시나리오"가 이 기준의 검증 수단이다. 테스트에는 `// 검증: FR-EVENT-07` 형식
주석을 단다(finalize 2-1).

## 도메인 로직

### 대표 격자 3단 결정 (FR-EVENT-08, PRD §4.1)

시딩 시점에 계산해 `event_locations.representative_grid_id`에 저장한다. 조회와 업로드는
저장값만 읽는다. 계산 입력은 시드의 사각형 목록이 아니라 **전개된 격자 집합**(사각형 합집합을
셀 단위로 펼치고 중복 제거한 것)이다. 같은 영역을 어떤 사각형 조합으로 표현했든 집합이 같으면
결과가 같아야 하므로, 판정을 표현이 아니라 기하에 건다. 결정 순서:

1. **홀수 직사각형 정중앙**: 집합의 경계 상자(`minGridY..maxGridY`, `minGridX..maxGridX`)에
   대해 `집합 크기 == 행 수 × 열 수`이면 영역은 직사각형이다(표현 무관 판정). 행 수
   `maxGridY - minGridY + 1`과 열 수 `maxGridX - minGridX + 1`이 모두 홀수면, 대표는
   `((minGridY + maxGridY) / 2, (minGridX + maxGridX) / 2)`다(합이 짝수라 정수 나눗셈이
   정확히 떨어진다). 이 경우 시드에 운영자 지정값이 있는데 정중앙과 다르면 모순 데이터로
   보고 시딩을 실패시킨다. FR-4가 정중앙을 무조건으로 요구하므로 지정값을 조용히 무시하면
   시드 파일과 저장값이 어긋난 채 남기 때문이다.
2. **운영자 지정**: 영역이 1의 조건을 벗어나면 시드의 `representativeGridId`를 쓴다. 지정
   격자가 영역 밖이면 시딩을 실패시킨다(FR-3 "유효한 대표 격자". DDL 복합 FK가 최종
   방어선이지만 지연 제약 위반 메시지는 읽기 어려우므로 시더가 먼저 명확한 메시지로 막는다).
3. **영역 중심 최근접 계산**: 지정도 없으면 영역 중심에 가장 가까운 소속 격자를 고른다.
   집합 크기 `n`, 좌표 합 `Sy = Σ gridY`, `Sx = Σ gridX`에 대해
   `(n·gridY - Sy)² + (n·gridX - Sx)²`를 최소화하는 격자다(중심 `(Sy/n, Sx/n)`과의 거리
   제곱에 `n²`을 곱한 동치식이라 **long 정수 산술만으로 비교**되고 부동소수점 오차가 없다).
   동률이면 `gridY`가 작은 것, 그다음 `gridX`가 작은 것(남서 우선)으로 결정성을 확보한다.

투영 호출이 필요 없는 이유: 격자 계산 규칙(EPSG:5179[^3], glossary)에서 인덱스 공간은 미터
평면을 100분의 1로 축소한 균일 평면이라, 인덱스 거리 비교가 실거리 비교와 동치다. 셀 중심
오프셋 0.5도 양변에서 상쇄되므로 순수 정수와 평균 연산으로 끝난다. `GridEncoder`를 부르지
않는다.

구현 위치 제안: `com.msg.fillmap.event.seed.RepresentativeGridResolver` (순수 함수, 시더만
호출). 입력은 전개된 영역 격자 집합과 운영자 지정값, 출력은 `"{gridY}_{gridX}"` 격자 id다.

### 행사 상태는 파생값 (저장 컬럼 없음)

PRD §8은 `status`와 `uploadClosesAt` 컬럼을 제안하지만 **둘 다 저장하지 않는다**. 두 값은
`startsAt`, `endsAt`와 서버 시각만으로 완전히 계산되고, 저장하면 일정 변경(행사 알림의 존재
이유가 일정 변경이다) 때 파생값과 어긋나는 잠복 버그가 생기며, 상태 전환 배치가 필요해진다.
파생으로 두면 PRD §10의 "상태 전환 작업은 재실행해도 안전해야 한다"는 요구가 작업 자체의
소멸로 충족된다(FR-22 서버 시각 판정과도 일치).

- `EventOccurrence.uploadClosesAt()` = `endsAt.plusDays(UPLOAD_GRACE_DAYS)`, 상수
  `UPLOAD_GRACE_DAYS = 30`.
- `EventOccurrence.statusAt(LocalDateTime now)` 도메인 메서드를 이 티켓이 구현한다(439가
  제안한 시그니처 채택). 반환 enum `EventStatus { UPCOMING, LIVE, UPLOAD_GRACE, ARCHIVED }`
  (비영속). 경계는 전부 반개구간[^4]이다: `now < startsAt`이면 UPCOMING,
  `startsAt <= now < endsAt`이면 LIVE, `endsAt <= now < uploadClosesAt()`이면 UPLOAD_GRACE,
  그 이후는 ARCHIVED. 정각은 다음 상태에 속한다(439 API 2의 정의와 동일, 정의는 이 메서드
  한 곳에만 둔다).
- `now`는 호출자가 주입한다. 엔티티 안에서 `LocalDateTime.now()`를 부르지 않는다
  (시각 컨벤션 MSG-376).

### EventVideo는 videos의 확장이다

행사 영상 레코드는 독립 파일 컬럼(PRD §8의 `videoUrl`, `thumbnailUrl` 등)을 갖지 않고 기존
`videos` 행을 1:1로 참조한다. 근거는 PRD §10의 "영상 접근 권한, 신고, 삭제 등 기존 공통 영상
정책을 그대로 적용한다"이다. 신고(`reports.video_id`), 처리 파이프라인(인코딩, AI 블러,
READY 전이), 소프트 삭제[^5](`VideoStatus.DELETED`), 재생 접근 제어가 전부 `videos` 행을
축으로 돌아가므로, 독립 테이블이면 그 전부를 복제해야 한다. PRD §8의 필드 제안 중
`videoUrl`, `thumbnailUrl`, `durationSeconds`, `capturedAt`, `createdAt`은 `videos`의 기존
컬럼(`encodedUrl`, `thumbnailUrl`, `duration_sec`, `recorded_at`, `created_at`)이 대신하고,
`interactionLocked`는 회차 상태의 파생값이라 저장하지 않는다. **영상 길이 제한도 기존과
동일하다(최대 30초, 2026-08-20 사용자 확정)**: `videos.duration_sec`(NOT NULL)가 이미 있고
US-004 카드의 길이 표시 재료도 이 컬럼이다. 상한 검증은 기존 업로드 검증을 440이 재사용한다.

이 선택의 귀결 세 가지를 명시한다.

- **노출 술어는 기존 전역 게이트와 동일**: 439의 `videoCount`와 440의 피드가 공유할 술어는
  `videos` 조인 후 `status = ACTIVE AND visibility = PUBLIC AND processing_status = READY`다.
  삭제(DELETED), 블라인드(BLINDED), 비공개, 처리 미완료가 한 술어로 걸러지므로 숫자와 피드의
  불일치, 존재 노출이 구조적으로 없다. 440 업로드는 공개범위를 PUBLIC으로 고정한다(행사
  피드는 공개 전제, 공개범위 선택 UI가 PRD에 없음). **PUBLIC 고정의 자연 귀결로, 기존
  공개범위 변경 API는 `event_videos` 행이면 요청을 거부한다**(행사 영상을 FRIENDS나
  PRIVATE로 바꾸면 행사 피드에서 사라져 고정이 무의미해진다). 강제와 차단 구현 모두 440
  쓰기 경로 몫이다.
- **전역 격자 피드에도 보인다 (2026-08-20 사용자 확정: "영상을 올리면 그 격자에 남아야
  한다")**: 행사 영상은 대표 격자에 놓인 정상 `videos` 행이므로 기존 격자 전역 조회(대표
  영상, 전역 목록)에 그대로 잡히고, 이것이 확정된 제품 정책이다. 별도 필터 코드가 없다.
- **점령도 일반 업로드와 동일하게 만든다 (2026-08-20 사용자 확정, 당일 번복)**: 당초 위치
  증거 부재(PRD §4.3)를 근거로 "점령 미생성"을 같은 날 확정했으나, 사용자가 당일
  번복했다(원문 "행사 영상도 점령을 만들어야 한다"). 안 가 본 격자가 도감에 칠해지는
  트레이드오프를 인지한 채 도감 노출을 우선한 결정이다. 따라서 440 업로드는 기존 확정
  경로의 점령 부수효과(`upsertUserGrid`, 수집률 갱신)를 그대로 타고, 삭제도 기존 점령 롤백
  경로(`VideoServiceImpl:356`의 `decrementVideoCount`부터 `deleteUserGridIfEmpty`,
  `reselectCover`)를 그대로 탄다. 별도 분기 코드가 없다.

**기존 업로드 파이프라인 부수효과 계약**. 번복 확정으로 행사 영상은 점령을 포함해 일반
업로드의 부수효과를 전부 그대로 받는다. **제외는 미션 하나뿐이다**(구 PRD 승계 확정 "미션
비연계" 유지). 포함 항목 중 스트릭, 핫스코어, 업로드 수 뱃지는 글로서리 정본("재방문 포함
아무 업로드", "모든 업로드 신호")에서 도출한 정본 준수 기본값이며 사용자 번복 가능하다.

| 뱃지 판정 전체(UPLOAD_COUNT, TOTAL_GRIDS, REGION_PERCENT, STREAK_DAYS) | 적용 | 점령 생성으로 collection 축도 정상 성립. 집계 원천은 `UserBadgeRepository.countMyVideos:48`, `countMyGrids:52`, `findMyRegionProgress:62`, 판정 훅(`awardCollectionBadges` 포함) 그대로 호출 |
| 획득 뱃지 즉시 응답(newBadges) | 적용 | FR-BADGE-05, 업로드 응답 동봉 선례(`VideoUploadResponseDto:35`), 구현 440 |
| 도감 지표, 지역별 목록, 커버·썸네일 | 적용 | 점령·`videos` 행 기반 집계에 자동 포함 (`UserGridRepository.getCollectionSummary:43`, `getRegionVideos:139`, `getCollectionGridsForFriend:157`, `VideoRepository.reselectCover:388`) |

**구현 노트 (미션 제외 계약의 배포 게이트)**: 미션 쿼리의 안티조인 여섯 쿼리는 **MSG-450**이
구현한다(439와 440 범위 밖, 미션 도메인 쿼리 측). **배포 게이트: MSG-450은 MSG-440 배포 전에,
늦어도 440과 같은 배포 단위에 들어가야 한다.** 440이 먼저 나가면 첫 행사 업로드부터 미션
진행도에 행사 영상이 섞여 "미션 비연계" 확정이 즉시 깨진다. 계약 자체(행사 영상은 미션 진행에
잡히지 않는다)는 이 스펙이 정본이다.

`videos.grid_id`가 대표 격자와 일치한다는 보장은 서비스 계층이 소유한다(440 쓰기 경로와 그
테스트). DDL로도 표현할 수는 있다: `event_videos`에 `grid_id`를 중복으로 두고
`videos(id, grid_id)`와 `event_locations(id, representative_grid_id)` 양쪽에 복합 FK를 걸면
된다. 채택하지 않는 근거: `videos`에 `UNIQUE(id, grid_id)` 추가 마이그레이션과 중복 컬럼이
필요한데, FK가 막아줄 시나리오(영상이 있는 위치의 대표 격자 변경)는 시더 가드(아래 시드
참조)가 이미 막아 추가 보장이 중복되고, 남는 쓰기 지점이 440 하나뿐이라 서비스 강제와
테스트로 충분하다.

`videos`의 NOT NULL 요건도 기존 경로가 채운다(구현 440): 행사 업로드는 좌표 입력이 없으므로
`geom`만 대표 격자 중심점(`GridEncoder`의 셀 중심 위경도 변환)으로 서버가 채우고, `grids` 행
생성(lazy insert)과 점령은 기존 업로드 확정 경로가 그대로 수행한다.

## 데이터 모델

Flyway `V39__event_room_schema.sql` 하나로 테이블 다섯 개를 만든다. 댓글과 도움돼요 테이블은
MSG-441 몫(V40 이후)이고, 알림 구독은 MSG-442 몫이다.

```sql
-- V39__event_room_schema.sql
-- MSG-438: 행사방 저장 기반. 시리즈/회차 분리(FR-EVENT-07), 격자 영역과 대표 격자(FR-EVENT-08).
-- 격자 컬럼은 grids 테이블을 FK 하지 않는다(lazy insert 전략상 행 존재가 보장되지 않음).

CREATE TABLE event_series (
	id         BIGSERIAL PRIMARY KEY,
	series_key VARCHAR(50) NOT NULL UNIQUE,  -- 시딩 UPSERT 자연키, 예: "biff"
	name       VARCHAR(100) NOT NULL
);

CREATE TABLE event_occurrences (
	id              BIGSERIAL PRIMARY KEY,
	event_series_id BIGINT NOT NULL REFERENCES event_series(id),
	occurrence_key  VARCHAR(60) NOT NULL UNIQUE,  -- 자연키, 예: "biff-busan-2026"
	title           VARCHAR(100) NOT NULL,
	city_name       VARCHAR(30) NOT NULL,   -- 시 칩 묶음 기준 라벨, 예: "부산" (FR-EVENT-01)
	starts_at       TIMESTAMP NOT NULL,     -- UTC (전 테이블 공통, MSG-376 체계)
	ends_at         TIMESTAMP NOT NULL,
	visible_from    TIMESTAMP NOT NULL,     -- 칩 노출 시작 = starts_at - 14일 (파생 고정, 시더 계산)
	min_grid_y      INTEGER NOT NULL,       -- 노출 영역 정수 사각형(뷰포트 겹침 판정 재료, zones 선례)
	max_grid_y      INTEGER NOT NULL,
	min_grid_x      INTEGER NOT NULL,
	max_grid_x      INTEGER NOT NULL,

	CONSTRAINT chk_event_occ_period    CHECK (starts_at < ends_at),
	-- 파생 규칙을 DDL로 고정: 어떤 쓰기 경로도 2주 전 정책을 우회하지 못한다 (2026-08-20 확정)
	CONSTRAINT chk_event_occ_visible   CHECK (visible_from = starts_at - INTERVAL '14 days'),
	CONSTRAINT chk_event_occ_y_range   CHECK (min_grid_y <= max_grid_y),
	CONSTRAINT chk_event_occ_x_range   CHECK (min_grid_x <= max_grid_x)
);

CREATE TABLE event_locations (
	id                     BIGSERIAL PRIMARY KEY,
	event_occurrence_id    BIGINT NOT NULL REFERENCES event_occurrences(id),
	location_key           VARCHAR(60) NOT NULL UNIQUE,  -- 자연키, 예: "biff-2026-cinema-center"
	name                   VARCHAR(100) NOT NULL,        -- "영화의전당"
	type                   VARCHAR(20) NOT NULL,         -- EventLocationType enum 문자열
	operating_hours        VARCHAR(100),                 -- 표시용 문자열, 없는 위치(퍼레이드) NULL
	display_order          INTEGER NOT NULL DEFAULT 0,   -- 위치 목록 정렬 1차 키(439 계약)
	representative_grid_id VARCHAR(20) NOT NULL,

	CONSTRAINT uq_event_locations_id_occ UNIQUE (id, event_occurrence_id)  -- 비정규화 FK 대상
);

CREATE TABLE event_location_grids (
	event_location_id   BIGINT NOT NULL,
	event_occurrence_id BIGINT NOT NULL,     -- 비정규화: 회차 내 격자 유일성 제약 재료
	grid_id             VARCHAR(20) NOT NULL,

	PRIMARY KEY (event_location_id, grid_id),
	-- 한 격자는 한 회차 안에서 위치 하나에만 귀속(439 계약 3). 행 단위 저장이라 EXCLUDE 불요.
	-- DEFERRABLE: 격자를 위치 A에서 B로 옮기는 재시드에서 Hibernate flush 가 insert 를 delete 보다
	-- 먼저 실행하므로, 즉시 제약이면 순서 통제가 필요해진다. 커밋 시점 검증으로 순서 의존을 없앤다.
	CONSTRAINT uq_event_grid_per_occ UNIQUE (event_occurrence_id, grid_id)
		DEFERRABLE INITIALLY DEFERRED,
	-- 비정규화 정합: 격자 행의 회차 = 소속 위치의 회차임을 DDL이 보장
	CONSTRAINT fk_event_grid_location FOREIGN KEY (event_location_id, event_occurrence_id)
		REFERENCES event_locations(id, event_occurrence_id) ON DELETE CASCADE
);

-- 대표 격자는 반드시 영역 소속(FR-3). 순환 참조라 지연 제약: 같은 트랜잭션 안에서
-- 위치 insert 후 격자 insert 가 가능하고, 커밋 시점에 소속이 검증된다.
ALTER TABLE event_locations
	ADD CONSTRAINT fk_event_loc_rep_grid FOREIGN KEY (id, representative_grid_id)
		REFERENCES event_location_grids(event_location_id, grid_id)
		DEFERRABLE INITIALLY DEFERRED;

CREATE TABLE event_videos (
	video_id            BIGINT PRIMARY KEY REFERENCES videos(id) ON DELETE CASCADE,
	event_occurrence_id BIGINT NOT NULL,
	event_location_id   BIGINT NOT NULL,

	-- 영상의 회차 = 소속 위치의 회차(FR-EVENT-07 미혼합의 쓰기 시점 보장)
	CONSTRAINT fk_event_video_location FOREIGN KEY (event_location_id, event_occurrence_id)
		REFERENCES event_locations(id, event_occurrence_id)
);

-- 위치별 count(439)와 피드(440)의 조회 키. 사용자 콘텐츠라 증가 테이블이므로 인덱스를 단다.
CREATE INDEX idx_event_videos_location ON event_videos(event_location_id);
```

- `video_id`가 PK이므로 한 영상은 최대 하나의 행사 위치에만 연결된다(FR-7 "각각 한 번만").
- 행사 이미지 필드는 **이번 범위 없음 확정(2026-08-20 사용자)**이라 컬럼을 두지 않는다.
  US-002의 행사 이미지는 이번 범위에서 서버 재료가 없다.
- `event_location_grids`에 역조회(`grid_id` 선두) 인덱스를 달지 않는다. 수동 시드 소량(도시별
  행사 한두 개, 위치당 격자 수십)이라 어떤 접근도 인덱스를 주도로 타지 않는다(zones V8 선례와
  같은 근거). 행사 수가 커지면 그때 단다.
- `event_series`와 회차, 위치, 격자 행의 시드 파일 삭제는 DB 반영하지 않는다(아래 시드 참조).
  행 삭제가 필요하면 수동 SQL이다. 아카이브 보존이 요구사항(US-010)이라 자동 삭제가 더
  위험하다.

## 시드

zones 선례(`seed/zones.json`, 기동 시 멱등 UPSERT, MSG-259 D-8)를 따르되 계층 구조라 파일
형태와 갱신 로직은 이 스펙이 새로 정한다.

- 파일: `src/main/resources/seed/events.json`. 등재 기준은 BTS 부산 콘서트급 초대형 행사만,
  도시별 한두 개다(FR-EVENT-01 "행사 추가는 시드 행 추가만으로 끝난다"). 등재할 행사의
  선정은 사용자가 실제 영향력을 직접 보고 결정한다(2026-08-20 확정). **첫 시드 3건도 같은
  날 사용자가 선택했다**(아래 시드 실값 초안 참조).
- 시더: `com.msg.fillmap.event.seed.EventSeeder` (`ApplicationRunner`).
  `fillmap.event.seed.enabled`(기본 false), dev와 prod 프로파일에서 상시 on(zones와 동일
  운영). regions 등 타 시더와 FK 의존이 없지만 결정성을 위해 `@Order(30)`을 준다(Region 10,
  Zone 20 다음).
- 갱신 로직: 자연키(series_key, occurrence_key, location_key)로 찾아 있으면 갱신, 없으면
  생성한다. zones의 native UPSERT와 달리 JPA 조회 후 저장으로 구현한다. 격자 영역 대조(추가
  행 insert, 제거 행 delete)를 위해 읽기가 어차피 필요하고, ON CONFLICT 같은 PostgreSQL 전용
  기능이 필요한 지점이 없어 native 최소화 권고(2026-08-19 멘토링)에 부합한다. 전체가
  `@Transactional` 한 번이라 두 지연 제약(격자 유일, 대표 격자 소속)도 커밋 시점에 함께
  검증된다. **시더끼리의 동시 실행은 트랜잭션 서두의 advisory lock으로 직렬화한다**
  (`pg_advisory_xact_lock`에 고정 키. 행이 아니라 임의의 키에 거는 PostgreSQL 잠금이라 아직
  존재하지 않는 행에 대한 경쟁도 막고, 트랜잭션 종료 시 자동 해제된다): 롤링 배포 중 두
  인스턴스의 `ApplicationRunner`가 동시에 돌 때 신규 행은 존재하지 않아 행 잠금을 걸 수 없고,
  동시 INSERT는 자연키 UNIQUE 위반으로 한쪽 기동을 실패시키기 때문이다. advisory lock은
  PostgreSQL 전용이라 native 허용 대상이다(`VideoRepository.acquirePendingKeyConfirmLock:349`
  선례).
- `visible_from`은 시드 입력이 아니다. **시더가 항상 `startsAt - 14일`로 계산해 저장한다**
  (2026-08-20 사용자 확정 "행사 시작 2주 전"). 시드 JSON에 필드 자체가 없어 우회할 수 없고,
  DDL CHECK(`visible_from = starts_at - INTERVAL '14 days'`)이 다른 쓰기 경로까지 막는다.
  **기존 회차의 일정 변경 재시드에서는 회차 갱신 메서드가 `startsAt`과 `visibleFrom`을 항상
  함께 세팅한다**(한 flush의 단일 UPDATE로 두 컬럼이 같이 나가므로 행 단위 CHECK 등식이
  중간 상태 없이 유지된다).
- 대표 격자는 매 실행 3단 규칙으로 재계산해 저장한다. 계산이 결정적이라 재계산이 곧
  멱등이고, 영역이 바뀐 재시드에서 갱신을 따로 다룰 필요가 없다. **단 그 위치에
  `event_videos`가 1건이라도 있으면, 재계산 결과든 지정값이든 기존 저장값과 다른 대표
  격자로의 변경을 거부하고 명확한 메시지로 기동을 실패시킨다.** 기존 영상은 옛 격자에, 신규
  영상은 새 격자에 붙어 위치의 피드와 격자 노출이 갈라지는 드리프트를 막기 위해서다.
  **이 확인은 440 업로드와의 동시성 계약과 함께다**(시더끼리는 위 advisory lock이 담당):
  시더는 대표 격자 재계산 전에 해당 `event_locations` 기존 행을 `SELECT FOR UPDATE`(JPA
  `@Lock(PESSIMISTIC_WRITE)` 파생 쿼리, 구현명 `findWithLockByLocationKey`)로 잠근 뒤
  `event_videos` 존재를 확인하고, 440 업로드 경로도 `videos.grid_id`를 결정하기 위해 대표
  격자를 읽을 때 같은 행 잠금(또는 잠금 후 재독)을 따른다. 같은 행 하나를 같은 순서로
  잠그므로 교착이 없다. 영상 이전(기존 `videos.grid_id`와 `geom`을 새 대표 격자로 일괄
  UPDATE)은 도입하지 않는다. 대표 격자를 정말 옮겨야 하는 날이 오면 그 이전 로직이
  업그레이드 경로다.
- 시드 형식 검증은 fail-fast다: `areaRects`가 비었거나, 어느 사각형이든 `min > max`로
  역전됐으면 즉시 기동 실패다(빈 영역은 대표 격자가 성립할 수 없고, 역전은 전개 결과가
  빈 집합이 되어 오류가 조용히 숨는다). 격자 인덱스는 0 초과 100,000 미만만 허용한다
  (EPSG:5179 국내 정의역을 넉넉히 포함하는 방어 상한, 정수 제곱 산술의 오버플로 여유 확보).
  위치당 **고유 셀 수**는 2,500(5km × 5km 상당)을 상한으로 한다(zones의 남북 26행 캡과 같은
  성격의 입력 상한). 검사는 두 단계다: 단일 사각형의 `행 수 × 열 수`가 2,500을 넘으면 전개
  전에 즉시 거부하고(단일 사각형의 고유 셀 수는 정확히 `행 수 × 열 수`라 과잉 거부가 없는
  OOM 1차 가드), 여러 사각형의 합집합은 고유 셀 집합에 하나씩 추가하다가 2,501번째 고유
  셀에서 즉시 실패한다. 겹침을 중복으로 세지 않으므로 같은 영역의 다른 표현이 다른 판정을
  받지 않는다(표현 무관 계약 유지).
- 파일에서 사라진 시리즈, 회차, 위치는 삭제하지 않는다(위 데이터 모델 참조). 위치 안의 격자
  행만 파일과 완전 일치로 동기화한다. 격자 행은 `event_locations.representative_grid_id`의
  지연 FK가 참조하므로, 삭제가 안전한 이유는 "참조가 없어서"가 아니라 같은 트랜잭션에서
  대표 격자를 재계산해 갱신하고 커밋 시점에 FK가 성립함을 검증하기 때문이다.
- 파일을 못 읽으면 기동 실패(fail-fast, ZoneSeeder와 동일). 빈 배열은 정상이다.

## MSG-439 계약 입력 5건 판정

439 스펙의 선행 의존 체크리스트와 대조한 결과다. 초기 판정에서 "439 표기 교체 필요"로 지목했던
3건(uploadClosesAt 파생값, 저장 status 컬럼 없음, 행사 이미지 동봉 없음)은 **439 세션이 이미
반영했음을 현행 MSG-439.md 기준으로 확인했다.** 아래 항목 1의 지목 이력은 그 반영의 근거
기록으로 남긴다.

1. **회차 조회 재료 (채택)**: `min/max_grid_y/x` 노출 사각형, `city_name`, `visible_from`을
   439가 가정한 이름 그대로 `event_occurrences`에 둔다. 표기 교체 불필요. 지목했던 정정
   3건은 439에 반영 완료됐다: `uploadClosesAt`은 저장값이 아니라 파생값(`uploadClosesAt()`)
   노출이고(응답 필드 계약 불변), 저장 `status` 컬럼은 없어 파생 전용이며(439는 이미
   파생값만 사용), **행사 이미지는 이번 범위 없음 확정**(2026-08-20 사용자)이라 컬럼도
   응답 동봉도 없다. `statusAt(now)` 제안은 채택했고 정의는 이 티켓의 엔티티 한 곳이다.
2. **EventVideo 노출 술어 재료 (채택, 표현 확정)**: `videos` 1:1 참조 모델이므로 술어는 기존
   전역 게이트 그대로 `status = ACTIVE AND visibility = PUBLIC AND processing_status = READY`다
   (439가 가정한 술어와 일치). 소프트 삭제는 `VideoStatus.DELETED`로 표현되어 같은 술어에
   포함된다. 439의 `videoCount`와 440 피드가 이 술어 하나를 공유하면 된다.
3. **격자 귀속 유일성 (채택, DDL 층으로 확정)**: EXCLUDE 제약이 필요 없다. PRD §8이 영역을
   사각형이 아니라 격자 행 단위(`EventLocationGrid`)로 저장하므로, 회차 id를 비정규화[^6]한
   `UNIQUE (event_occurrence_id, grid_id)` 하나로 잡힌다(재시드 순서 의존을 없애기 위해
   지연 제약이며 커밋 시점 검증이다). 비정규화 값의 정합은 복합 FK가 보장하므로 시드 검증
   층에 의존하지 않는다(시드 아닌 쓰기 경로가 생겨도 제약이 유지된다).
4. **표시 순서 필드 (채택)**: `display_order INTEGER NOT NULL DEFAULT 0`. 439 위치 목록 정렬
   1차 키로 쓰면 된다(동률 타이브레이커 `locationId`는 439 결정 유지).
5. **SRS FR-EVENT-02 "일정과 프로그램 안내" 문구 (스펙 범위 아님 확인)**: 정본 PRD US-002에
   없는 구 PRD 잔재가 맞다. 이 스펙의 어떤 테이블에도 일정, 프로그램 필드를 두지 않으며,
   SRS 문구 보정(해당 구절 삭제)을 이 티켓의 docs 커밋 계획에 포함한다(439가 438 편승을

- `격자를_다른_위치로_옮기는_재시드가_한_트랜잭션에서_성공한다` (지연 UNIQUE, flush 순서
  무관 검증)
- `기존_회차의_시작_시각을_바꾸는_재시드가_성공하고_visible_from도_함께_이동한다`
  (CHECK 등식과 동시 갱신 계약)
- `한_회차에서_두_위치에_같은_격자를_넣은_시드는_실패한다` (uq_event_grid_per_occ)
- `다른_회차는_같은_격자를_각자_가질_수_있다` (제약 범위가 회차 단위임을 검증,
  검증: FR-EVENT-07)
- `격자_행의_회차와_위치의_회차가_다르면_저장이_거절된다` (복합 FK)
- `영상_연결의_회차와_위치의_회차가_다르면_저장이_거절된다` (복합 FK, 검증: FR-EVENT-07)
- `대표_격자가_영역_격자_행_없이_커밋되면_지연_FK가_거절한다`
- `빈_영역이나_역전된_사각형_시드는_기동이_실패한다` (형식 fail-fast)
- `좌표_범위나_고유_셀_수_상한을_넘는_시드는_기동이_실패한다` (단일 사각형 전개 전 가드와
  합집합 고유 셀 2,500 상한. 겹치는 사각형 표현이 고유 셀 기준으로는 상한 안일 때 통과하는
  케이스 포함)
- `visible_from은_항상_시작_2주_전으로_계산돼_저장된다` (파생 고정, DDL CHECK 포함 검증)
- `시드_시각의_KST_오프셋_표기는_UTC로_저장된다` (MSG-376 체계)
- `오프셋_없는_시드_시각은_파싱_실패로_기동이_멈춘다`
- `시드_파일이_없으면_기동이_실패하고_빈_배열은_정상이다` (ZoneSeeder 선례)
- `파일에서_사라진_회차는_삭제되지_않는다` (아카이브 보존)

파생 상태 (`EventOccurrence`):

- `상태_파생_계산은_반개구간이다` (endsAt과 uploadClosesAt 정각이 각각 UPLOAD_GRACE와
  ARCHIVED에 속하는 4상태 경계, 439와 공유하는 정의의 정본 테스트)
- `업로드_마감_시각은_종료_30일_후로_파생된다`

부수효과 계약의 검증(점령 포함 기존 업로드·삭제 경로 그대로 동작, PUBLIC 고정과 공개범위
변경 차단, newBadges 동봉, 업로드 측 잠금 계약)은 쓰기 경로 소유자인 MSG-440 테스트 몫이고,
미션 안티조인 여섯 쿼리의 검증은 MSG-450 몫이다(위 구현 노트의 배포 게이트 포함). 시더끼리의
동시 실행 직렬화(advisory lock)는 위 동시성 통합 테스트와 별개로, 실환경 재현이 어려워 잠금
획득 호출의 존재를 단위 검증하는 수준으로 남긴다.

## 미해결 질문

행사 업로드의 점령 여부(**미생성 확정 후 2026-08-20 당일 번복, 최종: 일반 업로드와 동일하게
생성**), 전역 격자 피드 노출(포함 확정), 영상 길이 재료(`videos.duration_sec` 실재로 해소,
30초 제한 동일 확정), `visibleFrom` 정책(시작 2주 전 파생 고정 확정), 첫 시드 행사 선택(3건
확정)은 모두 종결됐다. 스트릭, 핫스코어, 업로드 수 뱃지 포함은 글로서리 정본에서 도출한
기본값이다(정본 준수 기본값, 사용자 번복 가능). 남은 것 한 건:

1. **시드 초안값의 세부 확정**: 격자 인덱스는 앵커 보간 초안이라 구현 단계의
   `GridEncoder.encode` 전수 재계산으로 확정한다(테스트
   `첫_시드_실값의_기준_위경도가_초안_격자와_일치한다`가 게이트). 시작·종료 시각(시 단위)과
   영역 사각형 크기도 제안값이라 사용자가 조정할 수 있다. 어느 쪽도 구현 착수를 막지 않는다
   (시드 행 값 교정만으로 끝난다).

[^1]: 대표 격자: 행사 위치의 영역 격자 중 영상 레코드가 실제로 연결되는 단 하나의 격자.
    영역 전체에 영상을 복제하지 않기 위한 장치다 (FR-EVENT-08).
[^2]: 멱등(idempotent): 같은 작업을 여러 번 실행해도 한 번 실행한 것과 결과가 같은 성질.
    기동마다 도는 시더가 이 성질을 가져야 재시작이 안전하다.
[^3]: EPSG:5179: 한국 국토 평면 좌표계. 미터 단위 평면이라 좌표를 100으로 나누면 100m 격자
    인덱스가 나오고, 인덱스 공간의 거리 비교가 실거리 비교와 비례해 동치다.
[^4]: 반개구간: 시작점은 포함하고 끝점은 제외하는 구간 표기. 경계 정각이 정확히 한 상태에만
    속하게 만들어 상태 판정의 빈틈과 겹침을 없앤다.
[^5]: 소프트 삭제(soft delete): 행을 지우는 대신 상태 값(여기서는 `VideoStatus.DELETED`)으로
    삭제를 표시하는 방식. 참조 무결성과 이력을 보존하면서 노출만 끊는다.
[^6]: 비정규화: 다른 테이블에서 조회로 얻을 수 있는 값을 성능이나 제약 표현을 위해 중복
    저장하는 설계. 여기서는 격자 행에 회차 id를 중복 저장해 "회차 내 격자 유일" 제약을 단일
    UNIQUE로 표현했고, 중복 값의 정합은 복합 FK가 지킨다.
[^7]: 안티조인(anti join): 다른 테이블에 대응 행이 **없는** 행만 남기는 조회 방식. SQL로는
    `NOT EXISTS (SELECT 1 FROM event_videos ev WHERE ev.video_id = v.id)` 형태이며, 여기서는
    "행사 영상이 아닌 videos만 센다"를 표현한다.
