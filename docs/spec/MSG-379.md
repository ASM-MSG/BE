# MSG-379: 시각 저장의 환경 의존 잔재 정리 (MSG-376 후속)

**Owner**: 공동 (파일별 배정은 아래 "오너십" 절. PRD 면제: 기존 규약 "naive 시각 = UTC"의 잔재
정리라 제품 요구사항을 만들거나 바꾸지 않는다. 요구사항 정본은 Jira MSG-379 티켓 본문과
`docs/spec/MSG-376.md` 작업 로그의 후속 티켓 발행 항목. Codex 1라운드 리뷰 반영 개정판:
잔여 경로 인벤토리를 DEFAULT 위임 경로까지 확장하고 D8 마이그레이션 설계로 교체.
2라운드 반영: V33 이전 시드 마이그레이션 수용 조항 확장, 변경 파일 표 보완)

## 개요

MSG-376이 API 경계와 주요 쓰기 경로를 "naive `LocalDateTime`[^1] 값 = UTC" 관례로 고정했지만,
그 올바름이 아직 실행 환경에 기대는 지점이 남아 있다. 서버(EC2)는 JVM이 UTC라 앱 경로가
정상이지만, 로컬 KST 맥에서 앱을 띄우거나 DB 컨테이너에 psql로 직접 SQL을 실행하면(목 데이터
시딩 실사례) KST 벽시계가 저장돼 9시간 어긋난다. 이 티켓은 그 환경 의존 경로를 0곳으로 만든다.

## 배경, 목표

- 컨벤션 정본은 `.claude/rules/project-conventions.md`의 "시각(날짜·시간) 처리 (MSG-376 명문화)"
  절이다. 이 티켓은 그 컨벤션이 코드와 환경 양쪽에서 실제로 성립하게 만드는 마무리 작업이다.
- 메커니즘 정리(판정의 공통 전제):
  - pgJDBC[^2]로 붙는 앱 세션의 타임존은 앱 JVM의 기본 존을 따른다. 컨테이너의 `TZ` 환경변수는
    앱 세션에 영향이 없고, psql 직접 세션과 DB 로그 표기에만 영향을 준다.
  - naive `timestamp` 컬럼에 `LocalDateTime`을 파라미터로 바인딩하면 세션 존 변환 없이 벽시계
    그대로 저장된다. 반면 SQL 안의 맨 `now()`[^3]와 `DEFAULT CURRENT_TIMESTAMP` 평가는
    `timestamptz`라서 `timestamp` 컬럼에 대입될 때 세션 존으로 캐스트된다. 그래서 같은 쿼리가
    EC2(UTC JVM)에서는 옳고 로컬 KST 앱이나 psql 직접 세션(컨테이너 TZ)에서는 9시간 어긋난다.
  - `statement_timestamp() AT TIME ZONE 'UTC'`[^4]는 세션 존과 무관하게 UTC 벽시계를 낸다.
    이미 레포 관례다 (streak, notification, badge, region, mission, video 리포지토리 선례).

**환경 의존 잔여 경로의 전수 인벤토리** (2026-08-15 grep 실측, Codex 1R에서 확장):

1. `PushTokenRepository.upsert`의 맨 `now()` (26행) 1곳.
2. 타임스탬프 컬럼을 INSERT에서 생략해 `DEFAULT CURRENT_TIMESTAMP`에 맡기는 **활성 경로 6곳**:
   `UserRepository.insertOAuthUserIgnoreConflict`(35행, users.created_at),
   `VideoRepository`의 grids 신설 INSERT(243행, grids.first_seen_at과 created_at),
   `UserMissionRepository.insertIgnoreConflict`(26행, user_missions.completed_at),
   `NotificationOptOutRepository.insertOptOut`(23행, notification_opt_outs.created_at),
   `SearchKeywordDailyCountRepository`(29행, search_keyword_daily_counts.created_at),
   그리고 미션 시더 3종의 JPA save(`Mission.java:79`가 created_at을 `insertable = false`로
   매핑해 DEFAULT에 위임).
3. psql 직접 세션의 시딩과 수동 SQL (컨테이너 TZ가 KST).

**목표(티켓 완료 기준)**: `src/main`에 세션 타임존이나 JVM 기본 존에 따라 저장값이 달라지는 시각
생성 경로 0곳. 어디서 띄워도(EC2, 로컬 bootRun, IDE 직접 실행, psql 직접 세션 포함) naive
컬럼에는 UTC 벽시계만 저장된다. 이 기준이 성립하는 구조는 D8이 만든다: `now()` 교체(D4)와
DEFAULT의 존 무관 식 교체(D8)로 **V33 적용 이후의 런타임 쓰기 경로는** 앱과 psql 어느 세션에서도
저장식 자체가 존 무관이 된다. V33보다 먼저 실행되는 이전 마이그레이션들 내부의 시드 INSERT는
이 보장 밖이며(신규 DB 재구축 한정), 그 잔여는 D8의 수용 조항과 D3 가드로 처리한다.

## 성공 기준

1. 잔여 경로 인벤토리의 1번(D4)과 2번(D8)이 코드, 마이그레이션으로 닫힌다. 2번은 리포지토리
   6곳을 고치지 않고 신규 마이그레이션 하나가 DEFAULT 식을 교체해 닫는다.
2. DB 컨테이너 3개(로컬 1, dev, prod)의 `TZ`가 UTC로 바뀌고, **로컬, dev, prod 각각에서**
   반영(컨테이너 재생성) 후 psql `SHOW timezone`과 `SELECT now()`가 UTC로 실측된다.
   서버 2곳은 CD가 compose를 배포하지 않으므로 D1 런북의 수동 반영이 완료 조건에 포함된다.
3. dev DB의 KST 저장분(psql 시딩 목 데이터)이 보정 또는 재시드로 UTC 정합 상태가 된다.
4. 휴면 `@CreationTimestamp`[^5] 3곳이 제거되고 빌드와 기존 테스트가 green을 유지한다.
5. `AiBlurPoller`가 `Clock`[^6] 주입으로 전환되고 AiBlurPollerTest가 전면 고정 시계로 바뀌어
   타임아웃 판정 테스트가 결정적이 된다.
6. bootRun에 `-Duser.timezone=UTC`가 기본 적용되고 IDE 직접 실행 안내가 문서에 남는다
   (D8 이후 이것은 방어선 중첩이다. 아래 D3 참조).

## 작업 항목과 결정

### 항목 1. DB 컨테이너 TZ UTC 전환 (D1 — 미해결 질문 1은 2026-08-15 수용 확정으로 해소)

- `docker-compose.yml:11`, `docker-compose.server.yml:19`(postgres-dev),
  `docker-compose.server.yml:38`(postgres-prod)의 `TZ: Asia/Seoul`을 `TZ: UTC`로 바꾼다
  (2026-08-15 실측 라인).
- 효과: psql 직접 세션의 기본 타임존이 UTC가 된다. D8이 DEFAULT 식 자체를 존 무관으로 바꾸므로
  저장 정합의 필수 조건은 아니게 되지만, psql에서 실행하는 임의 SQL(시딩 스크립트의 `now()` 등)
  까지 UTC로 맞추는 환경 정리다.
- 한계: 앱 세션에는 영향이 없다 (앱 세션 존 = JVM 존). 앱 경로의 교정은 D3, D4, D8이 담당한다.
- **실행 조건**: 운영 중 psql 조회 표시가 KST에서 UTC로 바뀌는 영향(미해결 질문 1)은 2026-08-15
  정민이 수용을 확정해 충족됐다. compose 수정을 커밋할 수 있고, 서버 컨테이너 반영만 아래 런북을
  따른다.

**서버 반영 런북 (Codex 1R High 2)**: `cd-dev.yml`, `cd-prod.yml`은 JAR 교체와 systemd 재시작만
하고 compose 파일을 배포하지 않는다(cd-dev.yml:8 주석 실측). **머지만 하면 서버에는 no-op이다.**
반영 절차:

1. 수정된 `docker-compose.server.yml`을 EC2에 반영한다 (git pull 또는 scp).
2. 컨테이너를 **재생성**한다: `docker compose -f docker-compose.server.yml up -d`
   (env 변경을 감지해 recreate한다. 단순 `docker restart`는 기존 env를 유지하므로 불가.
   미감지 시 `--force-recreate postgres-dev postgres-prod` 명시). 볼륨은 유지되므로 데이터는
   보존되지만, prod DB 순단이 생기니 반영 시점은 사용자와 합의한다.
3. 반영 확인: psql에서 `SHOW timezone`, `SELECT now()`. **기존 볼륨에서 TZ env 변경만으로
   `SHOW timezone`이 바뀌는지는 레포에서 검증 불가**(initdb 시점 postgresql.conf에 고정됐을 수
   있다). 재생성 후에도 KST면 `ALTER SYSTEM SET timezone = 'UTC'; ALTER SYSTEM SET log_timezone
   = 'UTC'; SELECT pg_reload_conf();`로 마저 맞추고 결과를 작업 로그에 남긴다.
4. 로컬도 같은 확인을 한다 (compose 재기동 후 `SHOW timezone` 실측).

### 항목 2. dev DB의 KST 저장분 보정 (D2)

- 대상: psql 직접 시딩한 목 데이터(서면 50격자 등)의 시각 컬럼. KST 벽시계가 저장돼 있다.
- 방침: **목 데이터이므로 재시드를 1안**으로 한다. 시딩 스크립트를 (TZ 전환된 컨테이너에서, 또는
  `SET timezone TO 'UTC'` 세션에서) 다시 실행해 갈음한다. 재시드가 곤란하면 2안으로 보정
  UPDATE를 쓴다. 어느 쪽인지는 dev DB 실측 후 결정한다 (미해결 질문 2).
- **2안 런북 (Codex 1R 7)**: 일괄 `- interval '9 hours'`는 UTC 행과 KST 행이 혼재하면 정상 행을
  망가뜨린다. 절차:
  1. **대상 행 식별 기준을 먼저 확정한다**: 시딩분을 PK나 식별 컬럼(시딩 계정 user_id, 시딩
     grid_id 목록, 시딩 실행일의 값 범위 등)으로 특정하는 SELECT를 만들고, 행 수와 대상 컬럼별
     현재 값 분포를 실측해 사용자에게 제시한다. 식별 불가 행이 하나라도 나오면 1안(재시드)으로
     회귀한다.
  2. 실행 전 `pg_dump`로 대상 테이블 백업을 뜬다 (키 기반 롤백의 원본).
  3. 앱 쓰기 중단 상태(또는 대상 행이 앱이 안 건드리는 시딩분임을 확인)에서 단일 트랜잭션으로
     식별 SELECT와 같은 술어의 UPDATE를 실행한다.
  4. 사후 검증: 대상 행의 시각이 기대 UTC 범위에 들어왔는지, 행 수가 1번 실측과 일치하는지
     확인 후 커밋. 불일치면 롤백.
  5. 커밋 후 문제 발견 시 백업에서 키 기반 복원한다 (전체 리스토어가 아니라 대상 행만).
- **실행 전 사용자 승인 게이트(필수)**: dev 서버 DB 조작이다. 실행할 SQL 또는 재시드 절차 전문과
  대상 행 수 실측을 사용자에게 먼저 제시하고, 승인 응답 전에는 실행하지 않는다.
- 이 데이터 보정은 Flyway로 만들지 않는다. dev 한 환경의 목 데이터 정정이라 전 환경 공통 스키마
  이력에 넣을 성격이 아니다 (스키마 쪽 마이그레이션은 별개로 D8이 있다).

### 항목 3. 로컬 개발 가이드, JVM 존 표준화 (D3, 방어선 중첩)

- **결정: `build.gradle`의 `bootRun`에 `-Duser.timezone=UTC`를 기본 적용한다** (현재 bootRun 관련
  설정 없음, 실측). 문서화만 하는 안은 기각한다. 가이드는 잊히기 때문이다.
- 지위 (Codex 1R 3): D4와 D8이 앱의 저장식 자체를 존 무관으로 만들므로, D3는 저장 정합의 필수
  조건이 아니라 **방어선 중첩**이다. 커버하는 잔여 위험: 미래에 컨벤션을 어기고 들어오는 존 의존
  코드, V33 이전 마이그레이션의 존 의존 식(맨 `now()`, 시드 INSERT의 DEFAULT 위임)이 신규 DB
  재구축에서 재실행되는 경우(D8 수용 조항의 목록), `Clock.systemDefaultZone()` 류 우회.
  IDE에서 메인 클래스를 직접 실행하면 bootRun 설정이 안 타므로
  `.claude/docs/infrastructure.md`(로컬 DB 세팅 절)에 VM 옵션 안내를 한 줄 남긴다.
  IDE 실행이 가이드를 놓쳐도 D8 덕에 저장값은 어긋나지 않는다는 것이 "어디서 띄워도"가 실제로
  성립하는 근거다.
- 테스트 태스크에는 걸지 않는다. 테스트는 이미 KST JVM에서 전체 green(MSG-376 작업 로그 실측)
  이고, 존 의존 버그를 로컬에서 재현해 잡는 창을 남겨두는 편이 낫다.

### 항목 4. 앱 잔재 정리: now() 교체와 DEFAULT 존 무관화 (D4, D5, D8)

- **D4. `PushTokenRepository.upsert`의 맨 `now()`** (26행 실측):
  `statement_timestamp() AT TIME ZONE 'UTC'`로 교체한다. 60일 스테일 판정 입력이라 9시간 오차가
  무해하다는 판정(NotificationRepository.java:85 주석)은 유지되지만, 완료 기준이 "환경 의존 경로
  0곳"이라 일관성으로 닫는다. 교체 후 그 무해 판정 주석(`NotificationRepository.java`)의 문구도
  현행화한다.
- **D8. DEFAULT CURRENT_TIMESTAMP를 존 무관 식으로 교체하는 신규 마이그레이션** (Codex 1R High 1,
  설계 정본): 리포지토리 6곳의 INSERT를 고치지 않는다. 대신 마이그레이션 하나가 naive timestamp
  컬럼의 DEFAULT를 전부 `(statement_timestamp() AT TIME ZONE 'utc')`로 바꾼다. 모든 DEFAULT
  위임 경로가 한 곳에서 닫히고, 앱 코드 무수정이며, 앱 세션이든 psql 세션이든 세션 존과 무관하게
  UTC 벽시계가 저장된다. 파일명 `V33__timestamp_defaults_utc.sql` (V32까지 존재 실측, **push와
  PR 전에 develop의 최신 번호 재확인**, pr-base-sync 관례). DDL은 `ALTER TABLE ... ALTER COLUMN
  ... SET DEFAULT ...`라 기존 행은 건드리지 않고 즉시 완료된다.

  대상 컬럼 전수 (마이그레이션 SQL grep 실측 20개. 활성 경로가 안 쓰는 컬럼도 균일하게 바꾼다,
  미래 경로가 생길 때의 함정 제거):

  | 정의 위치 | 테이블.컬럼 |
  |---|---|
  | V1:36 | users.created_at (활성: OAuth 가입) |

### 항목 6. AiBlurPoller Clock 주입 (D7)

- 컨벤션 문서가 "임시 허용, 후속 교체 대상"으로 남긴 항목의 이행. 현재

  `Duration.between(start, LocalDateTime.ofInstant(clock.instant(), ZoneOffset.UTC))`로 바꾼다.

  두고 모든 픽스처 시각을 그 기준 상대값으로 바꾼다.

[^1]: naive LocalDateTime: 타임존 정보가 없는 날짜, 시각 값. 이 프로젝트는 "naive 값은 전부
    UTC 벽시계"라는 관례로 통일했고(MSG-376), DB의 `TIMESTAMP`(without time zone) 컬럼과 짝이다.
[^2]: pgJDBC: 자바 앱이 PostgreSQL에 접속할 때 쓰는 JDBC 드라이버. 접속 시 DB 세션의 타임존을
    앱 JVM의 기본 존으로 맞춘다. 그래서 컨테이너의 TZ 설정은 앱 경로에 영향을 주지 못한다.
[^3]: now(): PostgreSQL 함수로, 타임존 붙은 시각(timestamptz)을 반환한다. `CURRENT_TIMESTAMP`도
    같은 값이다. 타임존 없는 컬럼에 넣으면 그 순간 세션 타임존으로 변환되므로, 같은 SQL이나
    같은 DEFAULT가 세션 존에 따라 다른 벽시계를 저장한다.
[^4]: statement_timestamp() AT TIME ZONE 'UTC': 현재 문장 실행 시각을 UTC 벽시계로 바꾼 표현.
    세션 타임존과 무관하게 항상 같은 값이 나와 이 레포의 native 쿼리 시각 기록 관례다. now() 대신
    statement_timestamp()를 쓰는 이유는 트랜잭션 시작 시각 고정을 피하기 위해서다(MSG-200 선례).
[^5]: @CreationTimestamp: Hibernate가 JPA로 엔티티를 저장할 때 생성 시각을 자동으로 채우는
    애너테이션. 채우는 시각이 JVM 기본 존을 따르고, 행 생성이 native SQL 전용인 엔티티에서는
    아예 실행되지 않아 휴면 상태다.
[^6]: Clock: 자바 표준의 시계 추상화. 프로덕션에서는 `Clock.systemUTC()`, 테스트에서는 고정
    시각을 주입해 "지금"이 들어가는 로직을 결정적으로 검증할 수 있게 한다.
