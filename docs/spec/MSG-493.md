# MSG-493: 바다에 걸친 격자의 표시 이름

> 선행 정본: `docs/prd/MSG-493-prd.md` (상태 검토됨, 2026-08-27 승인)
> 작성일: 2026-08-27 · **Owner** A (grid 패키지) · **계약 변경 1건** — `RegionQueryService`에 거리 상한 오버로드 추가 (3km 상한 확정으로 발생, D-3)

## 개요

어느 행정동에도 속하지 않는 격자(해안)를 단일 조회하면 `regionName`이 null이라 화면이
격자 번호를 그대로 노출한다. 그 자리에 가장 가까운 행정동 이름을 채운다.

**표시 전용이다.** `grids.region_code` 저장 라벨, 수집률·탐험률 귀속, 뷰포트·핫구역
응답은 전부 불변이다(PRD 확정 결정 3건).

## 성공 기준

1. 경계 3km 안의 무귀속 격자는 단일 조회(`GET /api/grids/{gridId}`) 응답에 최근접 행정동
   이름이 실리고, 3km 밖은 종전처럼 빈 이름이다
2. 행정동에 속하는 격자의 응답은 바이트 단위로 같다 (폴백 미발동)
3. 행사 위치 이름 조회(`resolveRegionNames`)는 종전대로 무귀속이면 이름 없음 (범위 밖 회귀 가드)
4. 수집률·탐험률·by-grid 귀속이 변하지 않는다
5. 서비스 범위 밖 좌표 가드(null 반환, 6400 미발생)는 그대로다

## 도메인 로직

`GridQueryServiceImpl.getCell`의 이름 판정에만 최근접 폴백을 잇는다.

```text
getCell (단일 조회)          : resolveByPoint 비면 → resolveNearestByPoint   ← 이번 변경
resolveRegionNames (행사 벌크): resolveByPoint 비면 → 그대로 없음             ← 불변
```

### D-1. 공유 헬퍼에 폴백을 넣지 않는다

`resolveRegionName`은 `getCell`과 `resolveRegionNames`(MSG-439 행사 위치 벌크)가 공유한다.
헬퍼에 폴백을 넣으면 행사 응답까지 바뀌어 승인 범위("보이는 문제가 있는 데만")를 넘고,
행사 벌크는 격자 수만큼 공간 조회가 늘어난다. 폴백은 `getCell` 경로에서만 잇는다.

### D-2. 최근접 호출 조건

`resolveByPoint`가 빈 결과일 때만. 서비스 범위 밖 좌표는 기존 가드가 먼저 null을 돌려
최근접까지 가지 않는다(6400 미발생 유지). 정상 격자는 추가 쿼리 0이다.

### D-3. 결정성은 계약이, 상한은 이 스펙이 정한다 (2026-08-27 개정)

결정성은 `resolveNearestByPoint` 2단 KNN(인덱스 스캔 + 동률 `region_code` 정렬, dev 실측
20.7ms)이 보장한다.

**거리 상한 3km는 이 경로 전용이다** (정민 확정). 계약에 상한 오버로드
`resolveNearestByPoint(lat, lon, maxDistanceMeters)`를 더했고(내부는
`findNearestRegionWithin` — 같은 2단 구조의 바깥 단에 `WHERE distance <= :max` 한 줄),
`getCell`이 3,000m 상수로 부른다. 상한 필터를 바깥 단에 두는 이유는 안쪽에 넣으면 KNN
인덱스 순서 스캔이 다시 흔들리기 때문이다.

초안의 "상한 없음"은 MSG-492 D-5를 그대로 가져온 것이었는데 전제가 달랐다 — 그쪽 대상은
검증된 972칸(최대 2,189m)이고, 이쪽은 지도의 아무 격자다. 바다 한가운데(예: 서해 90km)를
누르면 태안군 근흥면이 붙는 것을 확인해 되돌렸다. 코스 시더는 상한 없는 오버로드를 그대로
쓴다.

## 데이터 모델

변경 없음. 마이그레이션 없음.

## 테스트 시나리오

1. 무귀속 격자 getCell → 최근접 행정동 이름 (실 PostGIS, 합성 폴리곤)
2. 폴리곤 안 격자 getCell → 종전과 같은 이름, 최근접 미호출 (verify)
3. 서비스 범위 밖 격자 getCell → regionName null, 예외 없음 (기존 가드 회귀)
4. `resolveRegionNames`는 무귀속 격자를 결과에서 뺀다 — 폴백이 새지 않는다 (범위 가드)
5. 미점령 무귀속 격자도 이름이 나온다 (grids row 무관, MSG-349 성질 유지)

## 작업 로그

### 2026-08-27 구현

- 변경은 `GridQueryServiceImpl` 한 파일이다. `getCell`이 부르는 이름 판정을
  `resolveRegionNameWithFallback`(신설)으로 바꿨다 — 기존 `resolveRegionName`이 null이면
  `resolveNearestByPoint`를 잇는다. 공유 헬퍼는 그대로라 행사 벌크 경로는 안 바뀐다(D-1)
- 저장 위치: 없음. 저장을 전혀 하지 않는 조회 시점 표시 폴백이다
- 실행 쿼리: 무귀속 격자에서만 최근접 KNN 1회 추가(MSG-492가 만든 2단 쿼리 그대로,
  dev 실측 20.7ms). 정상 격자는 추가 쿼리 0
- 예외 흐름: 새 예외 없음. 서비스 범위 밖 좌표는 기존 가드가 최근접 호출 전에 null을
  돌려 6400이 여전히 새지 않는다
- 빈 동작: 변화 없음. 스케줄러·트랜잭션 경계 무변경
- 테스트: 기존 "무귀속이면 null" 테스트(MSG-349 FR-5)를 개정 요구에 맞게 "최근접 이름"으로
  바꾸고, 정상 격자 폴백 미발동(verify never)·행사 벌크 미누수 가드·상한 경계(2km 이름 있음,
  5km 이름 없음)·리포지토리 상한 쿼리 2건을 더했다.
  합성 블록(36.5N 124.5E)이 약 5km, 가장 가까운 실데이터 육지(태안군 근흥면)가 약 94km라 최근접 판정이 결정적이다
