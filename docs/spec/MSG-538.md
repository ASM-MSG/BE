# MSG-538: 이벤트 대표 이미지를 저장하고 내려준다

**Owner**: B (콘텐츠·인증 도메인, `com.msg.fillmap.event.*`)

> 요구사항 정본: `docs/prd/event-room-location-videos.md` US-002 (상태 확정, 2026-08-20 정민 승인)
> 요구사항 ID: FR-EVENT-02 (2026-09-01 개정 → 2026-09-02 dev 실측으로 상태 구현됨)
> 선행 티켓: MSG-439(회차 상세·위치 목록 API), MSG-500(위치 커버 이미지 승인 복사)

## 개요

이벤트 상세 화면의 헤더에 행사 대표 이미지가 들어가야 하는데 서버가 그 자리를 내려주지 않는다.
회차에는 이미지를 담을 컬럼 자체가 없고, 행사 위치는 컬럼이 있으나 참여형 신청 승인으로만
채워져서 시드로 들어온 위치 아홉 곳이 전부 비어 있다. 이 티켓은 회차에 대표 이미지 키 컬럼을
만들고, 시더가 시드 파일에서 회차와 위치의 이미지를 함께 적재하도록 해서 두 자리를 모두 채운다.

## 배경 · 목표

정본 PRD US-002 의 판정문은 "행사 이미지, 행사명, 기간, D-day, 열람 인원, 작은 알림 토글이
표시된다" 이다. 이미지는 2026-08-20 정본 전환 때부터 요구에 있었다. 그런데 SRS FR-EVENT-02 가
헤더 재료를 이름과 기간과 상태 셋으로만 옮겨 적었고, MSG-439 구현이 그 행을 따라가면서 이미지가
통째로 빠졌다. FR-EVENT-02 는 `구현됨` 으로 남아 있었기 때문에 이 갭이 문서상으로도 드러나지
않았다. 요구사항을 새로 만드는 작업이 아니라 이미 있는 요구의 미구현분을 채우는 작업이므로
PRD 게이트는 면제가 아니라 통과다.

목표는 셋이다. 회차 상세 응답이 대표 이미지 주소를 함께 내려준다. 시드 파일 하나로 회차와 위치의
이미지를 모두 적재할 수 있다. 이미지가 없는 회차와 위치도 지금과 똑같이 동작한다.

## 성공 기준

- AC-538-01: 회차 상세 조회 응답에 `imageUrl` 이 있고, 이미지 키가 저장된 회차는 우리 버킷의 공개 주소가 담긴다.
- AC-538-02: 이미지 키가 없는 회차는 `imageUrl` 이 `null` 이고 나머지 필드는 종전과 같은 값으로 응답한다.
- AC-538-03: 위치 목록 응답의 `imageUrl` 이 시드로 적재한 위치에서도 값을 갖는다. 참여형 승인분만 값을 갖던 종전 동작이 확장된다.
- AC-538-04: 시더를 두 번 실행해도 이미지 키가 시드 파일의 값으로 수렴하고, 그 사이 일정 개정 번호[^1]는 증가하지 않는다.
- AC-538-05: 시드 파일에서 회차의 이미지 항목을 지우고 다시 시딩하면 저장된 이미지 키가 `null` 로 되돌아간다.
- AC-538-06: 이미지 키만 바뀐 재시드는 일정 변경 알림을 발송하지 않는다.
- AC-538-07: 뷰포트 회차 목록 응답의 필드 구성은 바뀌지 않는다.
- AC-538-08: 시드 파일의 회차 네 건과 위치 아홉 곳에 이미지 키가 채워져 있고, 각 키가 버킷에서 공개로 읽힌다.

## API 명세

### 회차 상세 조회 (변경)

`GET /api/event-occurrences/{occurrenceId}`

응답 `EventOccurrenceDetailResponseDto` 에 필드 하나가 는다. 기존 필드는 이름과 타입과 의미가
모두 그대로다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `imageUrl` | `String`, nullable | 대표 이미지 공개 주소. 이미지가 없으면 `null` |

에러 케이스는 변경 없다. 존재하지 않는 회차와 아직 노출 기간 전인 예정 회차는 종전대로 404 에
developCode 13404 이다.

### 위치 목록 조회 (동작 확장, 스키마 무변경)

`GET /api/event-occurrences/{occurrenceId}/locations`

응답의 `imageUrl` 은 MSG-500 이 이미 추가해 두었다. 이 티켓은 그 값이 채워지는 경로를 시드로
넓힐 뿐이라 응답 스키마는 그대로다. Swagger 설명의 "참여형 승인분만 값이 있다" 문구는 사실과
어긋나게 되므로 함께 고친다.

### 변경하지 않는 응답

뷰포트 회차 목록(`GET /api/event-occurrences`)과 격자 역조회
(`GET /api/grids/{gridId}/event-locations`)에는 이미지를 넣지 않는다. 근거는 D4 에 적는다.

## 도메인 로직

### D1. 대표 이미지는 시리즈가 아니라 회차에 붙인다

부산국제영화제처럼 해마다 열리는 행사는 회차마다 포스터가 다르다. 시리즈에 한 장을 달면 지난
회차 목록까지 같은 그림으로 덮이고, 회차 사이에 데이터가 섞이지 않는다는 FR-EVENT-07 의
성질과도 어긋난다. 그래서 컬럼은 `event_occurrences` 에 둔다.

### D2. 키만 저장하고 공개 주소는 조회 시점에 조립한다

저장하는 값은 버킷 상대 키이고, 응답에 담기는 주소는 `AwsProperties.publicUrl(key)` 이 조회
시점에 만든다. 행사 위치 이미지(MSG-500)와 미션 이미지(MSG-383)가 쓰는 방식 그대로다. 절대
주소를 저장하면 환경마다 버킷이 다른데 값이 한 환경에 고정되고, 실제로 그렇게 저장된 가짜 시드가
서명 주소를 기형으로 만들어 403 을 낸 사례가 MSG-512 에 있다.

### D3. 이미지 변경은 일정 개정이 아니다

`EventOccurrence.update()` 는 시작과 종료 시각이 실제로 바뀐 경우에만 일정 개정 번호를 올리고,
시더는 그 번호가 올라간 회차에만 일정 변경 알림을 보낸다. 이미지 키는 이 판정에 넣지 않는다.
포스터를 갈아 끼웠다는 이유로 알림을 켠 사용자 전원에게 "행사 일정이 변경됐어요" 가 나가면 안 된다.

### D4. 노출은 회차 상세 한 곳이다

디자인의 이벤트 칩은 텍스트만 담고(`포켓몬 부산 D-7`), 격자 역조회는 지도에서 격자를 눌렀을 때
어느 위치인지 알려 주는 응답이라 그림 자리가 없다. 응답마다 이미지를 흩뿌리면 같은 값을 여러
계약이 물게 되고, 나중에 주소 조립 방식을 바꿀 때 고칠 곳이 늘어난다.

### D5. 이번 티켓의 공급원은 시드 하나다

행사 등재 신청에서 회차 이미지를 받는 경로는 만들지 않는다. 등재 v2 는 지금 신청 단위 커버를
행사 위치에 복사하는 구조이고(MSG-500), 회차 커버를 신청에서 받으려면 어느 신청이 부모 회차의
대표를 정하는지부터 정해야 한다. 그 결정은 등재 레인에 있다.

### D6. 이미지는 없을 수 있다

컬럼은 nullable 이고 응답도 `null` 을 허용한다. 이번 시드는 회차 네 건과 위치 아홉 곳을 모두
채우지만(2026-09-01 결정 — 리그 오브 레전드 국가대표 평가전도 이미지를 넣기로 했다), 결측 자체는
정상 경로로 남긴다. 승인 경로가 열리면 이미지 없는 위치가 들어올 수 있고, 미션 축제 적재에서도
461 건 중 5 건이 이미지 없이 정상 적재된 선례가 있다(MSG-384).

### D7. 재시드는 시드 파일 값으로 수렴한다

이미지 키는 시드 파일이 정본이라, 항목을 지우면 저장값도 `null` 로 돌아간다. 노출 영역처럼
"시드 값을 바닥으로 두고 승인분을 얹는" 합집합 규칙(MSG-500 D-8)을 쓰지 않는 이유는, 회차
이미지를 승인이 채우는 경로가 D5 에 따라 아직 없어서 얹을 대상 자체가 없기 때문이다. 행사 위치
이미지는 사정이 달라서 D8 에 따로 적는다.

### D8. 위치 이미지는 시드 위치에만 적용한다

행사 위치의 이미지 키는 참여형 승인이 이미 채우고 있다(MSG-500). 시더의 위치 갱신이 그 값을
무조건 덮으면 승인으로 올라온 커버가 재기동마다 지워진다.

이 사고는 지금 구조에서 일어나지 않는다. `upsertLocation` 은 시드 파일의 위치를 하나씩 돌면서
그 위치의 자연키로 행을 찾아 갱신하고, 승인 위치의 자연키는 `EventLocation.SUBMISSION_KEY_PREFIX`
(`sub-`)로 시작하므로 시드 파일에 그런 키가 없는 한 시더가 닿을 경로가 없다. 그래서 이 티켓은
가드를 새로 넣지 않고, 이 성질이 깨지지 않도록 테스트로 고정만 한다. 이미지 키가 추가되면서
시더가 위치 행에 쓰는 값이 하나 늘기 때문에, 실수로 조회 범위를 넓혔을 때 잃는 것도 하나 는다.

## 데이터 모델

### 마이그레이션

`V52__event_occurrence_image.sql`

```sql
ALTER TABLE event_occurrences
    ADD COLUMN image_key VARCHAR(255);   -- 공개 프리픽스 키, 공개 주소는 조회 시점 조립
```

번호 근거는 `origin/develop` 기준 최신이 V51(MSG-500 `event_submission_review`)이라는 실측이다.
`event_locations.image_key` 와 길이와 널 허용을 맞춘다. 제약은 걸지 않는다. 키 형식 검증은
적재하는 쪽 책임이고, 이미 있는 위치 이미지 컬럼도 제약 없이 운영 중이다.

### 엔티티

`EventOccurrence` 에 `imageKey` 필드를 더하고 `update()` 의 마지막 인자로 받는다. D3 에 따라
일정 개정 판정에는 넣지 않는다.

### 시드 파일

`EventSeed.Occurrence` 레코드에 `imageKey` 를 더한다. 행사 위치 쪽 `EventSeed.Location.imageKey`
는 이 티켓 착수 시점에 이미 워킹트리에 들어와 있었고(검증 테스트는 없었다) 이 티켓이 흡수한다.

`seed/events.json` 의 회차 네 건과 위치 아홉 곳에 키를 채운다. 객체는 `event-locations/seed/`
프리픽스에 올린다. 회차와 위치가 프리픽스를 나누지 않는 이유는 공개 읽기 버킷 정책이 프리픽스
단위라, 나누면 환경마다 Statement 를 둘씩 관리해야 하기 때문이다.

시더는 저장 전에 키 형식을 검증하고 어긋나면 기동을 실패시킨다. 프리픽스 이탈과 경로 탈출과
래스터가 아닌 확장자 셋을 함께 본다 — 미션 시더의 같은 규칙(MSG-394 D2)과 같은 내용이고, 그
메서드가 미션 패키지 전용에 `JsonNode` 를 받아 공유하려면 미션 시더 넷의 호출부를 함께 건드려야
해서 이 티켓은 같은 규칙을 시더 안에 둔다.

[^5]: 자연키는 시드 파일이 정하는 문자열 식별자다. 회차는 `occurrenceKey`, 위치는 `locationKey` 이고, 시더는 이 값으로 기존 행을 찾아 갱신하므로 여러 번 실행해도 행이 늘지 않는다.

#### 실행 쿼리

시더의 회차 UPSERT 는 JPA 더티 체킹이라 이미지 키가 다른 컬럼과 한 UPDATE 로 나간다. 값이 같으면
문장 자체가 생략된다(멱등):

```sql
update event_occurrences set city_name=?, ends_at=?, image_key=?, max_grid_x=?, max_grid_y=?,
  min_grid_x=?, min_grid_y=?, occurrence_key=?, schedule_revision=?, event_series_id=?,
  starts_at=?, title=?, visible_from=? where id=?
```

(실측 — `EventSeederTest$Images` 를 `org.hibernate.SQL: DEBUG` 로 돌려 뽑았다. 설정은 되돌렸다.)

조회는 쿼리가 늘지 않는다 — 상세 응답의 `imageUrl` 은 이미 읽어 온 엔티티의 `image_key` 를
`AwsProperties.publicUrl(key)` 이 문자열로 조립할 뿐이다(`https://{버킷}.s3.{리전}.amazonaws.com/{키}`).
키가 null 이면 주소도 null 이다.

#### 예외 흐름

- 시드 이미지 키 형식 위반 → `EventSeeder.validatedImageKey` 가 `IllegalStateException` 을 던진다.
  `ApiException` 이 아니고 `GlobalExceptionHandler` 밖이다 — `ApplicationRunner` 실행 중이라
  **기동 자체가 실패한다**(developCode 변환 없음). 의도한 동작으로, 깨진 공개 주소가 DB 에 퍼진
  뒤에 발견되는 것보다 기동 실패가 싸다. 검사 셋: 프리픽스 이탈, 프리픽스 뒤 단일 객체 이름
  위반(경로 탈출·URL 구분자), 래스터 확장자 아님(jpg·jpeg·png·webp 만).
- 회차 상세 조회의 실패 경로는 종전과 같다 — 미존재·노출 기간 전 회차는
  `ApiException(EventErrorCode.EVENT_NOT_FOUND)` → 404 / developCode 13404. 이미지 유무는 이
  판정에 관여하지 않는다.
