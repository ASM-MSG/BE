# MSG-388: 도감 갤러리 조회 확장, 행정동 내 내 격자 카드 지원

**Owner**: 공동 (구현 주도 B, 계약 인터페이스 변경 포함)

> 요구사항 정본: `docs/prd/MSG-388-prd.md` (상태: 검토됨, 2026-08-15 사용자 승인)

## 개요

지도 홈 사이드 패널의 격자 카드를 "내 격자 기준"으로 채울 수 있도록, 기존 내 도감 갤러리 조회
`GET /api/collections/grids`에 선택 쿼리 파라미터 세 개(regionCode, sort, limit)를 더한다.
신규 엔드포인트가 아니라 기존 조회의 확장이며(PRD §3 확정), 파라미터 없는 기존 호출의 동작과
응답은 그대로다(FR-7). FE는 지금 전역 조회 `GET /api/regions/{regionCode}/grids`를 임시로 쓰고
있어 타인 격자가 내 격자 자리에 노출되는 상태다(dev 실측: 부전2동 카드 8장 중 본인 격자 2장).

## 배경 · 목표

2026-08-13에 "상단 칩을 켜지 않는 한 지도 홈은 전부 내 격자 기준"이 확정됐다(SRS FR-MAP-07,
FR-MAP-10). 그런데 한 행정동 안에서 내 격자를 카드(썸네일과 영상 수)로 주는 서버 조회가 없어,
FE가 전역 공개 콘텐츠 조회를 임시 사용 중이다. 이 티켓은 그 구멍을 기존 갤러리 조회 확장으로
메운다. 목표는 두 가지다: FE가 행정동 코드 하나로 그 동네의 내 격자 카드를 최신 업로드순 최대
20장으로 받게 하고, FE 연동 가이드의 "전역 조회 임시 사용" 안내를 새 조회로 교체한다.

## 성공 기준

1. `GET /api/collections/grids?regionCode={동코드}&sort=UPLOADED&limit=20` 호출이 그 행정동에
   속한 내 점령 격자만 최신 업로드순으로 최대 20장 반환한다. 타인 격자는 절대 섞이지 않는다.
2. 파라미터 없는 `GET /api/collections/grids` 호출은 기존 필드·정렬·상한(수집 시각순, 최대
   30개)이 불변이다. 신규 필드(coverDurationSec)는 additive 추가만 허용한다(FR-7 취지 유지).
3. 내 격자가 없거나 존재하지 않는 행정동 코드에서 200과 빈 배열이 온다(FR-6, 신규 에러 코드 0).
4. 마이그레이션 없음, 신규 인덱스 없음(비기능 "운영", 아래 성능 근거 참조).

## API 명세

### GET /api/collections/grids (기존 확장)

인증: 토큰 필수(기존과 동일). 본인 것만 조회된다.

| 파라미터 | 타입 | 필수 | 기본값 | 의미 |
|---|---|---|---|---|
| `regionCode` | String | X | 없음(전국) | 행정동 코드. 지정하면 그 행정동에 속한 내 격자만 |
| `sort` | enum | X | `COLLECTED` | `COLLECTED`(수집 시각순) 또는 `UPLOADED`(최신 업로드순) |
| `limit` | Integer | X | 아래 표 | 카드 수 상한. 1 미만은 1로 보정(전역 탐색 선례) |

**sort 값 확정(PRD 미해결 질문 3의 답)**: 값 이름은 `COLLECTED`와 `UPLOADED`, 생략 기본값은
`COLLECTED`다. 근거는 두 가지다. 첫째, 기본값이 수집 시각순이어야 무파라미터 호출(기존 갤러리)의
정렬 계약이 파라미터 추가만으로 보존된다(FR-7). 둘째, 전역 탐색의 `LATEST`는 "격자의 최신 공개
영상 시각"이라는 전역 축 정의를 이미 점유하고 있어, 내 업로드 축인 이 정렬에 같은 이름을 쓰면
두 API 사이에서 뜻이 갈라진다. 축이 다르면 이름도 가른다. 와이어 값은 대문자 전용이고 소문자
포함 무효 값은 enum 바인딩[^1] 실패로 400이다(`ExploreSort` 선례, 조용한 기본값 폴백 금지).

**limit 생략 시 동작**: regionCode 유무에 따라 갈린다.

| regionCode | limit | 결과 |
|---|---|---|
| 없음 | 없음 | 최대 30개(기존 갤러리 계약 그대로, FR-7) |
| 없음 | 지정 | 지정값 상한 |
| 지정 | 없음 | 그 동네의 내 격자 전부(전역 조회의 전체 보기 계약 승계, PRD 미해결 질문 2 채택) |
| 지정 | 지정 | 지정값 상한. 지도 홈 패널은 20 |

서버는 상한을 강제하지 않는다(FR-3, MSG-387 FR-3 승계). 상한 없는 반환의 규모 근거: 한 행정동의
내 점령 격자 수는 개인 활동량에 비례하는 작은 수이고, 전국 갤러리도 이미 30장을 같은 구조로 준다.

**응답**: 기존과 동일하게 `SuccessResponse<List<CollectionGridResponseDto>>`. 기존 필드는
불변이고(gridId, gridY, gridX, firstCollectedAt, lastUploadedAt, videoCount, coverVideoId,
coverThumbnailUrl, regionName, zoneName, zoneCell), **`coverDurationSec`(Integer, nullable)
하나를 additive로 추가한다**. FE 연동 가이드(위키 §패널)가 카드의 duration 뱃지를
`grids[].coverDurationSec`로 그리므로, 새 조회로 갈아타는 순간 이 재료가 서버에 있어야 한다.
값은 커버 영상의 duration_sec을 READY 게이트 없이 읽는다: videos.duration_sec은 업로드 확정
시점부터 non-null이라 인코딩 완료 전 카드에도 뱃지 재료가 살아 있고, null인 경우는 커버 자체가
없을 때뿐이다(썸네일은 계속 READY 게이트 적용). 카드 커버는 도감 갤러리와 같은
`user_grids.cover_video_id` 규칙을 쓴다: 첫 영상 유지, 삭제·블라인드 시 재선정(블라인드 해제는
상태만 복귀하고 커버를 원복하지 않음), 재선정 대상이 없으면 커버 없음(실측: upsert의 ON
CONFLICT 절은 cover를 갱신하지 않고, `VideoModerationServiceImpl.blind()`의 reselectCover만
재선정한다. PRD 미해결 질문 1 채택).

**성공/에러 케이스**:

| 케이스 | 응답 |
|---|---|
| 정상 조회 | 200, developCode 200, 카드 배열 |
| 내 격자 없음 또는 미존재 regionCode | 200, 빈 배열(FR-6, 404 아님) |
| sort 무효 값(소문자 포함) | 400 BAD_REQUEST(전역 핸들러의 타입 미스매치 매핑, 신규 코드 없음) |
| 미인증 | 401(SecurityConfig 기존 동작) |

## 도메인 로직

- **대상은 내 점령 격자다**: `user_grids`에서 본인 행만 읽는다. 다른 사용자의 격자나 비공개 영상
  존재가 이 응답으로 새지 않는다(비기능 "보안/인가". 쿼리가 user_id로 시작하므로 구조적으로 보장).
- **행정동 귀속은 격자 축이다**(FR-5): `grids.region_code`를 equi 조인[^2]으로 소비한다. 영상
  좌표가 옆 동이어도 격자 소속 동 기준으로 잡힌다. 같은 컨트롤러의 동 단위 내 영상 조회
  (`getRegionVideos`, MSG-167 §D3)와 같은 기준이라 화면 안에서 귀속이 어긋나지 않는다.
- **세는 대상은 내 도감 관례다**(FR-4): 점령 롤백이 `user_grids` 행 자체를 지우므로 남은 행이 곧
  현재 진실이다. `video_count`는 삭제만 차감되고 블라인드는 포함된 수다(실측: upsert가 +1,
  차감은 삭제 경로뿐이며 모더레이션은 video_count를 건드리지 않는다). PRIVATE든 인코딩 중이든
  포함되며, currentRegion 집계(MSG-374)와 동일 기준이라 지도 홈 안의 숫자들이 어긋나지 않는다
  (패널 헤더의 카운트 줄 자체는 2026-08-15 폐기돼 화면에는 동 이름만 남았다. FR-MAP-06).
- **READY 게이트[^3]는 썸네일에만 건다**(FR-8): 도감 갤러리와 동일하게 coverVideoId는 readiness
  무관 그대로이고, 썸네일 key만 READY 조건으로 가져온다. coverDurationSec은 게이트 밖이다:
  커버 영상 행에서 READY 조건 없이 읽으므로 인코딩 완료 전 격자도 카드에서 빠지지 않고
  coverThumbnailUrl만 null, duration 뱃지 재료는 살아 있다.
- **커버 없는 격자도 카드는 유지된다**: 블라인드로 커버가 재선정될 때 다른 ACTIVE 영상이 없으면
  cover_video_id가 null이 되는데, video_count는 블라인드 포함이라 0이 아니므로 점령 롤백이
  일어나지 않고 행이 남는다. 이 격자는 카드로 나가되 coverVideoId·coverThumbnailUrl·
  coverDurationSec이 모두 null이다(FE는 썸네일 null 플레이스홀더 규칙 그대로).
- **정렬 동률 처리**: `UPLOADED`는 `last_uploaded_at DESC, grid_id DESC`, `COLLECTED`는 기존과
  같은 `first_collected_at DESC, grid_id DESC`. 타이브레이크가 있어 페이지 없는 목록이라도
  순서가 결정적이다.

## 데이터 모델

읽기 전용 조회라 엔티티 변경과 Flyway 마이그레이션이 없다. 신규 인덱스도 없다: 쿼리 구동이
`user_grids` PK 선두(user_id)로 사용자 행만 몰아 읽은 뒤 grids PK 조인과 region_code 필터로
좁히는 구조라, 동 단위 내 영상 조회(MSG-167 §D5)와 같은 논리로 region_code 인덱스가 불요하다.

## 계약 변경

**`UserGridQueryService.getCollectionGrids` 시그니처 확장**:

```java
// 변경 전
List<CollectionGridView> getCollectionGrids(long userId);
// 변경 후
List<CollectionGridView> getCollectionGrids(long userId, String regionCode, CollectionGridSort sort, Integer limit);
```

`UserGridQueryService`는 B 제공, A 소비의 계약 인터페이스지만, 이 메서드는 javadoc에 명시된
"B 내부 read"로 `CollectionController`만 소비한다(getRegionVideos, getUploadHistory와 같은
분류). Owner A 소비 지점이 없어 실질 non-breaking이나, 계약 인터페이스 파일 수정이므로 상단
Owner를 공동으로 판정하며 리뷰에서 상대 팀원 확인을 거친다. regionCode와 limit은 null 허용
(각각 전국, 기본 상한)이고 sort는 컨트롤러 defaultValue로 항상 비null이다. sort는 서비스
계약까지만 enum이고 리포지토리 경계에서는 String(`sort.name()`)으로 좁혀 넘긴다(아래 구현
가이드의 바인딩 근거). `CollectionGridView`에는 coverDurationSec(Integer, nullable)이
additive로 추가된다.

| `usergrid/repository/UserGridRepository.java` | `getCollectionGrids` 네이티브 쿼리[^4] 확장(아래), 커버 조인 재편(READY 게이트를 썸네일 표현식으로 이동) + `v.duration_sec` 추가 |

리포지토리는 별도 메서드 추가 대신 기존 `getCollectionGrids` 쿼리 하나를 파라미터화한다.
파라미터 조합이 4가지(regionCode 유무 × sort 2종)라 메서드를 늘리면 같은 SELECT 목록이 복제되어
응답 재료가 갈라질 위험이 생긴다(전역 탐색이 신규 엔드포인트를 기각한 것과 같은 이유). 확장 골격:

```sql
LEFT JOIN videos v ON v.id = ug.cover_video_id
...
	CASE WHEN v.processing_status = 'READY' THEN v.thumbnail_url END AS "coverThumbnailKey",
	v.duration_sec AS "coverDurationSec",
...
WHERE ug.user_id = :userId
	AND (CAST(:regionCode AS varchar) IS NULL OR g.region_code = CAST(:regionCode AS varchar))
ORDER BY
	CASE WHEN :sort = 'UPLOADED' THEN ug.last_uploaded_at END DESC,
	CASE WHEN :sort = 'COLLECTED' THEN ug.first_collected_at END DESC,
	ug.grid_id DESC
LIMIT CAST(:limit AS bigint)
```

커버 조인의 READY 조건은 조인 자체에서 빼고 썸네일 SELECT 표현식으로 옮긴다: duration은 게이트
없이 읽어야 하기 때문이다(위 API 명세). 썸네일 결과는 기존과 동일하다(READY 이전이면 null)라
FR-7이 유지된다. nullable 파라미터에는 CAST가 필수다: Hibernate 네이티브 쿼리에서 null을
바인딩하면 PostgreSQL이 파라미터 타입을 추론하지 못해 문장이 실패한다(무파라미터 기존 경로가
깨진다). 레포 선례는 `RegionRepository.findStats`의 `(CAST(:parentCode AS varchar) IS NULL OR
...)` 패턴이며, LIMIT의 null(무제한)도 같은 이유로 `CAST(:limit AS bigint)`를 쓴다. **`:sort`
파라미터는 String이다**: enum을 네이티브 쿼리에 직접 바인딩하면 Hibernate 6가 ordinal로
바인딩해 `'UPLOADED'` 텍스트 비교가 항상 실패한다. 서비스가 `sort.name()`을 넘긴다(전역 탐색은
정렬별 메서드 분리로 이 문제를 회피한 선례가 있고, 여기는 단일 쿼리 유지를 위해 String
바인딩으로 푼다).

PostgreSQL은 `LIMIT NULL`을 무제한으로 해석하므로 limit null 바인딩이 곧 "전부"다. 선택되지
않은 CASE 키는 전 행 NULL이라 동률로 취급되어 다음 키로 넘어간다. 나머지 SELECT 목록과 grids·
regions 조인은 기존 그대로다. 기존 무파라미터 경로는 서비스가 `(userId, null, COLLECTED, 30)`
으로 부르며, 이 조합의 결과가 기존 쿼리와 동일함을 테스트로 고정한다(FR-7 검증). 서비스의 뷰
매핑(toView: GridEncoder.decode, presign[^5], 구역 이름 리졸버 1회 획득)은 coverDurationSec
통과 한 줄 외에 변경 없이 재사용한다.

## 테스트 시나리오

리포지토리(통합, 공유 로컬 DB 정리 후):

- `무파라미터_조합은_기존과_같이_수집_시각순_최대_30개를_반환한다` (FR-7)
- `regionCode를_지정하면_그_행정동_격자만_반환한다` (타 동 격자 제외, FR-1)
- `귀속은_격자_소속_행정동_기준이다` (grids.region_code 축, FR-5)
- `UPLOADED_정렬은_최신_업로드순이고_동률은_grid_id_내림차순이다` (FR-2)
- `limit을_지정하면_그_수만_반환한다` (FR-3)
- `regionCode_지정에_limit_생략이면_그_동네_전부를_반환한다` (미해결 질문 2 채택안)

**실행 쿼리** — `UserGridRepository.getCollectionGrids` (native, 실소스):

```sql
SELECT ug.grid_id, ug.first_collected_at, ug.last_uploaded_at, ug.video_count, ug.cover_video_id,
	CASE WHEN v.processing_status = 'READY' THEN v.thumbnail_url END AS "coverThumbnailKey",
	v.duration_sec AS "coverDurationSec", r.region_name
FROM user_grids ug
LEFT JOIN videos v ON v.id = ug.cover_video_id
LEFT JOIN grids g ON g.grid_id = ug.grid_id
LEFT JOIN regions r ON r.region_code = g.region_code
WHERE ug.user_id = :userId
	AND (CAST(:regionCode AS varchar) IS NULL OR g.region_code = CAST(:regionCode AS varchar))
ORDER BY
	CASE WHEN :sort = 'UPLOADED' THEN ug.last_uploaded_at END DESC,
	CASE WHEN :sort = 'COLLECTED' THEN ug.first_collected_at END DESC,
	ug.grid_id DESC
LIMIT CAST(:limit AS bigint)
```

`LIMIT NULL`은 PostgreSQL이 무제한으로 해석한다(limit null 바인딩 = 전체 보기). 선택되지 않은 CASE 정렬 키는 전 행 NULL이라 동률 통과. 구동은 user_grids PK 선두(user_id) 후 PK/equi 조인 — 신규 인덱스 불요.

**예외 흐름** — sort 무효 값(소문자 포함)은 스프링 enum 바인딩 실패 `MethodArgumentTypeMismatchException` → `GlobalExceptionHandler.handleTypeMismatch`가 400 BAD_REQUEST(공통 developCode 400)로 변환. 신규 에러 코드 0건. 미인증은 SecurityConfig 401(2403). 미존재 regionCode·내 격자 없음은 예외가 아니라 200 + 빈 배열.

**빈 동작** — 신설 빈 없음. 조회는 기존 `UserGridQueryServiceImpl`의 `@Transactional(readOnly = true)` 경계 그대로이고 스케줄러·비동기·afterCommit 훅 관여 없음.
