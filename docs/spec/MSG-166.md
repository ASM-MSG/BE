## 개요

미션 정의(`missions`)·판정 대상 격자(`mission_grids`)·완료 스탬프(`user_missions`) 3개 테이블을 만드는
Flyway V6 마이그레이션 1건 + ERD 문서화다. 첫 진입 빈 화면 문제(미점령 격자 미표시 정책의 부작용)를 미션이
"안내판"으로 채우기 위한 데이터 골격이며, 격자를 **기록 단위(방문·점령)** 에 더해 **미션 판정 단위**로 겸하게 한다.

```
[현재] V1~V5 — 미션 개념 없음. 격자는 videos(방문)·user_grids(점령) 축만 존재
[MSG-166] V6 — missions(정의)·mission_grids(판정 대상)·user_missions(스탬프) 3테이블 추가
[이후] MSG-222/223 — JPA 엔티티·조회 API·완료 판정 로직 (본 티켓 범위 밖)
```

이 티켓은 **스키마 + ERD만** 다룬다. 엔티티 매핑·API·판정 로직은 후속 티켓(§범위 밖).

## 배경 · 목표

- **사용자/제품 관점**: 지도 첫 진입 시 미점령 격자를 안 그리는 정책 탓에 화면이 비어 보인다. 지자체 축제·
  둘레길 코스·테마 스팟을 "미션"으로 얹어 가야 할 곳을 안내하고, 완료하면 스탬프를 준다(도감=면적 축과 분리된
  개수 축). 그 데이터를 담을 스키마가 이 티켓이다.
- **목표**: 설계검토에서 확정한 미션 5종을 **테이블 3개 + 단일 판정 쿼리**로 흡수하는 스키마를 Flyway V6로
  반영한다. 유형별 전략 클래스 없이 쿼리 분기만으로 처리 가능하도록, 판정에 필요한 최소 컬럼(대상 격자 집합·
  기간·목표 수)과 영속 스탬프만 담는다. MSG-145(V3 AI 컬럼)과 **분리된 별도 버전**으로 작성한다.

## 성공 기준

1. Flyway V6가 컨텍스트 부팅 시 적용돼 `missions`·`mission_grids`·`user_missions` 3테이블이 생성된다.
2. `missions.type`은 5종(`COURSE`/`AREA`/`EVENT`/`THEME`/`CONTINUOUS`)만 허용하고 그 외 값은 CHECK 위반으로 거부한다.
3. **코스 무기간(상시)**: `missions.start_at`/`end_at`이 NULL 허용된다(코스는 기간 조건 없이 상시).
4. `missions.path`는 **코스 외 미션에 NULL**이 강제된다(CHECK) — 표시용 GeoJSON LineString은 코스에만.
5. `mission_grids.grid_id`는 **grids에 row가 없는 격자(미방문 포토스팟)도 INSERT된다** — FK 부재 확인(§D2).
6. `mission_grids`는 `(mission_id, grid_id)` 중복을 PK로 거부하고, `grid_id → mission` 역방향 조회 인덱스를 갖는다.
7. `user_missions`는 `(user_id, mission_id)` UNIQUE(=PK)를 강제하고, **스탬프가 있는 미션은 삭제되지 않는다**
   (mission FK NO ACTION). `user` 삭제 시 스탬프는 CASCADE 삭제된다.
8. **기존 V1~V5 checksum 불변** — `./gradlew test` 전체 green(부팅 시 V6까지 마이그레이션 성공).
9. **엔티티·API·판정 로직은 이 티켓에 없다**(§범위 밖) — 스키마와 ERD만.

## 설계 결정 (근거 포함)

| # | 포인트 | 결정 | 근거 |
|---|---|---|---|
| D1 | `missions.path` 타입 | **JSONB (GeoJSON `LineString` 객체 저장)** — GEOMETRY(LINESTRING) 아님 | path는 **표시용이지 판정용이 아니다**(코스 폴리라인 렌더링). PostGIS geometry의 유일한 가치(GIST·`ST_` 공간연산)를 path는 **하나도 안 쓴다** — `center_geom`/`boundary_geom`(공간 판정+GIST)과 성격이 정반대. FE가 GeoJSON을 소비하므로 JSONB는 저장값을 **읽을 때 변환 0**(geometry면 매 조회 `ST_AsGeoJSON`)이고, 148 코스 반영구 시드라 쓰기 빈도 극저·seeding은 JSON 문자열 INSERT로 끝난다. *대안(리뷰 교체 가능): 타 지오 컬럼과의 표기 일관성을 위해 `GEOMETRY(LINESTRING, 4326)`로 가고 조회 시 `ST_AsGeoJSON` — 동작 동일, 읽기 변환 비용만 추가. 공간연산이 영영 안 붙으므로 본 스펙은 JSONB 채택.* |
| D2 | `mission_grids.grid_id` FK | **grids FK 걸지 않음 — 논리 참조(`VARCHAR(20)`, `"{grid_y}_{grid_x}"`)** | grids는 **lazy insert**(glossary: grids row = "누군가 영상을 올린 격자"). 미션 포토스팟은 **미션 저자가 지정**하는 것이라 아직 아무도 안 올린 격자면 grids에 row가 없다 → FK를 걸면 미방문 포토스팟의 `mission_grids` INSERT가 **FK 위반으로 실패**한다. 격자 키 자체가 좌표에서 계산되는 논리 식별자(`GridEncoder`)라 grids row 없이도 유효하다. 판정 시 조인은 videos.grid_id 문자열 매칭으로 성립(grids 불필요). |
| D3 | `missions.type` 표현 | **`VARCHAR(20) + CHECK IN (5종)`** — native enum 아님. CHECK는 **5종 전부** 나열 | V1 설계 노트 #4 관용("ENUM→VARCHAR+CHECK, 개발 중 값 변경 유연성")을 그대로 따른다(users.provider·videos.status 등 전례). native enum은 값 추가에 `ALTER TYPE` 필요. **CHECK에 5종 전부 넣는 이유**: MVP 스코프(어느 유형까지 서비스할지, §미해결 1)는 **seeding/서빙 계층에서 게이트**하고 스키마는 5종을 모두 수용한다 — 스코프 결정과 스키마를 분리해 머지 게이트 해제 시 스키마 재작업이 없게 한다. |
| D4 | `mission_grids` 역방향 인덱스 | **`idx_mission_grids_grid ON mission_grids (grid_id)`** 추가 | 판정(MSG-223)의 hot path는 "이 영상의 grid_id가 어떤 미션의 대상 집합에 드는가" = `WHERE grid_id = ?`. PK `(mission_id, grid_id)`는 grid_id가 **두 번째 컬럼**이라 grid_id 단독 조회에 못 쓴다 → 별도 인덱스 필요. 정방향("미션의 대상 격자 전부")은 PK 프리픽스로 커버. |
| D5 | `missions` 보조 인덱스 | **추가하지 않음**(PK만) — 의도된 결정 | active 미션 조회(`GET /api/missions/active`)는 위키 확정상 **bbox 없이 TTL 1h 전역 캐시**라 실제 쿼리는 시간당 1회, 대상은 **수백 행**(148 코스 + 소수 이벤트/구역)이다. 판정 경로도 missions엔 `mission_grids` 조인(D4)으로 **PK로만** 닿는다. NULL 많은 `start_at`/`end_at`에 시간창 인덱스를 얹어봐야 tiny-table 풀스캔보다 이득이 없다(YAGNI). *업그레이드 트리거: 미션이 수만 행을 넘거나 active 조회의 캐시가 걷히면 `idx_missions_active` 재검토.* |
| D6 | `reward` 컬럼 | **미추가** — MVP 보상은 스탬프뿐 | MVP는 완료 시 **무조건 스탬프 1개**만 발급(보상 축 분리: 도감=면적, 스탬프북=개수). `user_missions` row 자체가 보상이라 `missions.reward`에 담을 변주가 없다(전 행 'STAMP'면 정보 0 = YAGNI). Phase 2에서 다양 보상(뱃지·포인트·쿠폰) 도입 시 additive ALTER(V7)로 추가 — V2~V5가 전부 그런 additive 진화라 지금 비워두는 비용은 0. *설계검토 컬럼 목록엔 reward가 있어 §미해결 2에서 확인 요청.* |
| D7 | `user_missions` 구조 | **`user_badges` 패턴 미러** — 복합 PK `(user_id, mission_id)`, `user_id` CASCADE, `mission_id` NO ACTION, 단일 `completed_at` | `user_badges`(사용자↔뱃지 획득 junction)가 정확한 기존 전례다: 복합 PK·서러게이트 없음(V1 노트 #2), user 삭제 시 CASCADE, 정의(badge/mission) FK는 NO ACTION. `completed_at` 하나로 충분(스탬프 발급=완료 시각, created_at 별도 불필요). mission FK **NO ACTION**이라 스탬프가 걸린 미션은 하드 삭제가 막혀 **영구 기록이 보호**된다(스탬프 비회수 요구, §D8). |
| D8 | 스키마가 인코딩하는 불변식 | **완료 판정 원천 = videos + 기간**(user_grids 아님) · **스탬프 ≠ 점령, 비회수** | (1) 판정을 `user_grids`(점령)가 아니라 `videos`(방문) + 기간 조건으로 하면 **작년 기록으로 스탬프 자동발급되는 결함**이 차단된다(코스는 무기간이라 기간 조건 생략). 스키마는 그래서 `user_grids`를 건드리지 않는다 — **가짜 격자 삽입 절대 금지**. (2) 스탬프(`user_missions`)는 점령(`user_grids`)과 **독립 테이블**이라, 영상 삭제로 점령이 롤백(glossary: video_count=0 → user_grids 삭제)돼도 **이미 발급된 스탬프는 유지**된다(비회수). 판정/발급 로직은 MSG-223이지만 이 분리가 스키마의 존재 이유다. |

## 데이터 모델 (Flyway V6)

**신규 파일**: `src/main/resources/db/migration/V6__mission_schema.sql`
**기존 V1~V5 무수정**(MSG-130). MSG-145(V3)와 분리된 별도 버전.

```sql
-- V6__mission_schema.sql
-- MSG-166: 미션 스키마 — missions · mission_grids · user_missions.
-- 2026-07-20 설계검토 + 2026-07-23 후속결정(반영구 시드 · 코스 target=포토스팟 5~8곳) 반영.
-- MSG-145(V3 AI 컬럼)과 분리된 별도 버전. 기존 V1~V5 무수정(MSG-130 checksum).
-- MVP 미션 범위 = 5종 그대로 확정(2026-07-23) — 머지 게이트 해제.

-- ============================================================================
-- missions (미션 정의 — 5종: COURSE·AREA·EVENT·THEME·CONTINUOUS)
-- 코스는 무기간(상시): start_at/end_at NULL 허용. reward 컬럼 없음(MVP 보상=스탬프뿐, §D6).
-- ============================================================================
CREATE TABLE missions (
	id           BIGSERIAL PRIMARY KEY,
	type         VARCHAR(20)  NOT NULL,
	title        VARCHAR(200) NOT NULL,
	region_code  VARCHAR(10)  REFERENCES regions(region_code),  -- 구역(AREA) 등 행정동 귀속, 그 외 NULL
	start_at     TIMESTAMP,                                      -- NULL = 무기간(상시, 코스)
	end_at       TIMESTAMP,                                      -- NULL = 무기간(상시, 코스)
	target_count INTEGER      NOT NULL,                          -- 완료에 필요한 distinct 방문 격자 수 (이벤트=1, 코스=포토스팟 일부/전부)
	path         JSONB,                                          -- 코스 표시용 GeoJSON LineString, 코스 외 NULL (§D1)
	created_at   TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,

	CONSTRAINT chk_missions_type   CHECK (type IN
		('COURSE', 'AREA', 'EVENT', 'THEME', 'CONTINUOUS')),
	CONSTRAINT chk_missions_target CHECK (target_count > 0),
	CONSTRAINT chk_missions_period CHECK (start_at IS NULL OR end_at IS NULL OR start_at <= end_at),
	CONSTRAINT chk_missions_path   CHECK (path IS NULL OR type = 'COURSE')
);

-- ============================================================================
-- mission_grids (미션 판정 대상 격자 — 코스는 포토스팟 5~8곳만, 전체 격자 아님)
-- grid_id 는 grids FK 없음: grids 는 lazy insert 라 미방문 포토스팟은 grids row 부재 가능(§D2).
-- ============================================================================
CREATE TABLE mission_grids (
	mission_id BIGINT      NOT NULL REFERENCES missions(id) ON DELETE CASCADE,
	grid_id    VARCHAR(20) NOT NULL,                            -- 논리 참조("{grid_y}_{grid_x}") — grids FK 없음(§D2)
	seq        INTEGER,                                         -- 코스 포토스팟 순번(1..N), 순서 없는 유형은 NULL

	PRIMARY KEY (mission_id, grid_id)
);
CREATE INDEX idx_mission_grids_grid ON mission_grids (grid_id);  -- 역방향: grid_id → 미션 (판정, §D4)

-- ============================================================================
-- user_missions (스탬프 — 비회수·영속. 미션 만료 후 videos 재계산으로 복원 불가라 영속 필요)
-- user_badges 패턴 미러(복합 PK · user CASCADE · mission NO ACTION · 단일 타임스탬프, §D7).
-- ============================================================================
CREATE TABLE user_missions (
	user_id      BIGINT    NOT NULL REFERENCES users(id) ON DELETE CASCADE,
	mission_id   BIGINT    NOT NULL REFERENCES missions(id),   -- NO ACTION: 스탬프 걸린 미션 하드삭제 차단(비회수 보호)
	completed_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

	PRIMARY KEY (user_id, mission_id)
);
```

**엔티티 매핑**: 없음(§범위 밖 — MSG-222). `region_stats`·`badges`처럼 스키마만 선반영, JPA 엔티티는 후속.
**계약 인터페이스**: 무변경(§계약 변경).
**신규 에러코드**: 없음(스키마 티켓 — 런타임 에러 경로 없음).

### 판정 로직이 이 스키마에 거는 요구 (참고 — 로직 자체는 MSG-223)

스키마가 아래 판정을 지지하도록 설계됐음을 남긴다(구현 아님, 컬럼 존재 이유 확인용):

- 완료 판정(개념): `SELECT count(DISTINCT v.grid_id) FROM videos v WHERE v.grid_id IN (미션 대상 격자) AND [기간 조건] >= target_count`.
  - 대상 격자 = `mission_grids WHERE mission_id = ?`의 `grid_id` 집합. 기간 조건 = `v.recorded_at BETWEEN start_at AND end_at`,
    **코스는 무기간이라 기간 조건 생략**(start/end_at NULL). 판정 원천은 videos이지 user_grids가 아니다(§D8).
- 유형 분기는 **쿼리 분기**로 족하다(기간 유/무, target=1 등) — 유형별 전략 클래스 금지(설계검토 확정).

## 테스트 시나리오 (JUnit5 + AssertJ · 한국어 백틱 메서드명)

**검증 방식**: 코드베이스에 별도 Flyway 단정 하네스는 없다. 기존 관용(`GridRegionCodeLabelTest` 등)대로
`@SpringBootTest` + `local`(실 PostGIS, Flyway V1~V6 자동 적용) + `@Transactional` 롤백으로 부팅 검증한다.
격리는 합성 행(실데이터와 충돌 없는 값)만 쓰고 truncate하지 않는다. 컨텍스트가 뜨는 것 자체가 V6 적용 증거이며,
그 위에서 제약 동작을 native INSERT로 확인한다.

### 마이그레이션 적용 (부팅 = V6 성공)
- `V6가_적용되면_missions_mission_grids_user_missions_3테이블이_존재한다` (`information_schema.tables` 확인)

### missions 제약
- `type이_5종_외_값이면_chk_missions_type_위반으로_INSERT가_실패한다`
- `코스_5종_전부는_INSERT된다` (`COURSE`/`AREA`/`EVENT`/`THEME`/`CONTINUOUS` 각 1건)
- `코스는_start_at_end_at이_NULL이어도_INSERT된다` (무기간 상시)
- `코스가_아닌_미션에_path를_넣으면_chk_missions_path_위반이다`
- `코스에_GeoJSON_LineString_path를_JSONB로_저장하고_조회할_수_있다`
- `start_at이_end_at보다_뒤면_chk_missions_period_위반이다`
- `target_count가_0이하면_chk_missions_target_위반이다`

### mission_grids 제약 (§D2 핵심)
- `grids에_row가_없는_격자도_mission_grids에_INSERT된다` (FK 부재 — lazy insert 미방문 포토스팟)
- `같은_mission_id와_grid_id_조합은_PK로_중복이_거부된다`
- `mission을_삭제하면_mission_grids가_CASCADE로_함께_삭제된다`
- `seq는_NULL이_허용된다` (순서 없는 유형)

### user_missions 제약 (§D7 스탬프)
- `같은_user_id와_mission_id_스탬프는_PK로_중복이_거부된다` (UNIQUE 대체)
- `스탬프가_있는_mission은_삭제되지_않는다` (mission FK NO ACTION — 비회수 보호)
- `user를_삭제하면_user_missions가_CASCADE로_함께_삭제된다`
