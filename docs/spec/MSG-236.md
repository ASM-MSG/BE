# MSG-236: `refreshRegionStats` recompute를 `grids.region_code` equi-join으로 단순화 (MSG-167 §D6 후속)

**Owner**: A (region/grid)
— 변경 지점이 전부 Owner A 자산이다: `RegionRepository.refreshRegionStats`(region) + 테스트 픽스처 `GridFixtures`(grid — 신규 `seedLabeledGrid` 추가, `seedGrid`는 무변경). Owner B 코드·크로스오너 계약 4종 시그니처 불변, 스키마 변경 0.

> **부모: MSG-167 §D6**가 예약한 후속이다. 167은 `grids.region_code`(격자 중심점 행정동 라벨)를 쓰기 시 1회 판정·저장하고 조회를 순수 equi로 만들었으나, 155 `refreshRegionStats`의 두 `ST_Covers`를 equi로 바꾸는 최적화는 **비스코프로 유예**했다 — 사유: (1) 스코프 봉쇄, (2) 155는 지금 정확해 강제 사유(버그) 없음, (3) equi 정확성이 **모든 격자의 신뢰성 있는 라벨**에 의존(NULL 격자를 equi가 해안 취급). 그 선결 조건(라벨 신뢰성)이 **167 merge로 충족**됐다: upsertGrid 인라인 라벨 + V5 백필 + `RegionSeeder.run` 시딩 직후 `backfillGridRegionCodes` 보정(§D2 보정, `RegionRepository.backfillGridRegionCodes`). 이 티켓이 그 교체를 수행한다.

---

## 개요

`RegionRepository.refreshRegionStats`(155)는 수집률 재계산 시 `ST_Covers`를 **두 번** 판정한다 — ① 대상 격자의 귀속 행정동(LATERAL `tr`), ② 사용자가 점령한 격자들 각각의 귀속을 대상 행정동과 대조(LATERAL `cnt` 내부 상관 서브쿼리). 두 판정 모두 **167이 이미 저장해 둔** `grids.region_code`를 읽으면 되므로, 라이브 `ST_Covers`를 `grids.region_code` equi-join으로 치환한다. 저장 라벨 = 라이브 판정이 167 일치 테스트로 고정돼 있어 결과는 등가다.

**핵심은 "동작하는 쿼리의 등가 재작성"** — 새 기능·API·스키마 없음. 게이트는 `RegionStatsRecomputeTest` 전건이 그대로 green이다.

---

## 배경 · 목표

- **왜**: 167 §D6이 라벨 신뢰성 확보를 조건으로 예약한 정리다. recompute는 첫 점령·롤백마다 도는 쓰기 경로인데, 지금은 저장된 라벨을 두고도 매번 GIST `ST_Covers`를 다시 판정한다(대상 1회 + 점령 격자 수만큼 N회). 라벨을 읽는 equi로 바꾸면 판정 경로가 하나(쓰기 시 upsertGrid 1회)로 수렴해 "귀속 판정은 격자 생애 1회"라는 167 설계가 recompute까지 일관되게 관철된다.
- **목표**:
  1. `refreshRegionStats`의 두 `ST_Covers`를 `grids.region_code` equi로 치환하고 `WHERE g.region_code IS NOT NULL` 가드를 둔다.
  2. `RegionStatsRecomputeTest` 전건 + `RegionStatsConcurrencyTest`(165)가 **무변경으로 green** — 등가·무회귀 증명.
  3. advisory lock 직렬화 로직(`RegionStatsCommandServiceImpl.refresh` → `acquireUserRegionStatsLock`)은 **손대지 않는다**.

## 성공 기준 (관찰 가능)

1. `refreshRegionStats` 쿼리 문자열에 **`ST_` 연산이 하나도 없다** (두 LATERAL의 `ST_Covers` 제거).
2. `RegionStatsRecomputeTest` 전건(현 10건) **결과·기대값 무변경으로 green** — collected_count·경계 격자·해안 no-op·다중매칭 타이브레이크·롤백 0-UPSERT·멱등·사용자 격리가 equi 버전에서 동일.
3. `RegionStatsConcurrencyTest`(165)가 무변경 green — advisory lock 직렬화로 최종 `collected_count = 2`.
4. **무라벨(`region_code IS NULL`) 격자**: 대상이면 no-op(가드), 점령 격자 중 하나면 카운트에서 제외 — 이는 167 라벨 파이프라인이 격자를 신뢰성 있게 채운다는 전제 하에 라이브 `ST_Covers` 결과와 등가다(§D2).
5. 크로스오너 계약 4종 시그니처 불변. **스키마 변경 0**(마이그레이션 추가 없음 — `grids.region_code`는 V5에서 이미 존재). 신규 에러 코드 없음. 공유 로컬 DB 미오염.

## 결정 (Decisions)

### D1 — 두 `ST_Covers` LATERAL → `grids.region_code` equi-join, 가드는 대상 격자에

- **결정**: `refreshRegionStats`의 `SELECT` 본문을 아래로 치환한다. `ON CONFLICT … DO UPDATE`·시그니처·파라미터는 불변.

**기존 (2× `ST_Covers`)**:
```sql
FROM grids g
JOIN LATERAL (                                     -- ① 대상 격자의 귀속 행정동
    SELECT r0.region_code, r0.total_grid_count
    FROM regions r0
    WHERE ST_Covers(r0.boundary_geom, g.center_geom)
    ORDER BY r0.region_code LIMIT 1
) tr ON TRUE
JOIN LATERAL (
    SELECT COUNT(*) AS collected
    FROM user_grids ug
    JOIN grids g2 ON g2.grid_id = ug.grid_id
    WHERE ug.user_id = :userId AND tr.region_code = (   -- ② 점령 격자별 귀속을 대조
        SELECT r2.region_code FROM regions r2
        WHERE ST_Covers(r2.boundary_geom, g2.center_geom)
        ORDER BY r2.region_code LIMIT 1)
) cnt ON TRUE
WHERE g.grid_id = :gridId
```

**신규 (equi, `ST_` 0)**:
```sql
FROM grids g
JOIN regions tr ON tr.region_code = g.region_code    -- ① 저장 라벨 equi (LATERAL 제거)
JOIN LATERAL (
    SELECT COUNT(*) AS collected
    FROM user_grids ug
    JOIN grids g2 ON g2.grid_id = ug.grid_id
    WHERE ug.user_id = :userId
      AND g2.region_code = tr.region_code            -- ② 저장 라벨 equi (상관 ST_Covers 제거)
) cnt ON TRUE
WHERE g.grid_id = :gridId
  AND g.region_code IS NOT NULL                      -- 가드: 무라벨/해안 대상 = no-op
```
- `tr`은 `total_grid_count`를 위해 `regions`와 조인해 남긴다(더는 LATERAL 아님, 순수 PK equi).
- 안쪽 `cnt` LATERAL 구조는 유지(집계라 상관 필요) — 내부의 `ST_Covers` 서브쿼리만 `g2.region_code = tr.region_code` equi로 축약.
- **가드 위치**: 대상 격자 `g`. `g.region_code IS NULL`(해안·무라벨)이면 no-op — 기존의 "덮는 행정동 없으면 LATERAL empty → 무변경 no-op"와 등가. equi에선 `JOIN regions tr ON tr.region_code = g.region_code`가 NULL을 자연 탈락시키므로 가드는 **엄밀히는 redundant지만**, no-op 의도를 명시하고 향후 LEFT JOIN 재작성 방어용으로 둔다(§D6이 지정한 형태).
- **근거**: `grids.region_code`는 격자 중심점의 함수로 167이 쓰기 시 저장했고, 저장값 = 라이브 판정이 167 3중 일치 테스트로 고정됐다(§D2). 라이브 재판정은 순수 낭비.

### D2 — 등가성 논증 + 무라벨 격자 엣지 결론

세 축으로 등가를 논증하고, 유일한 발산 후보(무라벨 격자)의 실재 여부를 검토한다.

- **① 대상 격자 귀속**: `g.region_code`(저장) == `ST_Covers(boundary, g.center_geom) ORDER BY region_code LIMIT 1`(라이브). 같은 규칙·같은 점, 167 일치 테스트(`저장된_region_code는_by_grid_귀속과_같은_행정동이다`)로 고정. **등가**.
- **② 점령 격자 카운트**: `g2.region_code = tr.region_code`(저장 equi) == 라이브 `ST_Covers(g2.center_geom)` 결과 = `tr.region_code`. `g2.region_code`가 저장 라벨 = 라이브 판정이므로 **등가**. 경계 격자·다중매칭 타이브레이크(`ORDER BY region_code`)도 저장 시 이미 결정적으로 단일화돼 있어 동일.
- **③ NULL 라벨(해안)**: 저장 NULL == 기존 `ST_Covers` 무매칭(빈 LATERAL). 대상이면 no-op, 점령 격자면 카운트 제외 — 기존과 **등가**.

**무라벨 격자 엣지(핵심 검토 대상)**: `regions`가 격자 생성 **후** 시딩됐고 **백필 실행 전**인 격자는 `region_code = NULL`이다(V5 백필은 Flyway 시점=시더 이전, upsertGrid는 기존 격자를 건너뜀). 이 창에서 라이브 `ST_Covers`(기존)는 regions가 이제 있으니 **정상 귀속·카운트**하지만, equi(신규)는 NULL을 해안 취급해 **제외** → 발산.

- **이 창이 실제로 존재하는가**: **정상 운영에선 닫혀 있다.** recompute는 업로드(점령/롤백) HTTP 요청으로만 트리거되고, 그건 앱 기동 완료 후에만 서빙된다. `RegionSeeder.run`은 기동 시 regions 시딩 **직후 같은 기동에서** `backfillGridRegionCodes`(EXISTS 가드, 멱등)를 1회 돌려 라벨 가능한 모든 NULL 격자를 채운다(167 §D2 보정). 따라서 첫 recompute가 도는 시점엔 백필이 이미 끝났다 → **발산 창 없음**.
  - regions 미시딩(시딩 플래그 off) 환경: 백필 no-op, 격자 라벨 NULL. 그러나 이때 라이브 `ST_Covers`도 regions가 비어 무매칭 → **양쪽 다 no-op으로 동일**. 발산 없음.
- **잔여 리스크 = 167이 이미 스코프-아웃한 운영 이벤트뿐**: 런타임 중 `RegionSeeder.run` 경로 밖으로 regions를 바꾸는 경우(행정동 경계 개편). 167 §작업 로그가 "개편 = regions 재시딩 + 전체 재라벨(region_code 리셋 후 백필) 운영 마이그레이션이 필요한 별도 전사 이벤트"로 명시 수용했고, 그 창에선 목록 라벨·동 단위 영상·recompute가 **모두 같은 stale 라벨을 읽는다** — recompute equi는 다른 `grids.region_code` 소비자보다 **더 stale하지 않다**. 라벨 자체가 신뢰 원천이라는 167 전제를 recompute도 공유할 뿐이다.
- **결론**: **정상 운영에서 등가.** 유일한 발산은 167이 이미 별도 운영 이벤트로 격리한 경계 개편뿐이고, 그건 라벨 소비 전반의 성질이지 이 티켓이 새로 여는 구멍이 아니다. D6의 선결 조건(라벨 신뢰성)이 167 merge로 충족됐으므로 교체 가능.

### D3 — `RegionStatsRecomputeTest`가 게이트가 되려면 픽스처가 라벨을 실어야 한다 (신규 `seedLabeledGrid` 분리 — `seedGrid`는 무라벨 계약 유지)

- **문제(게이트 성립의 전제)**: 현재 `GridFixtures.seedGrid`는 grids를 `region_code` **없이**(NULL) 삽입한다. 기존 recompute/동시성 테스트는 region을 먼저 시드하고 grid를 seedGrid로 넣은 뒤 refresh를 부르는데, 지금은 라이브 `ST_Covers`가 판정하므로 grid의 NULL 라벨이 무해했다. equi로 바꾸면 **NULL 라벨 격자 = 해안 취급 → 모든 기존 테스트가 collected_count 0으로 깨진다.** 즉 픽스처를 고치지 않으면 "등가 게이트" 자체가 성립하지 않는다.
- **결정(정정 2026-07-23, Codex)**: `GridFixtures.seedGrid`는 **NULL 삽입 그대로 유지**하고, **신규 `seedLabeledGrid`**(upsertGrid와 같은 판정 서브쿼리 인라인)를 추가해 **refresh 경로를 타며 라벨-탄생 격자를 기대하는 테스트 호출부 전부**를 교체한다 — 전수 기준은 grep(`refresh` 호출 ∩ `seedGrid` 사용)이며 현재 4클래스: `RegionStatsRecomputeTest`·`RegionStatsConcurrencyTest`(165)·`RegionStatsCommandServiceTest`·`RegionStatsPointGridQueryServiceTest`(정정 2026-07-23 — 최초 목록 2개는 불완전, 구현 시 grep 재확인 의무). 이유: `GridRegionCodeBackfillTest`는 region-먼저-시드 후에도 **무라벨로 태어난 격자**가 계약이다(첫 백필=1행 갱신·재실행 0행 등 5개 케이스) — 공유 픽스처 하나가 "라벨 탄생"과 "무라벨 탄생"이라는 정반대 의도를 동시에 만족할 수 없어, 루트 1곳 수정 대신 **의도별 픽스처 분리 + 영향 호출부 명시 교체**가 맞다.
```sql
INSERT INTO grids (grid_id, grid_y, grid_x, center_geom, bbox_geom, region_code)
VALUES (
    :gridId, :gridY, :gridX,
    ST_SetSRID(ST_MakePoint(:centerLng, :centerLat), 4326)::geography,
    ST_MakeEnvelope(:west, :south, :east, :north, 4326)::geography,
    (SELECT r.region_code FROM regions r
       WHERE ST_Covers(r.boundary_geom, ST_SetSRID(ST_MakePoint(:centerLng, :centerLat), 4326)::geography)
       ORDER BY r.region_code LIMIT 1))          -- ← upsertGrid·V5 백필과 동일 규칙
ON CONFLICT (grid_id) DO NOTHING
```
- **근거**:
  1. **게이트 유효성**: recompute·165 테스트가 `seedLabeledGrid`로 라벨 탄생 격자를 쓰면 equi refreshRegionStats가 프로덕션과 동일하게 동작 → 기존 기대값 무변경 green이 진짜 등가 게이트가 된다. 백필 테스트의 무라벨 계약은 seedGrid 그대로라 무영향.
  2. **프로덕션 충실**: upsertGrid가 격자 탄생 시 라벨하는 것과 정확히 같아, 픽스처가 프로덕션 상태를 재현한다.
  3. **부작용 없음**: regions를 시드하지 않는 순수 grid 테스트에선 서브쿼리가 NULL → 기존과 동일. 라벨은 격자 중심점을 덮는 합성 region이 있을 때만 붙는다.
- **순서 요건**: `seedLabeledGrid`의 인라인 판정이 잡으려면 **region을 grid보다 먼저 시드**해야 한다. 기존 게이트 테스트들은 이미 그 순서라 호출부 이름 교체만으로 충족(§테스트). 무라벨 격자는 기존 `seedGrid`가 그대로 담당(백필 테스트·신규 엣지).
- **기각**: ① seedGrid 자동 라벨(최초안) — `GridRegionCodeBackfillTest`의 무라벨 탄생 계약 파괴(첫 백필 1행 갱신 단언 등). ② 각 테스트에서 seedGrid 후 `backfillGridRegionCodes` 호출 — 픽스처가 프로덕션 라벨 시점(탄생)과 어긋나고 호출부 수정 범위는 동일.

## 벤치마크 — 구(ST_Covers LATERAL 2회) vs 신(equi-join) 실측 (2026-07-24)

채택 의사결정 입력으로 두 팔을 동일 조건에서 비교 실측했다 (2026-07-24 사용자 지시 — 벤치는 검증이 아니라 선택 근거).

- **측정 종류**: SQL **서버측 문장 지연** (plpgsql `clock_timestamp()` 하네스, warmup 5회 후 300 샘플/팔/K). 측정 대상은 refreshRegionStats의 SELECT부(귀속·집계)만 — `INSERT … ON CONFLICT` 물질화는 양팔 동일이라 제외. 네트워크/JDBC 미포함.
- **환경**: 로컬 `fillmap-postgres`(PostGIS 16-3.4), regions 실데이터 3,558 폴리곤, 서울 육지 격자 32×32 블록 + 벤치 사용자 1명 합성 시드 — 전량 단일 트랜잭션 ROLLBACK (복원 검증 regions=3558·bench 잔여 0). 스크립트: `scripts/bench-msg236.sql`.
- **K** = 사용자 점령 격자 수 (구 팔 분자 카운트의 격자당 ST_Covers 재판정 횟수를 지배하는 변수).

| K | 팔 | p50(ms) | p95 | p99 | avg | max |
|---|---|---|---|---|---|---|
| 10 | 구 ST_Covers | 0.5560 | 0.5960 | 0.7332 | 0.5631 | 0.8070 |
| 10 | 신 equi-join | 0.0290 | 0.0351 | 0.1180 | 0.0317 | 0.2140 |
| 100 | 구 ST_Covers | 5.9265 | 6.6480 | 15.4063 | 6.1630 | 21.6820 |
| 100 | 신 equi-join | 0.1230 | 0.1370 | 0.1660 | 0.1239 | 0.1820 |
| 1,000 | 구 ST_Covers | 60.2340 | 64.0297 | 72.9882 | 60.9053 | 98.4380 |
| 1,000 | 신 equi-join | 1.0560 | 1.1274 | 1.1862 | 1.0611 | 1.2140 |

- **스케일링**: 구 팔 p50은 K에 선형(≈0.06ms × K — 점령 격자당 GIST ST_Covers 1회, EXPLAIN에서 `idx_regions_boundary` SubPlan `loops=1000` 실측). 신 팔은 K=1,000에서도 ≈1ms (PK/btree만: `grids_pkey`·`regions_pkey`·`user_grids_pkey`). p50 배율 19×(K=10) → 48×(K=100) → **57×(K=1,000)**.
- **플랜 증명**: 신 팔 EXPLAIN에 GIST 스캔·`st_covers` 필터 **부재** (buffers 9,477→4,197, exec 60.3ms→1.25ms @K=1,000).
- **등가 스팟체크**: 동일 입력에서 OLD=NEW (`1117062500`, collected 106) — 실데이터 폴리곤 기준 귀속 일치.
- **쓰기측 상각 비용**(참고): 라벨 백필 1,024격자 84.91ms ≈ 0.083ms/격자 — 격자 생애 1회 (upsertGrid 인라인과 동일 규칙).
- **결론(권고)**: equi-join 채택. 구 팔은 점령 수에 비례해 악화(도감 1,000격자 사용자의 업로드/삭제마다 60ms+), 신 팔은 상수 근접. 알려진 무해 잔여: 시퀀스 전진, ANALYZE 의도적 생략(reltuples 잔류 차단, bench-msg164 관례).
