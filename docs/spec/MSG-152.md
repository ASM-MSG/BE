# MSG-152: 개인 도감 요약 API + usergrid 패키지 신설

**Owner**: B (`com.msg.fillmap.usergrid.*`) — 순수 Owner B. 단, `UserGridQueryService`(A↔B 계약 인터페이스)를 **신설**하므로 §계약 변경은 Owner A 확인 필수(155·156이 소비 예정).

> 신규 read 기능이자 **usergrid 패키지의 첫 티켓**이다. `status.md` 기준 `usergrid`는 ❌ 미생성 —
> 패키지 골격(repository·service·controller·dto)과 `UserGridQueryService` 계약을 이 티켓에서 처음 세운다.
> `user_grids`·`videos`에 데이터는 쌓이는데(MSG-66) 이를 집계해 볼 API가 없어 PRD ①(지도 홈 상단 카드)·⑦(개인 도감) 요약이 미구현이다.
>
> **용어(glossary 단일 진실 원천)**: 이 API가 세는 것은 **점령**(user_grids row = 개인 도감)과 **방문**(videos row = 이벤트)이다.
> `도감(Collection)` = 사용자가 점령한 격자 집합 = `user_grids`. API 리소스 경로는 사용자 대면 용어 `collections`를 쓰고,
> 구현 패키지는 백엔드 전용 명칭 `usergrid`를 쓴다(§D1). "점령/방문/수집" 표현을 코드·문서에서 혼용하지 않는다.
>
> **형제 경계**: MSG-155(region_stats 갱신 — 점령/롤백 시 사용자·행정동별 collected_count 계산, Owner A) ·
> MSG-156(수집률 조회, Owner A)가 이 티켓이 세운 `UserGridQueryService`를 **소비**한다. 본 티켓은 152에 필요한 최소 계약만 구현하고,
> 155가 쓸 read 프리미티브는 시그니처만 명세해 둔다(§계약 변경, §D10).

## 개요

개인 도감(⑦)·지도 홈(①) 상단 "요약 카드"에 쓰이는 집계 조회 API. 로그인 사용자 기준으로
**점령한 격자 수 · 올린 영상 총합 · 방문한 행정동 수** 세 값을 한 번에 내려준다.

```
GET /api/collections/summary  →  { totalGridCount, totalVideoCount, visitedRegionCount }
                                    ↑ user_grids       ↑ user_grids       ↑ videos.region_code
                                    COUNT              SUM(video_count)   COUNT(DISTINCT)
```

세 값 모두 이미 저장 중인 데이터에서 파생된다(신규 컬럼/마이그레이션 없음). streak·badge 등
게임화 지표는 MVP 응답에서 제외한다(§D3).

## 배경 · 목표

- **사용자/제품 관점**: 지도를 켜면 상단에 "내 도감 · N개 격자", 도감 화면에 "영상 M개 · 행정동 K곳"
  같은 한 줄 요약이 보여야 성취감·재방문 동기가 생긴다. 지금은 이 숫자를 계산해 줄 API가 없어 화면이 비어 있다.
- **목표**:
  1. 로그인 사용자의 도감 요약 3지표를 **단일 엔드포인트·단일 쿼리**로 제공한다.
  2. `usergrid` 패키지 골격과 **`UserGridQueryService` read 계약**을 세운다 — `GridQueryService`(A 제공→B 소비)와
     **대칭**(B 제공→A 소비). Owner A가 수집률(region stats)을 계산할 때 이 계약으로만 개인 도감을 읽는다.
  3. 점령 0건 사용자도 에러 없이 `{0, 0, 0}`을 받는다(빈 도감도 유효 상태).

## 성공 기준 (검증 가능)

1. `GET /api/collections/summary`(인증 필요)가 로그인 사용자 기준
   `{ totalGridCount, totalVideoCount, visitedRegionCount }` 3필드를 `SuccessResponse.of(...)`(HTTP 200 · `developCode 200`)로 반환한다.
2. `totalGridCount` = 내가 점령한 격자 수(`COUNT(user_grids)` where user_id).
3. `totalVideoCount` = 내 영상 총합(`SUM(user_grids.video_count)`), 점령 0건이면 0(NULL 아님).
4. `visitedRegionCount` = 내 영상이 남긴 서로 다른 행정동 수(`COUNT(DISTINCT videos.region_code)`, `DELETED` 제외).
   `region_code`가 NULL인 영상은 세지 않으며, `regions` 테이블이 시딩되지 않아도 계산된다.
5. **점령 0건 사용자**는 에러 없이 `{ 0, 0, 0 }`을 받는다(DoD 필수 케이스).
6. **사용자 격리**: 응답은 로그인 사용자 본인의 점령·영상만 반영한다(타인 데이터 미포함).
7. `usergrid` 패키지(`repository`·`service`+impl·`controller`·`dto`)와 `UserGridQueryService` 계약이 생성된다.
8. streak/badge 지표(`streaks`·`user_badges`)는 응답 스키마에 **필드 자체가 없다**(Phase 2).
9. DB 스키마 변경 없음(Flyway 불필요). 전체 테스트 green. `status.md` `usergrid`·계약 인터페이스 행 갱신(wrap-up).

## API 명세

인증: 로그인 필요. `userId`는 `@AuthenticationPrincipal AuthPrincipal`에서 획득(기존 방식). `SecurityConfig` 무변경(`anyRequest().authenticated()`).

### `GET /api/collections/summary`

- 요청 파라미터/바디 **없음**(인증 주체 기준 집계).
- 성공 200 `body` = `CollectionSummaryResponseDto`:

| 필드 | 타입 | 소스 | 의미 |
|---|---|---|---|
| `totalGridCount` | `Integer` | `COUNT(user_grids)` where user_id | 내가 점령한 격자 수(도감 크기) |
| `totalVideoCount` | `Long` | `COALESCE(SUM(user_grids.video_count), 0)` | 내가 올린 영상 총합 |
| `visitedRegionCount` | `Integer` | `COUNT(DISTINCT videos.region_code)` (`DELETED` 제외) | 내가 방문한 서로 다른 행정동 수 |

**응답 예시**
```json
{
  "developCode": 200,
  "httpStatus": "OK",
  "message": "성공",
  "body": {
    "totalGridCount": 15,
    "totalVideoCount": 42,
    "visitedRegionCount": 6
  }
}
```

**점령 0건 사용자 응답**
```json
{ "developCode": 200, "httpStatus": "OK", "message": "성공",
  "body": { "totalGridCount": 0, "totalVideoCount": 0, "visitedRegionCount": 0 } }
```

**에러**: 도메인 실패 케이스 없음. 인증 실패(토큰 없음/무효)는 기존 시큐리티/`CustomAuthenticationEntryPoint`가 401로 처리(본 티켓 신규 코드 아님). → **신규 에러 코드 enum 없음**(§D8).

## 도메인 로직

### 집계 규칙 (핵심)

세 지표를 **단일 네이티브 쿼리(스칼라 서브쿼리 3개)**로 1왕복 조회한다(§D4).

```sql
SELECT
  (SELECT COUNT(*)::int
     FROM user_grids WHERE user_id = :userId)                         AS "totalGridCount",
  (SELECT COALESCE(SUM(video_count), 0)
     FROM user_grids WHERE user_id = :userId)                         AS "totalVideoCount",
  (SELECT COUNT(DISTINCT region_code)::int
     FROM videos WHERE user_id = :userId AND status <> 'DELETED')     AS "visitedRegionCount"
```

- **점령 = user_grids row 존재**(glossary). `totalGridCount`는 개인 도감 크기다. 미점령 격자·타인 점령은 세지 않는다.
- `totalVideoCount`는 `user_grids.video_count`의 합이다. 영상 삭제 시 `video_count`가 감소(MSG-72)하므로 **활성 영상만 반영**된다. 점령 0건이면 `SUM`이 NULL → `COALESCE`로 0.
- `visitedRegionCount`는 `videos.region_code`의 distinct 수다.
  - `region_code`는 nullable이고 SQL `COUNT(DISTINCT)`가 NULL을 자동 제외 → **regions 미시딩·좌표 밖 업로드여도 계산 가능**(regions 테이블 JOIN 없음, 저장된 코드 문자열만 셈).
  - `status <> 'DELETED'`로 삭제 영상 제외 → `totalVideoCount`(활성만 반영)와 의미 정합. `BLINDED`(모더레이션 숨김)는 방문 사실로 보고 포함(§D6).
- **타입 주의**: Postgres `COUNT(*)`/`COUNT(DISTINCT)`는 `bigint`를 반환하므로 `::int` 캐스트로 `Integer` 프로젝션과 맞춘다. `SUM(int)`은 `bigint` → `Long`.

### 레이어 구성 (3-layer 준수, GridQueryService 대칭)

- `UserGridRepository extends JpaRepository<UserGrid, UserGridId>`(§D4): 위 집계 네이티브 쿼리 1개 → `CollectionSummaryProjection`(`getTotalGridCount():Integer`, `getTotalVideoCount():Long`, `getVisitedRegionCount():Integer`).
- `UserGridQueryServiceImpl`: `getCollectionSummary(userId)` — 리포지토리 호출 후 `CollectionSummaryView`로 매핑. `@Transactional(readOnly = true)`.
- `CollectionController`: `@AuthenticationPrincipal`에서 `userId` → 서비스 호출 → `CollectionSummaryResponseDto.from(view)` → `SuccessResponse.of(...)`. 컨트롤러는 얇게.

## 계약 변경

**Owner A 확인 필요.** `UserGridQueryService`는 infrastructure.md의 A↔B 계약 인터페이스 4종 중 하나(**B 제공 → A 소비**)이며, 이 티켓에서 **신설**된다. 155/156(Owner A)이 소비할 계약이므로 시그니처 형태를 Owner A가 리뷰에서 확인한다.

### `UserGridQueryService` 신설 (Owner B 제공)

```java
/**
 * 개인 도감 조회 계약 (B 제공 → A 소비, infrastructure.md 경계면). GridQueryService 와 대칭.
 * 엔티티는 grid.entity.UserGrid(Owner A, MSG-78 D6) — usergrid 는 그 위의 조회 계약 패키지.
 */
public interface UserGridQueryService {

	/** 로그인 사용자의 도감 요약: 점령 격자 수 · 영상 총합 · 방문 행정동 수. 점령 0건이면 (0, 0, 0). */
	CollectionSummaryView getCollectionSummary(long userId);
}
```

- 반환은 **내부 뷰 record `CollectionSummaryView(int totalGridCount, long totalVideoCount, int visitedRegionCount)`**. HTTP DTO 변환은 컨트롤러(§D7).
- **155에서 non-breaking 추가 예정(구현 안 함 — §D10)**: `region_stats.collected_count` 계산용 read 프리미티브.
  예상 시그니처 `int countCollectedGridsInRegion(long userId, String regionCode)` — 사용자가 특정 행정동에서 점령한 격자 수
  (grid↔region은 v6상 `videos.region_code`로 해소되며 정확한 조인 규칙은 155에서 확정). 인터페이스 메서드 추가는 non-breaking이라 **소비처(155)가 생길 때 추가**한다.

### 나머지 계약 인터페이스

`GridQueryService`·`HotZoneService`·`UserOidcCommandService` 시그니처는 **불변**. (본 티켓은 `GridQueryService`를 소비하지도 않는다 — 집계는 usergrid가 `user_grids`/`videos`를 직접 읽는다.)

### 신규 에러 코드

**없음**(§D8). 도메인 실패 케이스가 없어 `UserGridErrorCode` enum·`usergrid/exception` 패키지를 만들지 않는다. 실패 케이스가 생기면 그때 도메인 대역(2xxx auth·3xxx video·4xxx grid와 겹치지 않는 대역)으로 추가한다.

## 확정 결정 (구현 전 잠금)

> spec-driven-dev 오케스트레이터/개발 에이전트는 아래 결정을 그대로 따르며 재논의하지 않는다.

- **D1 — 패키지·경로·클래스 매핑**: 구현 패키지 `com.msg.fillmap.usergrid`(Owner B), API 리소스 `/api/collections`, 컨트롤러 `CollectionController`. 백엔드 구현명(usergrid) ↔ 사용자 대면 리소스(collections) ↔ glossary `도감(Collection)` = `user_grids`. (`GridController`가 grid 패키지에서 `/api/grids`를 서비스하는 것과 동일한 impl↔resource 분리.)
- **D2 — 엔드포인트·인증**: `GET /api/collections/summary` 하나. 인증 필수이며 `SecurityConfig`의 기존 `anyRequest().authenticated()`로 커버 → **SecurityConfig 무변경**.
- **D3 — 응답 필드**: `totalGridCount`(Integer)·`totalVideoCount`(Long)·`visitedRegionCount`(Integer) 3필드만. streak/badge 필드는 **응답 스키마에서 제외**(Phase 2, 필드 자체를 넣지 않는다).
- **D4 — 집계 방식**: **단일 네이티브 쿼리(스칼라 서브쿼리 3개) 1왕복.** `UserGridRepository extends JpaRepository<UserGrid, UserGridId>`(grid.entity.UserGrid 재사용 — infrastructure.md·MSG-78 D6). `videos`는 같은 Owner B 도메인이라 네이티브로 직접 집계(계약 경계 아님). `GridQueryService`를 경유하지 않는다.
- **D5 — totalVideoCount**: `COALESCE(SUM(user_grids.video_count), 0)`. 삭제 시 `video_count` 감소로 이미 활성 영상만 반영. 점령 0건이면 0.
- **D6 — visitedRegionCount**: `COUNT(DISTINCT videos.region_code) WHERE status <> 'DELETED'`. NULL은 COUNT DISTINCT가 자동 제외(regions 미시딩 무관). 삭제 영상 제외로 totalVideoCount 의미와 정합, `BLINDED`는 방문으로 포함. (티켓 원문의 `COUNT(DISTINCT region_code)`에 status 필터를 더한 형태 — 소프트 삭제 모델과의 일관성을 위한 확정.)
- **D7 — 뷰/DTO 분리**: 서비스는 내부 뷰 `CollectionSummaryView`를 반환, 컨트롤러가 `CollectionSummaryResponseDto.from(view)`로 변환(GridQueryService 패턴 대칭). 요청 DTO 없음(GET).
- **D8 — 에러 코드 없음**: 도메인 실패 케이스가 없어 `UserGridErrorCode`·`usergrid/exception` 미생성.
- **D9 — 마이그레이션 없음**: 필요한 컬럼이 `V1__init.sql`에 전부 존재. `V{N}__*.sql` 추가하지 않는다.
- **D10 — 계약 최소 구현**: `UserGridQueryService`는 152 메서드 `getCollectionSummary(userId)`만 선언·구현. 155 소비 예정 프리미티브(`countCollectedGridsInRegion` 등)는 본 문서에 시그니처만 명세하고 **인터페이스에 넣지 않는다** — 인터페이스 메서드 추가는 non-breaking이므로 소비처(155)에서 추가.
