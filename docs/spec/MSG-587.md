**Owner**: 공통 (`global/config` · 설정)

> 요구사항 변경 없음 — 설정 변경이라 PRD 면제 (CLAUDE.md 면제 기준 "요구사항 불변"). 다만 런타임 동작이
> 바뀌므로 스펙은 남긴다. 발단은 `docs/audit/2026-09-08-backend-audit.md` §3.4 osiv(O1, P2)와
> 2026-09-07 박원형 멘토링. 지라: MSG-587.

## 개요

`spring.jpa.open-in-view`를 `false`로 명시한다. 지금까지 미설정이라 스프링 기본값 `true`로 켜져 있었고,
`application.yml:15`에 `open-in-view: false`가 주석 처리된 채 2026-07-01 초기 설정 커밋(`7895f2db`, MSG-55)부터
그대로였다. **켜 둔 이유도 끄려다 만 이유도 문서에 없다** — 스펙·PRD·컨벤션·LLM-WIKI 전수 검색 결과 0건이다.

OSIV가 켜져 있으면 요청이 끝날 때까지 영속성 컨텍스트가 열려 있어 컨트롤러·응답 직렬화 시점에도 지연 로딩이
된다. 편해 보이지만 그 편의에 기대는 코드가 생기면 화면을 그리는 도중에 쿼리가 나가고, 어디서 몇 번 나가는지
추적이 끊긴다. 끄면 지연 로딩은 트랜잭션 안에서만 되고, 밖에서 건드리면 `LazyInitializationException`으로 즉시
드러난다.

코드는 안 고친다. 감사에서 "끄기 전 수정 목록이 비어 있다"가 이미 확인됐다(O2).

### D-4. 왜 로그 경고로는 부족한가 (2026-09-10 실측)

감사는 적용 증명을 스프링 기동 경고(`spring.jpa.open-in-view is enabled by default`)의 유무로 했는데,
이 브랜치에서 재현되지 않았다. 세 상태로 같은 테스트 클래스(`EventLocationControllerTest`)를 돌린 결과:

| 설정 상태 | 경고 건수 |
|---|---|
| `open-in-view: false` (이번 변경) | 0 |
| `SPRING_JPA_OPEN_IN_VIEW=true` (명시적으로 켬) | 0 |
| 설정 줄 주석 처리 (변경 전 원래 상태) | 0 |

경고가 셋 다 0이라 **경고의 부재는 아무것도 증명하지 않는다.** 게다가 이 경고는 설계상
"값을 명시하지 않았을 때"만 뜬다(문구 자체가 `Explicitly configure ... to disable this warning`이다) —
누군가 `true`로 바꿔 켜면 경고 없이 켜진다. 완료 기준의 "기동 로그에서 경고가 사라진 것 확인"은
성립하지 않는 조건이었다.

그래서 값을 직접 읽는 가드 테스트를 뒀다. 단언 둘이다:

1. `Environment.getProperty("spring.jpa.open-in-view")`가 `"false"`
2. `OpenEntityManagerInViewInterceptor` 빈이 컨텍스트에 없다

둘째가 필요한 이유는 프로퍼티가 값일 뿐이기 때문이다. 요청 동안 영속성 컨텍스트를 실제로 붙들어 두는 주체는
저 인터셉터이고, 다른 설정이 인터셉터를 따로 등록하면 프로퍼티만 보는 단언은 통과해 버린다.

## 왜 안전한가 (감사 §3.4 + 이번 재확인)

- 연관관계를 가진 엔티티의 지연 로딩 접근 **29곳이 전부 `@Transactional`·`TransactionTemplate` 안**이다.
  트랜잭션 밖 접근 0건 (감사 O2, 파일:줄 전수 목록 있음)
- 컨트롤러가 엔티티를 반환하는 곳이 없다. `@RestController` 전수에서 엔티티 import는 enum 3건뿐
- 나머지 도메인(video·usergrid·friend·badge…)은 연관관계 없이 id만 보관해 영향 자체가 없다 (감사 O3)
- **감사 이후 늘어난 연관 2개도 확인했다.** MSG-585가 `Grid.region`·`UserGrid.grid`를 추가했지만

  (2026-09-10 grep)

### 2026-09-10 구현 (강정민 · Claude)

**데이터 저장 위치**: 변경 없음. 설정 한 줄이고 마이그레이션·DDL 없음.

**실행 쿼리**: 변경 없음. OSIV는 영속성 컨텍스트의 생존 구간만 바꾸고 쿼리 자체를 바꾸지 않는다.
트랜잭션 안에서 나가던 쿼리는 그대로 나간다.

**빈 동작 (이 티켓의 실체)**: `spring.jpa.open-in-view`가 `true`이면 스프링 부트가
`OpenEntityManagerInViewInterceptor`를 등록해 요청 시작부터 응답 완료까지 `EntityManager`를 붙들어 둔다.
`false`로 두면 그 빈이 아예 등록되지 않는다 — 가드 테스트 두 번째 단언이 이 사실을 잠근다. 실측으로
`SPRING_JPA_OPEN_IN_VIEW=true` 상태에서 인터셉터 단언이 실패하는 것을 확인했다. 커넥션 반납 시점은
종전과 같다(트랜잭션 종료 시) — OSIV는 컨텍스트를 붙들 뿐 커넥션을 붙들지 않으므로 이 변경으로
커넥션 점유가 달라지지 않는다 (감사 O3).

**예외 흐름**: 새 예외 코드 없음. 다만 앞으로 트랜잭션 밖에서 지연 로딩을 건드리면
`LazyInitializationException`(스프링 예외, `ApiException` 아님)이 나고 `GlobalExceptionHandler`의
포괄 `Exception` 분기가 `INTERNAL_SERVER_ERROR`로 변환한다. 현재 그런 경로는 0건이다.

**전체 테스트**: `./gradlew cleanTest test` — 517클래스 3,063건 통과, 실패 0·오류 0·스킵 5, 2분 10초.
