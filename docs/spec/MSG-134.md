## 왜 이 스파이크인가

지도 뷰포트 조회(`GET /api/grids?bbox&strategy`)는 **메인 화면 최고 트래픽**이다. 본격 구현
(MSG-90, MSG-89) 전에 (1) 실시간 전송방식과 (2) 부하 임계점을 서비스 성격에 맞게 못박는다.

## 결정 (DECIDED)

| # | 결정 | 한 줄 근거 (상세는 Confluence) |
|---|------|------|
| D1 | 전송 = **polling (fetch-on-pan)** | 개인 도감 뷰포트는 **내가 업로드할 때만** 바뀜 → 서버 push 불필요. 팬 하면 fetch |
| D2 | websocket = **Phase 2 유예** | 서버가 먼저 밀어야 하는 친구/전체 실시간·핫구역용. 연결당 메모리·FD·pub-sub 부담(t3.small) |
| D3 | SLO = **p95<300ms · p99<800ms · 5xx<1% · stale≤30s** | 읽기·개인·저위험 = 은행 아님. 지연 우선·에러 예산 느슨·강한 일관성 불요(캐시 공격적 가능) |
| D4 | 임계점 = **RPS 기준** (연결 수 아님) | polling이라 peak 부하에서 SLO(p95>300ms 또는 5xx>1%) 깨지는 지점 = 임계점 |

### SLO 3축 요약

| 축 | 목표 | 중요도 | 이유 |
|---|---|---|---|
| 지연 | p95<300ms / p99<800ms | 제일 중요 | 사용자가 팬 시 직접 체감. 150ms는 결제급이라 과함 |
| 가용성 | 5xx<1% | 느슨해도 됨 | 읽기라 다음 팬에 재요청 → 자가치유 |
| freshness | stale≤30s | 거의 안 중요 | 색칠 몇 초 늦어도 무해 → 캐시 TTL 30s 허용 |

## 부하 임계점: 정의와 측정

**임계점 = peak 부하에서 `p95 > 300ms` 또는 `5xx > 1%` 가 되는 무릎(knee).**

### 수요 (부하 모델)
```
peak RPS ≈ 동시 지도 사용자 U × 분당 팬·줌 A / 60
예) U=500·A=10 → 83 RPS   |   U=1000·A=20 → 333 RPS
```

### 공급 (saturation 실측)
- k6 `s4`(ramping-arrival-rate 100→1000 RPS)로 올려 무릎 탐색 = 실측 임계점.
- **t3.small에서 열린 모델**로 측정. runbook은 `monitoring/README.md` 재사용(§4 부하 실행).
- ⚠️ caveat: 로컬 벤치(전략 A ~286 RPS/40VU/p95 96ms)는 **내 맥·닫힌 모델**이라 t3.small 임계점이 아님.
  단일 인스턴스·콜드/워밍 캐시도 변수.

### 판정 + 레버
실측 임계점 ≥ peak 수요면 헤드룸 OK. 부족 시:

| 레버 | 효과 |
|---|---|
| Redis 캐시 (MSG-89) | 뷰포트 블록 반복 조회 흡수 → origin RPS를 히트율만큼 감소. with/without 비교로 수치화 |
| 좌표 스냅 | bbox를 격자 블록 단위 반올림 → 캐시 키 정규화 → 히트율↑ |
| 클라 디바운스 | 팬 멈춘 뒤 1회 요청 → 요청 수 감소 |
| 전략 A (채택됨) | 정수 범위 스캔이 GiST보다 빠름(부하테스트 p95 ~2.6×) |

## 아키텍처 함의

- **무상태 요청-응답** — 수평 확장·CDN/캐시 친화적.
- **캐시 TTL 30s 허용** — freshness 느슨 → 공격적 캐싱 가능(MSG-89).
- **"내 업로드 즉시 반영"은 FE 낙관적 색칠**로 처리 — 지도 캐시 stale이 UX를 안 해침.

### 줌 레벨(level) 파라미터는 MVP에 안 둔다

- **bbox가 이미 줌을 담는다** — viewport bbox는 줌 인/아웃에 따라 커지고 작아지므로 서버는 범위만 알면 됨.
- **폭주 방어 존재** — `MAX_VIEWPORT_SPAN_DEG=0.5`(약 55km) 초과 시 400 (MSG-73).
- **줌 아웃 → 셀 폭발** 대응: MVP는 span 상한 + **cursor 페이지네이션(MSG-90)**.
  낮은 줌에서 셀 개별 대신 **집계/클러스터링 응답**(이때 level/집계 단위 파라미터 도입)은 Phase 2 숙제.
