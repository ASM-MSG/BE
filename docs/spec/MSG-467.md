# MSG-467: 비로그인에서 행정동 조회 허용 (역지오코딩, 시군구 목록)

**Owner**: A

Owner 판정 근거: 실질 변경 대상이 `com.msg.fillmap.region` 열람 경로의 인가 정책이고, region 패키지는
CLAUDE.md 협업 원칙에서 Owner A(지도 인프라)다. 같은 성격의 선행 스펙 MSG-454가 Owner B였던 것은
그 티켓의 축이 미션(Owner B)이었기 때문이다. 이번 티켓은 미션·핫구역 코드를 한 줄도 건드리지 않는다.

**선행 정본**: `docs/prd/mission-map-explore.md` 8절 2026-08-24 확정 (사용자, MSG-467).
비로그인 개방을 화면이 쓰는 행정동 조회까지 넓히는 결정과 stats 계열 로그인 유지, 스크래핑 우려의
수용 논리(2026-08-22 확정 준용)가 그 PRD에 등재돼 있다.

## 개요

비로그인 사용자가 지도 홈에서 팝업스토어·지역축제 칩을 열면 미션 목록은 나오는데(MSG-454 개방)
좌측 패널의 위치줄과 지역 필터가 쓰는 행정동 조회 2종만 401로 실패한다. 원인은 MSG-454의 개방
범위에 region 경로가 없어 `SecurityConfig`의 `anyRequest().authenticated()`로 떨어지기 때문이다.
이 티켓은 좌표 역지오코딩[^1]과 시군구 목록 2종을 비로그인에 열고, 사용자별 값인 수집률 조회
4종(stats 계열)은 로그인 필수로 지킨다. 두 대상 엔드포인트는 principal[^2]을 받지 않으므로
컨트롤러·서비스·DTO는 무수정이고, 변경은 `SecurityConfig` 매처[^3] 등록 하나다. 응답 계약 불변.

## 배경 · 목표

MSG-454(2026-08-22)가 "상단 칩은 비로그인, 업로드는 로그인" 원칙으로 핫구역 1종과 미션 조회
4종을 익명에 열었는데, 그 칩 화면이 함께 부르는 행정동 조회가 범위에 빠져 화면이 반쪽으로
동작한다. 목표는 그 잔여 401의 제거다. 이번에 열리는 값은 행정동 이름과 시군구 목록으로, 공공
행정 데이터라 PRD가 미션 정보보다도 민감성이 낮다고 정리했다. 스크래핑 우려는 2026-08-22 확정의
수용 논리를 그대로 따르고, 호출량 제한은 이번에도 도입하지 않는다(PRD 8절).

## 성공 기준

1. 비로그인(무토큰) GET 요청이 다음 2개 경로에서 200으로 성공한다.
   `/api/regions/reverse-geocode`(lat·lng 필수)와 `/api/regions/districts`(파라미터 없음)다.
   역지오코딩은 좌표가 빠지면 인가와 무관하게 400 + developCode 6400(`INVALID_COORDINATE`)이
   나가므로, 익명 200 검증은 유효 좌표를 실은 요청 기준이다.
2. 비로그인 GET이 stats 계열 4종(`/api/regions/stats`, `/stats/by-point`, `/stats/national`,
   `/stats/by-grid`)에서는 여전히 401이다.
3. 두 공개 경로의 응답 본문은 로그인 조회와 완전히 같다(둘 다 사용자 무관 값, 개인화 없음).
4. 공개 GET에 무효 토큰이 실려 오면 기존과 같이 401 + developCode 2401이다
   (permitAll[^4]은 인증 불요이지 토큰 무시가 아니다, MSG-443 D4).
5. 두 경로의 비GET 요청(예: POST)은 여전히 401이다.

## API 명세

새 endpoint는 없다. 기존 GET 2종의 인증 정책만 바뀌고 요청·응답 계약은 그대로다.

| Method | Path | 변경 전 | 변경 후 |
|---|---|---|---|
| GET | `/api/regions/reverse-geocode` | 로그인 필수 | 익명 허용 (principal 미사용, 응답 변화 없음) |
| GET | `/api/regions/districts` | 로그인 필수 | 익명 허용 (principal 미사용, 응답 변화 없음) |
| GET | `/api/regions/stats` | 로그인 필수 | **유지** (내 수집률, 사용자별 값) |
| GET | `/api/regions/stats/by-point` | 로그인 필수 | **유지** (내 수집률, 사용자별 값) |
| GET | `/api/regions/stats/national` | 로그인 필수 | **유지** (내 탐험률, 사용자별 값) |
| GET | `/api/regions/stats/by-grid` | 로그인 필수 | **유지** (내 수집률, 사용자별 값) |

### 에러 케이스 (전부 기존 동작 그대로)

- 역지오코딩 좌표 누락 또는 서비스 범위 밖: 400 + developCode 6400. 익명이어도 같다.
- 바다·국외 좌표: 404가 아니라 200 + data null (MSG-93 계약 불변).
- 익명 stats 계열: 401 (`CustomAuthenticationEntryPoint`, 공통 UNAUTHORIZED).
- 공개 GET + 무효 토큰: 401 + developCode 2401 (`JwtAuthenticationFilter`가 기존대로 검증).
- 새 developCode 없음.

## 도메인 로직

### 1. SecurityConfig 매처 구성 (변경의 전부)

MSG-454 블록(핫구역·미션) 아래에 GET 한정 requestMatchers 한 항목을 더한다. 경로는 정확히 두
개만 열거한다.

```java
// 행정동 조회(MSG-467): 위 핫구역·미션 개방(MSG-454)과 같은 "상단 칩은 비로그인" 원칙의
// 잔여분이다(정본 docs/prd/mission-map-explore.md 8절 2026-08-24). 칩 좌측 패널이 위치줄과
// 지역 필터를 이 둘로 그린다. GET 한정과 경로 열거가 계약의 일부다: /api/regions/** 로 넓히면
// 내 수집률 stats 계열 4종의 인증이 함께 풀리고, 그 넷은 principal.userId() 를 바로 부르므로
// 익명 유입 시 NPE 500 이 된다. 둘 다 사용자 무관 값이라(FR-REGION-02·15) 응답 계약은 불변.
.requestMatchers(HttpMethod.GET,
	"/api/regions/reverse-geocode",
	"/api/regions/districts").permitAll()
```

- **왜 경로 열거인가 (fail-closed)**: `/api/regions/**` 프리픽스 개방은 stats 4종을 조용히
  익명에 여는 것에 그치지 않는다. 그 넷의 컨트롤러 메서드는 `principal.userId()`를 null 가드
  없이 호출하므로(현행 `RegionController` 76·114·131·145행) 익명 요청이 들어오는 순간 401이
  아니라 NPE 500이 된다. 인가 누수와 서버 오류가 동시에 생기는 구성이라 열거가 유일한 선택이다.
  미래에 `/api/regions/*` 한 세그먼트 GET이 추가돼도 기본이 인증 쪽으로 남는다(NFR-SEC-01).
- **왜 GET 한정인가**: 지금 region에는 쓰기 매핑이 없지만, 메서드 무제한 문자열 패턴으로 열면
  미래에 같은 경로에 붙는 쓰기 API가 함께 익명에 풀린다. MSG-439·440·454가 같은 이유로 GET
  한정을 계약으로 명문화한 선례를 그대로 따른다.
- MSG-454의 제약 변수(`{missionId:[0-9]+}`) 같은 장치는 불필요하다. 두 경로 모두 경로 변수
  없는 리터럴이라 형제 경로를 잡을 여지가 없다.
- HEAD는 열지 않는다. region에 명시 HEAD 매핑이 없고 칩 요구사항도 아니다(MSG-454 동일 정책).

### 2. JwtAuthenticationFilter는 건드리지 않는다

`PUBLIC_AUTH_PATHS`에 새 경로를 넣지 않는다. MSG-443 D4 원칙 그대로다: permitAll은 인증
불요이지 토큰 무시가 아니다. 무효 토큰이 실려 오면 기존과 같이 401 + 2401이고, 유효 토큰이
실려 오면 필터가 평소처럼 principal을 세운다(두 경로는 principal을 안 쓰므로 결과는 같다).

### 3. RegionController 클래스 주석 갱신

현행 클래스 주석의 "지도 화면 뒤 조회이므로 로그인 필요(SecurityConfig anyRequest)" 문구가 이
티켓으로 낡는다. 다음 취지로 고친다: 역지오코딩과 시군구 목록은 비로그인 열람이다(MSG-467, 상단
칩은 비로그인). 수집률 stats 계열은 사용자별 값이라 로그인 필수다. 그 외 컨트롤러·서비스·DTO
코드는 무수정이고, region 패키지의 자바 로직 변경은 이 주석 한 건뿐이다.

## 테스트 시나리오

MSG-454의 `MissionPublicAccessHttpTest` 패턴(@SpringBootTest + @AutoConfigureMockMvc, 서비스는
@MockitoBean 목이라 변수는 SecurityConfig 등록뿐)을 그대로 쓴다. 신규 클래스
`src/test/java/com/msg/fillmap/region/controller/RegionPublicAccessHttpTest.java` 하나에 담고,
`RegionQueryService`와 `RegionStatsQueryService`를 목으로 세운다. MockMvc[^5] 요청으로 시큐리티
필터 체인을 실제로 태운다.

검증 주석은 전부 FR 마커로 단다. `scripts/generate-rtm.sh`가 FR-* 패턴만 인식해 NFR 마커는
말폼드 토큰으로 버려지기 때문이다(`docs/rtm.md` 하단 말폼드 목록의 NFR-OPS-06 등이 같은 사례,
RTM 생성기 확장은 이 티켓 범위 밖). NFR-SEC-01의 성질 보존이라는 의미는 시나리오 설명에 적는다.

1. `무인증으로_행정동_조회_2종이_200으로_성공한다`: 성공 기준 1의 두 경로.
   역지오코딩은 좌표 누락 400이 익명 200 검증을 가리지 않도록 유효 좌표를 싣는다
   (`/api/regions/reverse-geocode?lat=37.4979&lng=127.0276`, 파라미터명은 lon이 아니라 **lng**다).
   districts는 파라미터 없이 그대로 부른다.
   주석: `// 검증: FR-REGION-02, FR-REGION-15`
2. `무인증_수집률_조회_4종은_401로_거절된다`: stats 계열 4종 전부. 누가 매처를
   `/api/regions/**`로 넓히면 이 테스트가 깨진다(회귀 가드이자 NPE 500 방지 가드). 지키는
   기본 원칙은 NFR-SEC-01(기본이 인증 필수)이고, 마커는 이 401이 보호하는 수집률 요구 셋으로
   단다. FR-REGION-06이 목록(`/stats`), FR-REGION-07이 단건(`/stats/by-point`·`/stats/by-grid`),
   FR-REGION-14가 전국(`/stats/national`)이다.
   주석: `// 검증: FR-REGION-06, FR-REGION-07, FR-REGION-14`
3. `무인증_비GET_행정동_경로는_401로_거절된다`: POST `/api/regions/districts`가 401인지.
   GET 한정 계약의 회귀 방지(MissionPublicAccessHttpTest의 같은 성격 시나리오와 동형,
   NFR-SEC-01의 성질 보존). 마커는 개방 대상 두 요구로 단다.
   주석: `// 검증: FR-REGION-02, FR-REGION-15`
4. `공개_GET에서도_무효_토큰은_2401로_거절된다`: 결정 2(필터 무수정)의 성질 보존.
   `Authorization: Bearer not-a-real-token`으로 역지오코딩 호출, 401 + developCode 2401 단언.
   시나리오 3과 같은 이유로 개방 대상 두 요구의 마커를 단다.
   주석: `// 검증: FR-REGION-02, FR-REGION-15`
5. `무인증_역지오코딩도_좌표가_빠지면_6400이다`: 파라미터 검증이 인가 개방과 무관하게
   살아 있는지. lat만 싣고 호출해 400 + developCode 6400 단언.
   주석: `// 검증: FR-REGION-02`

기존 region 테스트는 대상 2종에 대한 401 기대가 있으면 정책 변경의 직접 귀결로 정리하고
(MSG-454 작업 로그의 같은 판단 선례), stats 계열의 로그인 동작 테스트는 무변경 green이어야 한다.

[^2]: principal: 인증 필터가 요청마다 세우는 "지금 호출한 사용자" 객체. 이 프로젝트에서는
    `AuthPrincipal`(userId 보유)이고, 비로그인 요청에서는 null이다. 이번 두 경로는 이 객체를
    아예 받지 않아 익명 개방에 코드 수정이 필요 없다.
[^3]: 매처(request matcher): SecurityConfig에서 어떤 경로·메서드에 어떤 접근 규칙을 적용할지
    정하는 단위. 등록 순서대로 검사해 먼저 맞은 규칙 하나만 적용되고, 아무 매처에도 안 잡힌
    요청은 마지막 `anyRequest()` 기본 규칙(이 프로젝트는 인증 필수)으로 떨어진다.
[^4]: permitAll: Spring Security에서 특정 경로를 인증 없이 통과시키는 접근 규칙. 인증을 요구하지
    않는다는 뜻이지 실려 온 토큰을 무시한다는 뜻이 아니다. 무효 토큰은 평소처럼 401로 거절된다.
[^5]: MockMvc: 서버를 띄우지 않고 스프링 MVC 요청·응답을 통째로 실행하는 테스트 도구. 시큐리티
    필터 체인과 JSON 직렬화까지 타므로 인증 정책 검증에 적합하다.
