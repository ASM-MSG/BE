# MSG-246: 도감 요약 visitedRegionCount 항상 0 결함 — grids.region_code 조인으로 정정

**Owner**: B (`com.msg.fillmap.usergrid.*`) — 순수 Owner B. 계약 인터페이스 시그니처 불변(§계약 변경).

> **결함 수정 티켓** (Codex 교차 리뷰 발견, 2026-07-24 MSG-222 최종 라운드 — P1). PRD 없음.
> MSG-152가 만든 도감 요약의 `visitedRegionCount`가 **모든 사용자에게 항상 0**으로 나온다.
>
> **용어(glossary)**: 이 지표는 사용자의 **방문**(videos row = 업로드 이벤트)이 남긴 서로 다른
> 행정동 수다. 도감(= 점령 격자 집합)의 크기(`totalGridCount`)와는 다른 축이다.

---

## 개요

`UserGridRepository.getCollectionSummary`의 세 번째 스칼라 서브쿼리가
`COUNT(DISTINCT region_code) FROM videos`를 세는데, **`videos.region_code`는 프로덕션에서
아무도 채우지 않는다.** 결과적으로 `GET /api/collections/summary`의 `visitedRegionCount`가
항상 0이다. `videos ⨝ grids` 조인으로 **격자 라벨(`grids.region_code`) 축**의 DISTINCT 카운트로
정정한다 — MSG-167 "라벨은 by-grid 귀속" 원칙과 정합.

## 배경 · 결함 분석 (실코드 확인 결과)

### 결함 지점

- **쿼리**: `src/main/java/com/msg/fillmap/usergrid/repository/UserGridRepository.java:31-32`
  ```sql
  (SELECT COUNT(DISTINCT region_code)::int
      FROM videos WHERE user_id = :userId AND status <> 'DELETED') AS "visitedRegionCount"
  ```
- **원인 사슬**:
  1. `Video.java:27` 주석 — "region_code 는 **별도 판정 티켓 전까지 null**". 그 판정 티켓은 발행된 적 없다.
     `Video.create(...)`(Video.java:128)는 `regionCode`를 세팅하지 않고, 다른 어떤 쓰기 경로도 없다
     (video 패키지 전수 grep — `regionCode` 쓰기 0건).
  2. 그 사이 MSG-167이 지역 라벨의 귀속처를 **`grids.region_code`(격자 중심점 ST_Covers 판정,
     lazy insert 시 1회 + V5 백필)**로 확정했다 (`VideoRepository.upsertGrid`, V5/V7 마이그레이션).
  3. MSG-152 스펙(docs/MSG-152.md §선행 상태)은 "`videos.region_code` ✅ 업로드 시 1회 판정 저장(MSG-66)"
     이라 기록했으나 **실코드와 불일치한 전제**였다 — 그 위에 쿼리·테스트가 세워졌다.
- **영향**: 모든 사용자의 `visitedRegionCount` = 0. 다른 두 지표(`totalGridCount`·`totalVideoCount`)는 정상.

### 기존 테스트가 결함을 못 잡은 이유 (티켓 검증 요구사항)

`UserGridRepositoryTest.java:187-204`의 `video(...)` 픽스처가 **`videos.region_code`를 네이티브
INSERT로 손수 채운다** — 프로덕션 쓰기 경로에는 존재하지 않는 상태를 조작해 만든 것이다.
쿼리는 그 합성 데이터에 대해선 옳게 동작하므로 7개 테스트가 전부 green이었다.
서비스·컨트롤러 테스트는 stub projection/mock(값 6 고정)이라 SQL을 아예 타지 않는다.
즉 **"프로덕션 업로드 경로가 만드는 실제 데이터 형상"으로 요약을 검증하는 테스트가 없었다.**

기존 테스트는 0을 기대하지 않으므로(티켓의 조건부 지시 해당 없음) assert 정정이 아니라
**시딩 축 자체를 by-grid로 재작성**한다. 특히 `방문_행정동_수는_videos_region_code의_distinct_개수다`
(같은 격자에 영상 3개·행정동 3개)는 by-grid 의미론에서 **불가능한 상태**라 시나리오를 재설계한다(§테스트).

## 성공 기준

1. 라벨된 격자에 영상을 올린 사용자(프로덕션 데이터 형상: `videos.region_code` NULL,
   `grids.region_code` 라벨)의 요약에서 `visitedRegionCount ≥ 1`이 나온다 —
   **수정 전 쿼리로는 0이 나와 실패하는 결함 재현 테스트**로 검증.
2. NULL 제외(라벨 없는 격자 미집계)·`DELETED` 제외·`BLINDED` 포함(MSG-152 D6)이 유지된다.
3. 계약 인터페이스(`UserGridQueryService`)·프로젝션·DTO·API 응답 스키마 **불변**. 전체 테스트 green.

## API 명세

**변경 없음.** `GET /api/collections/summary` 응답 스키마·타입·에러 동작은 MSG-152 그대로.
바뀌는 것은 `visitedRegionCount` **값의 소스 축**뿐이다 (0 고정 → 실제 방문 행정동 수).

## 도메인 로직

### 수정 쿼리 (핵심)

`UserGridRepository.getCollectionSummary`의 세 번째 서브쿼리만 교체:

```sql
(SELECT COUNT(DISTINCT g.region_code)::int
    FROM videos v
    JOIN grids g ON g.grid_id = v.grid_id
    WHERE v.user_id = :userId AND v.status <> 'DELETED') AS "visitedRegionCount"
```

SQL 수준 검토 (티켓 요구사항):

- **NULL 처리 유지**: `COUNT(DISTINCT g.region_code)`는 NULL을 자동 제외 — 라벨 없는 격자
  (해안/무귀속, `grids.region_code` NULL)의 영상은 세지 않는다. 기존 의미(NULL 자동 제외)와 동일.
- **DELETED 제외 유지**: `v.status <> 'DELETED'` 그대로. `BLINDED` 포함(D6)도 그대로 —
  status 필터는 videos 쪽에만 걸리고 조인은 필터를 바꾸지 않는다.
- **inner JOIN 안전**: `videos.grid_id`는 `NOT NULL` + `REFERENCES grids(grid_id)`(V1__init.sql:86)
  이고 업로드 시 `upsertGrid`가 먼저 실행되므로 조인에서 유실되는 영상 row가 없다. LEFT JOIN 불요.
- **구동**: `videos` user_id 필터로 몰고(기존 인덱스) → `grids` PK equi 조인. geospatial 연산 0 —
  저장 라벨 소비는 equi-join만 쓴다는 MSG-167 원칙 그대로 (`getRegionVideos`·`getCollectionGrids`와
  동일 패턴, 같은 파일에 선례 있음).

### 의미 변화 (기록)

귀속 축이 "영상 업로드 좌표(by-video)" → **"격자 중심점 행정동(by-grid)"** 으로 바뀐다.
by-video 축은 구현된 적이 없으므로(항상 NULL) 동작 회귀는 없고, 0 → 정상값으로만 바뀐다.
격자 경계에서 업로드 좌표와 격자 소속 동이 다를 수 있으나, 이는 MSG-167이 이미 도감 갤러리
regionName·동 단위 영상에 적용한 규칙과 **한 축으로 통일**되는 것이다(라벨 이원화 지양 —
대안이었던 "업로드 시 videos.region_code 채우기"는 이 이유로 기각, 티켓 확정).

> **위키 대조**: `fillmap-wiki/04-decisions/ADR 격자 행정동 라벨 grids.region_code.md`(MSG-167)와
> 정합. 단 `fillmap-wiki/03-specs/개인 도감 화면 확정 UX·API 설계.md` §2 데이터 축 표는
> "방문 지역 수 = 업로드 좌표"로 기록돼 있어 **이 수정으로 낡는다** — wrap-up에서 위키 갱신 필요 표기.
> docs/MSG-152.md의 D6·성공 기준 4(videos.region_code 축)도 본 문서가 대체한다(원문은 수정하지 않음).

**신규 (결함 재현 — 수정 전 red, 수정 후 green)**
- `프로덕션_데이터_형상에서_방문_행정동_수가_1_이상이다` — region 시드 + 라벨된 격자 점령 +
  `videos.region_code` NULL인 영상 1건 → `visitedRegionCount == 1` (기존 쿼리는 0 반환, 티켓 DoD)

**재작성 (축 교체)**
- `방문_행정동_수는_영상이_있는_격자들의_행정동_distinct_개수다` — 행정동 2곳의 격자 3개
  (동A 격자 2 + 동B 격자 1)에 영상 → 2
- `라벨_없는_격자의_영상은_방문_행정동_수에_포함되지_않는다` — 무라벨 격자(해안) 영상 → 집계 제외
- `DELETED_영상만_있는_행정동은_방문_수에_포함되지_않는다` — 동A ACTIVE + 동B DELETED만 → 1
- `BLINDED_영상의_행정동은_방문_행정동_수에_포함된다` — 동A ACTIVE + 동B BLINDED → 2 (D2)
- `다른_사용자의_점령과_영상은_집계에_포함되지_않는다` — 사용자 격리 (라벨 축으로 시딩만 교체)
- `같은_행정동의_격자_여러개여도_행정동_수는_한번만_센다` — DISTINCT (같은 동 격자 2개 → 1)

**유지 (무관 지표)**
- `점령_격자_수와_영상_총합을_집계한다` · `점령이_없는_사용자는_격자수0_영상합0을_반환한다` — 무변경
