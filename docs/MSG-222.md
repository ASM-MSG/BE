# MSG-222: 활성 미션 조회 API (GET /api/missions/active — 유형별 응답 shape, 1h 전역 캐시)

**Owner**: B (신규 `com.msg.fillmap.mission.*`, 미션 = 콘텐츠 도메인 · 담당 성민). grid/region 패키지 무수정.

> 에픽: 미션·이벤트 (지자체 축제·둘레길 코스를 격자 위에). **미션 도메인의 첫 런타임 API**다. MSG-166(V6 스키마)이
> 선반영한 `missions`·`mission_grids`·`user_missions` 위에 JPA 엔티티와 조회 경로를 처음 얹는다. 지도가 뜰 때
> "지금 진행 중인 미션 전부"를 유형별 렌더 shape(면/폴리라인/점/경계)로 한 번에 내려주는 read API 1종.
> 위키 `02-planning/설계검토 미션·이벤트 기능 추가.md` §렌더링·§API, `05-meetings/2026-07-23 기획회의 미션·이벤트
> 표시 방식.md`, `04-decisions/미션 후속 결정 코스 포토스팟 방식.md`와 대조 완료: bbox 없이 **TTL 1h 전역 캐시**,
> 기존 `GET /api/grids`(유저별·페이지네이션)와 성격 정반대라 **합치지 않음**(설계검토 확정). PATH 소스는
> `mission_grids`가 아니라 **`missions.path`(JSONB GeoJSON LineString)**, `mission_grids`는 판정용 포토스팟(스팟 마커).
> **순수 Owner B**다 — 계약 인터페이스(`GridQueryService`/`HotZoneService`/`UserGridQueryService`/
> `UserOidcCommandService`) 시그니처 변경 없음(§계약 변경). `GridEncoder`(Owner A 순수 static 유틸) 소비는
> MSG-153(usergrid) 선례가 있는 데이터 이용이지 계약 변경이 아니다 → 상대 팀 확인 불필요.

## 개요

활성 미션 목록을 유형별 렌더 shape로 반환하는 read API 1종(`GET /api/missions/active`)을 만든다. FE가 지도를
그릴 때 축제 면·코스 폴리라인·테마 점·구역 경계를 한 번의 호출로 받아 유형에 맞게 렌더한다. bbox 파라미터 없이
전역 목록을 주고 **TTL 1h 전역 캐시**로 재계산을 흡수한다.

```
[현재] V6 스키마만 존재(MSG-166) — 엔티티·API·판정 로직 전무. 미션을 조회할 수단이 없다
[MSG-222] Mission·MissionGrid 엔티티 + GET /api/missions/active → active 판정 → 유형별 shape 합성 → 1h 캐시
[이후] MSG-223 완료 판정·스탬프(videos 집계) / MSG-224·225·235 시드 적재 (본 티켓 범위 밖)
```

**per-user 필드가 하나도 없다** — 내가 몇 곳 찍었는지(완료 진행도)는 MSG-223(판정)이고, 이 응답은 미션의 정의·
표시 shape뿐이라 **모든 사용자에게 동일**하다. 그래서 전역 캐시가 성립한다(§도메인 4).

## 배경 · 목표

- **사용자/제품 관점**: 미점령 격자를 안 그리는 정책 탓에 지도 첫 진입이 비어 보인다(MSG-166 배경). 미션이
  "안내판"으로 그 화면을 채우려면, 지도가 뜰 때 지금 진행 중인 미션들을 유형별 렌더 shape로 받아야 한다.
  이 API가 그 "미션 오버레이" 계약을 채운다.
- **목표**: 미션 도메인 안에서 완결되는 활성 미션 목록 read API를 제공한다. 유형별 전략 클래스 없이
  **type → shape 매핑 + 쿼리 분기**만으로 4개 shape(BOX/PATH/CELLS/REGION)를 합성한다(설계검토 "전략 클래스
  금지" 원칙). 좌표 산출은 기존 `GridEncoder.center/bbox`를 재사용하고, 신규 마이그레이션 없이(V6가 이미 있음)
  엔티티 매핑 + read 경로 + 최소 캐시만 추가한다. 시드는 별도 티켓이라 **시드 전엔 빈 배열이 정상 응답**이다.

## 성공 기준

1. `GET /api/missions/active`가 지금 활성인 미션 전부를 `List<MissionResponseDto>`로 반환한다. 시드 전이면
   **빈 배열 + 200**(404 아님).
2. **active 판정**(§도메인 2)이 정확하다: `(start_at IS NULL OR start_at <= now) AND (end_at IS NULL OR now <= end_at)`.
   무기간(양쪽 NULL) 코스·지속 미션은 항상 활성, 기간 지난 이벤트는 제외된다.
3. 각 미션이 **type에 맞는 단일 shape**를 갖는다(§도메인 3): COURSE→PATH, AREA→REGION, EVENT→BOX, THEME→CELLS,
   CONTINUOUS→CELLS. shape는 그 유형에 필요한 좌표만 담고 나머지는 없다.
4. **PATH**: `missions.path`(GeoJSON LineString)를 **그대로**(raw JSON) 내보내고, `mission_grids`를 seq 오름차순으로
   정렬한 스팟 마커(각 격자 중심점 + gridId + seq)를 함께 담는다.
5. **BOX**: 그 미션의 `mission_grids` 격자 집합을 감싸는 **경계 사각형 폴리곤**(min/max lat·lon)을 합성한다.
   축제 9×9면은 한 큰 사각형, 단일 격자 팝업은 한 셀 사각형(≈마커)으로 자연스럽게 나온다.
6. **CELLS**: `mission_grids` 각 격자의 중심점 배열(+ gridId)을 담는다.
7. **REGION**: `missions.region_code`만 담는다(경계 지오메트리 미반환 — regions.boundary_geom은 무겁고 FE가
   region API로 별도 조회, §설계 D5).
8. **1h 전역 캐시**(§도메인 4): TTL 내 재호출은 재계산·재쿼리 없이 캐시된 스냅샷을 반환한다. 단일 인스턴스 전제.
9. 인증 필수 — 미인증은 SecurityConfig가 401. 응답은 `SuccessResponse.of(...)`로 감싸 HTTP 200 + `developCode 200`.
   **Flyway 마이그레이션 없이**(V6 존재) 전체 테스트 green.

## 설계 결정 (근거 포함)

| # | 포인트 | 결정 | 근거 |
|---|---|---|---|
| D1 | 응답 형식 | **단일 `List<MissionResponseDto>`** — 유형별 그룹 맵이 아님. 각 항목이 `type` 판별자 + 그 유형의 `shape` 하나 | FE는 미션 목록을 한 번 순회하며 `type`으로 렌더러를 스위치한다(면/폴리라인/점/경계). 그룹 맵(`{BOX:[...], PATH:[...]}`)은 유형이 5→N개로 늘 때마다 최상위 스키마가 바뀌고 빈 그룹 키가 지저분하다. 단일 리스트 + 판별자는 추가 유형에 스키마 불변이고 정렬(위치기반, §범위 밖)도 리스트에 자연스럽다. |
| D2 | shape 다형성 표현 | **`sealed interface MissionShape permits BoxShape, PathShape, CellsShape, RegionShape`** — `MissionResponseDto.shape` 필드 타입. `@JsonTypeInfo`(discriminator) **미사용** | `type` 필드가 이미 판별자라 wire에 별도 `@type`을 붙일 필요가 없다. Jackson은 런타임 concrete record의 필드를 그대로 직렬화하므로 sealed interface + `Object` 대비 서비스 조립부의 타입 안전만 얻고 설정 비용은 0. 유형별 전략 **클래스**가 아니라 유형별 **DTO record**라 설계검토의 "전략 클래스 금지"에 위배되지 않는다(로직은 서비스 단일 분기, §도메인 3). |
| D3 | 1h 전역 캐시 구현 | **수동 인메모리 홀더**(`volatile` 스냅샷 + 만료 epoch, 만료 시 재계산·swap). 단일 인스턴스 전제 명시 | 코드베이스에 Spring Cache 추상화(`@EnableCaching`)도 Caffeine도 **없다**. Redis는 auth 전용(`@Profile("!test")`). 여기에 캐시 스택(starter-cache+Caffeine 의존성·CacheManager 빈·`@Cacheable`)이나 Redis 직렬화를 새로 들이는 건 **시간당 1회·수백 행 쿼리**에 과한 인프라다(ponytail: rung 1 — 쿼리 자체가 싸서 캐시는 저위험 최적화). AI 폴러(MSG-149/150)가 이미 "단일 인스턴스 전제"라 인메모리 홀더는 프로젝트 현실과 정합. `ponytail: 전역 단일 홀더 — 만료 경계에서 소수 동시요청이 중복 재계산(idempotent read라 무해). 멀티 인스턴스로 가면 Redis(TTL 1h)로 이관.` *대안(리뷰 교체 가능): 선언적 무효화가 필요하면 `spring-boot-starter-cache` + Caffeine `expireAfterWrite(1h)` + `@Cacheable("activeMissions")`. 동작 동일, 의존성 1개·설정 클래스 1개 추가.* |
| D4 | 엔티티 vs native | **JPA 엔티티 `Mission`·`MissionGrid`(read-only 매핑) + `MissionRepository`** — region_stats식 native 아님 | MSG-166 §범위 밖이 엔티티 매핑을 **명시적으로 MSG-222에 배정**했다("JPA 엔티티(Mission·MissionGrid·UserMission) \| MSG-222"). 이건 집계(region_stats)가 아니라 **평범한 테이블 read**라, `Grid`·`Region`·`Video`가 전부 엔티티인 관용(순수 aggregate만 native)에 맞다. 조회는 2쿼리(활성 미션 → 그 미션들의 mission_grids)로 N+1 없이 Java에서 그룹핑(캐시라 빈도 극저). `user_missions`는 판정용이라 이 티켓에서 엔티티 미생성(MSG-223). |
| D5 | REGION shape 내용 | **`region_code`만 반환** — `regions.boundary_geom`(경계 지오메트리) 미반환 | 행정동 경계는 MultiPolygon으로 수백KB~MB다(Region API 노트: "별도 엔드포인트로 분리·ST_Simplify 미정"). 전역 캐시 응답에 실으면 페이로드가 폭증하고, FE는 이미 `GET /api/regions/*` 역지오코딩·경계 계약을 쓴다. 구역 미션은 `region_code`만 주면 FE가 필요 시 그 계약으로 경계를 가져온다. |
| D6 | 에러코드·빈 목록 | **신규 에러코드 없음.** 빈 목록·미시드는 200 + `[]` | 이 read API에 실패 케이스가 없다 — active 없으면 빈 배열(region/grid read의 "빈 결과 200" 관용). response-pattern("새 실패 케이스 생기면 도메인 XxxErrorCode 추가")상 케이스가 없으니 `MissionErrorCode` enum도 만들지 않는다(YAGNI). **7xxx 대역만 mission에 예약** — MSG-223(판정: 미션 없음/기간 종료 등 실패)에서 처음 채운다. |
| D7 | path JSONB passthrough | **`missions.path`를 raw JSON 텍스트로 읽어 `@JsonRawValue`로 재발행** — 파싱·재직렬화 없음 | FE는 GeoJSON을 소비하고 path는 이미 GeoJSON LineString이라 서버가 파싱할 이유가 없다. 엔티티에 `@JdbcTypeCode(SqlTypes.JSON)` String 필드로 jsonb 원문을 읽고, `PathShape.line`을 `@JsonRawValue String`으로 두면 따옴표 없이 JSON 객체로 나간다. *fallback(엔티티 JSONB 매핑이 까다로우면): native 조회에서 `SELECT path::text` — jsonb를 String으로 깔끔히 받아 동일 처리. 구현 중 택1(§테스트로 검증).* |

## API 명세

인증: 로그인 필수. `MissionController`는 principal을 **읽지 않는다**(전역 데이터). 미인증은 SecurityConfig가 401
(`.anyRequest().authenticated()`, permitAll 미추가). `GridVideoController.getGridCover`가 principal 없이 인증만
통과하는 것과 동일한 결.

### `GET /api/missions/active` — 활성 미션 목록 조회

- Request 파라미터 없음(bbox 없음 — 전역 목록).
- 성공 200 `body` = `List<MissionResponseDto>` (active 없으면 `[]`).

**`MissionResponseDto` (공통 필드 + shape)**

| 필드 | 타입 | nullable | 의미 |
|---|---|---|---|
| `missionId` | Long | N | 미션 id (`missions.id`) |
| `type` | String | N | `COURSE`/`AREA`/`EVENT`/`THEME`/`CONTINUOUS` — FE 렌더러 판별자 |
| `title` | String | N | 미션 제목 |
| `targetCount` | Integer | N | 완료에 필요한 distinct 방문 격자 수(표시·판정 힌트, 판정은 MSG-223) |
| `startAt` | LocalDateTime | Y | 시작 시각. NULL = 무기간(상시) |
| `endAt` | LocalDateTime | Y | 종료 시각. NULL = 무기간(상시) |
| `shape` | MissionShape | N | 유형별 렌더 shape 하나(아래 4종 중 `type`에 대응) |

**shape 4종 (`sealed interface MissionShape`)** — 각 record는 자기 필드만 직렬화, 판별은 상위 `type`.

- `PathShape` (COURSE) — `{ "line": <GeoJSON LineString 객체>, "spots": [ {gridId, lat, lon, seq}, ... ] }`
  - `line`: `missions.path` 원문(raw JSON, §설계 D7). `spots`: `mission_grids` seq 오름차순, 각 격자 `GridEncoder.center`.
- `BoxShape` (EVENT) — `{ "polygon": [ {lat, lon} × 5 ] }`
  - 미션의 `mission_grids` 격자 집합을 감싸는 경계 사각형(남서→남동→북동→북서→남서 닫힌 링).
- `CellsShape` (THEME · CONTINUOUS) — `{ "cells": [ {gridId, lat, lon}, ... ] }`
  - `mission_grids` 각 격자의 `GridEncoder.center`(seq 무의미).
- `RegionShape` (AREA) — `{ "regionCode": "1168051500" }`
  - `missions.region_code`만(경계 지오메트리 미반환, §설계 D5).

## 유형 → shape 매핑

`type`이 곧 shape를 결정한다(1:1). 서비스는 이 표대로 단일 분기해 shape를 합성한다(유형별 전략 클래스 아님, §설계 D2).

| type | 개념 | shape | shape 소스 | 좌표 산출 |
|---|---|---|---|---|
| `COURSE` | 코스(둘레길) | **PATH** | `missions.path`(라인) + `mission_grids`(스팟, seq순) | path 원문 passthrough · 스팟 = `GridEncoder.center` |
| `AREA` | 구역(행정동) | **REGION** | `missions.region_code` | 없음(코드만) |
| `EVENT` | 축제·팝업 | **BOX** | `mission_grids` 격자 집합 | 경계 사각형 = `GridEncoder.bbox`들의 min/max |
| `THEME` | 테마 스팟 | **CELLS** | `mission_grids` | 각 `GridEncoder.center` |
| `CONTINUOUS` | 지속(상시) | **CELLS** | `mission_grids` | 각 `GridEncoder.center` |

핵심:
- **팝업(EVENT, `mission_grids` 1행)은 BOX가 한 셀 사각형**이라 지도상 ≈마커로 보인다(7/23 회의 "팝업=마커"와 자연 정합).
- **CONTINUOUS는 THEME와 같은 CELLS로 기본 매핑**(격자 집합·특수 지오메트리 없음). 확정 필요는 §미해결 질문 1.
- BOX는 `missions`에 좌표 컬럼이 없으므로 항상 `mission_grids`에서 **합성**한다(별도 좌표 저장 없음 — 스키마 무변경).

## 도메인 로직

### 1. 조회 흐름 (read, 캐시 경유)

`MissionQueryService.getActiveMissions()`:

1. 캐시 홀더가 유효(만료 전)하면 스냅샷을 그대로 반환(재쿼리 없음, §4).
2. 만료면 재계산:
   - `missionRepository.findActive(now)` — active 판정(§2) 통과한 미션들.
   - `missionGridRepository.findByMissionIds(ids)` — 그 미션들의 `mission_grids`(grid_id·seq) 일괄 조회(N+1 회피).
   - `missionId`로 그룹핑 후 유형별 shape 합성(§3).
   - 스냅샷 + 만료시각(now + 1h)으로 캐시 swap.
3. `List<MissionResponseDto>` 반환(빈 리스트 가능).

grid/region/videos 파생 없음 — 이 API는 **미션 정의·표시**만, 완료 판정(videos 집계)은 MSG-223.

### 2. active 판정 (기간, NULL = 상시)

```sql
WHERE (start_at IS NULL OR start_at <= :now)
  AND (end_at   IS NULL OR :now <= end_at)
```

- **양쪽 NULL**(코스·지속): 항상 활성.
- **end_at만 설정**: 종료 전까지 활성. **start_at만 설정**: 시작 후 활성.
- 두 컬럼을 독립적으로 판정한다("`start_at IS NULL`이면 상시" 단일 조건이 아니라 각 경계 독립) — 미래 이벤트가
  start 전인데 노출되는 실수 차단. `now`는 서버 시각(캐시 스냅샷 계산 시점, TTL 1h라 최대 1h 지연 허용 — 미션은
  분 단위 정밀도가 불필요).

### 3. 유형별 shape 합성 (§유형→shape 매핑)

단일 서비스 메서드에서 `type` switch로 합성한다(전략 클래스 없음).

- **PATH(COURSE)**: `line` = `missions.path` 원문(raw JSON, §설계 D7). `spots` = 그 미션의 `mission_grids`를 `seq`
  오름차순 정렬 → 각 `GridEncoder.center(gridId)` → `{gridId, lat, lon, seq}`. seq NULL 스팟은 뒤로(코스는 seq 채움).
- **BOX(EVENT)**: 미션의 모든 `mission_grids`에 대해 `GridEncoder.bbox(gridId)` 코너를 모아 **전역 min lat·min lon·
  max lat·max lon** 계산 → 5점 닫힌 링(남서→남동→북동→북서→남서). 격자 집합의 경계 사각형 = "면". 1격자면 그 셀.
- **CELLS(THEME·CONTINUOUS)**: 각 `mission_grids` → `GridEncoder.center(gridId)` → `{gridId, lat, lon}` 배열.
- **REGION(AREA)**: `{ missions.region_code }`. `mission_grids` 조회 불필요(§설계 D5).

`mission_grids`가 빈 미션: PATH/BOX/CELLS는 빈 좌표(spots/cells `[]`, BOX는 폴리곤 null 또는 빈 배열 — 시드 정상성은
저자 책임, 방어적으로 빈 shape 허용). REGION은 grid 무관이라 영향 없음.

### 4. 1h 전역 캐시 (수동 홀더, 단일 인스턴스)

- `MissionQueryService`가 `volatile` 스냅샷(`List<MissionResponseDto>`)과 만료 epoch(ms)를 보유. 읽을 때 만료면
  재계산 후 swap, 아니면 스냅샷 반환.
- **전역**: 응답에 per-user 필드가 없어(§개요) 모든 사용자에게 같은 스냅샷을 공유한다 — 이게 캐시 성립 근거다.
- **단일 인스턴스 전제**: dev는 단일 프로세스(AI 폴러 MSG-149/150와 동일 전제). 멀티 인스턴스면 인스턴스별 홀더라
  최대 1h 불일치가 나므로, 그때 Redis(TTL 1h) 이관(§설계 D3, ponytail 상한 주석).
- 만료 경계 동시요청은 중복 재계산할 수 있으나 read라 무해(락 불필요).

### 5. 인증 정책 (전역 데이터, 로그인 게이트)

- `/api/missions/active`는 전역 공개 데이터지만 **인증 필수**로 둔다 — SecurityConfig `permitAll` 목록에 추가하지
  않는다. 좌표 뒤 조회는 전부 로그인 게이트인 관용(reverse-geocode·grid `/cover`도 비개인 데이터인데 인증 필수)과
  정합. SecurityConfig **무변경**(계약·보안 경계 안 건드림).

## 데이터 모델

**Flyway 마이그레이션 불필요.** `V6__mission_schema.sql`(MSG-166)이 필요한 테이블·컬럼·제약·인덱스를 전부 보유.
`missions`·`mission_grids`를 **읽기만** 한다(INSERT/UPDATE 없음 — 시드는 MSG-224/225/235).

**신규 엔티티**(read-only 매핑, §설계 D4):
- `mission/entity/Mission` — `missions` 매핑. `id`·`type`·`title`·`regionCode`·`startAt`·`endAt`·`targetCount`·`path`·
  `createdAt`. `path`는 jsonb 원문 String(`@JdbcTypeCode(SqlTypes.JSON)`, §설계 D7). `@NoArgsConstructor(PROTECTED)`.
- `mission/entity/MissionGrid` — `mission_grids` 매핑. 복합키(`mission_id`, `grid_id`) + `seq`. `@IdClass` 또는
  `@EmbeddedId`(UserGrid/UserGridId 관용 참고). grid_id는 논리 참조라 Grid 연관 매핑 없이 String으로 둔다.

**신규 리포지토리**: `mission/repository/MissionRepository`(active 조회) + `mission_grids` 조회(MissionRepository의
`@Query`로 mission_id IN 조회하거나 `MissionGridRepository` 분리 — 구현 재량). 2쿼리로 N+1 회피.

**신규 서비스**: `mission/service/MissionQueryService`(+`Impl`) — active 조회·shape 합성·캐시 홀더.

**신규 컨트롤러**: `mission/controller/MissionController` — `GET /api/missions/active`, 얇은 3-layer.

**신규 DTO**: `mission/dto/MissionResponseDto`(record) + `MissionShape` sealed interface + `PathShape`·`BoxShape`·
`CellsShape`·`RegionShape` record + `Spot`·`Cell`·`LatLng` 값 record. `@Schema`·`from(...)` 팩터리(기존 DTO 관용).

**exception 패키지**: 본 티켓 미생성(에러코드 없음, §설계 D6). MSG-223이 `MissionErrorCode`(7xxx)를 처음 만든다.

**패키지 구조**: `com.msg.fillmap.mission` 신설 — `controller`/`service`/`repository`/`entity`/`dto`
(+`exception`은 MSG-223).

## 미해결 질문

1. **CONTINUOUS 미션의 shape.** 4개 shape(BOX/PATH/CELLS/REGION)는 축제·코스·테마·구역에 명시 매핑되지만,
   5번째 유형 CONTINUOUS(지속·상시)의 렌더는 위키에 없다. 본 스펙은 **CELLS로 기본 매핑**(격자 집합·특수
   지오메트리 없음 → THEME와 동형)을 택했다. MVP 시드에 CONTINUOUS가 없다면(MSG-224/225/235 확인) 사실상
   빈 응답이라 무해하다. 기획이 CONTINUOUS를 별도 shape로 원하면 조정 필요 — 기본값은 CELLS.
2. **EVENT 하위 축제 vs 팝업 표시 구분.** 7/23 회의는 축제=면, 팝업=마커로 구분했으나 스키마·타입은 둘 다
   EVENT다. 본 스펙은 **둘 다 BOX**로 통일하고(팝업 = 1격자 BOX ≈ 마커, 자연 정합) 별도 MARKER shape를 만들지
   않았다. FE가 "격자 수 1 → 마커 렌더"로 구분할 수 있어 서버 shape 분기는 불필요하다고 판단 — 팝업에 마커
   전용 메타(아이콘·정보카드 필드)가 서버에서 필요하다고 확정되면 EVENT를 세분하거나 shape 필드를 추가한다.
   기본값은 BOX 통일.
3. **시간 기준(타임존) 규약 — Codex 3라운드 지적 수용 기록.** active 판정은 `LocalDateTime.now(clock)`
   (JVM 기본 존)을 쓴다 — Video·AiBlurPoller 등 코드베이스 전체 관용과 동일하고, dev EC2는 JVM·DB 모두
   UTC라 내부 일관. 미션만 UTC 클록으로 고정하면 시드가 앱 존으로 쓰는 순간 어긋나므로 국소 수정을 기각했다.
   **시드 적재(MSG-224/225/235)에서 start/end_at 저장 타임존 규약을 확정할 것** — 그 결정이 전역 관용을
   바꾸면 이 판정도 함께 이관한다.
