# MSG-155: region_stats 수집률 갱신 로직

**Owner**: 공동 (A 주도 `region`/`grid` + B 트리거 배선 `video`)
— 캐시 쓰기 로직·recompute는 전부 Owner A(자기 도메인 테이블만 조인). Owner B는 업로드/삭제 경로에서 `refresh` 호출 2줄만.
**`RegionStatsCommandService` 신설**이 있으므로 §계약 변경은 grid-dev·auth-dev 상호 확인 필수.

> `region_stats`(수집률 캐시 테이블)는 **채우는 주체가 없다** — 스키마(`V1__init.sql`)에만 있고 아무도 쓰지 않는다.
> `GET /api/regions/stats`(**MSG-156**, 이 티켓 밖)가 이 캐시를 읽는다. 본 티켓은 **쓰기(캐시 갱신)만** 담당한다.
>
> **PO 확정(최종)**: 수집률 분자는 **점령(`user_grids`)** 기준이고, 각 점령 격자의 행정동은 **격자 중심점**(`grids.center_geom`)으로 귀속한다.
> 이 귀속은 **저장하지 않고 recompute 시점에 `ST_Covers`로 판정**한다 — `grids.region_code` 신설·마이그레이션·backfill이 전부 없다.
> `videos.region_code`(영상 좌표 라벨, MSG-66)는 **손대지 않는다**(분자에 안 씀).
>
> **용어(glossary 단일 진실 원천)**: `region_stats.collected_count` = 사용자가 특정 행정동에서 **점령한 격자 수**(개인 도감 = `user_grids`).
> "격자의 행정동 = 격자 중심점이 속한 행정동" → 격자당 행정동 정확히 1개 → **경계 격자 이중 카운트 없음**.
>
> **형제 경계**: MSG-93(`RegionQueryService` — 소비 안 함, ST_Covers 방식만 참조) / MSG-152(`UserGridQueryService`·`visitedRegionCount` — **영상 좌표축**, 본 티켓 격자 중심축과 의미 분리) /
> MSG-154(`regions.total_grid_count` — 분모 정본) / **MSG-155(본 티켓, region_stats 쓰기)** / MSG-156(`GET /api/regions/stats` 읽기 — 스코프 밖).

## 개요

점령/롤백이 일어날 때 `region_stats(user_id, region_code)`의 `collected_count`·`total_count`·`progress_rate`·`updated_at`을
**동기·단일 문장 recompute UPSERT**로 갱신한다. 분자는 `user_grids JOIN grids`를 격자 중심점(`grids.center_geom`)으로
`ST_Covers` 판정해 행정동별로 세고, 분모(`total_count`)는 `regions.total_grid_count`(MSG-154)의 비정규화 사본이다.

```
[업로드] saveVideo → upsertUserGrid → (첫 점령이면) refresh(userId, gridId)
[삭제]   deleteVideo → deleteUserGridIfEmpty==1(롤백) → refresh(userId, gridId)
             │
             ▼  RegionStatsCommandService.refresh (Owner A, 같은 트랜잭션)
    region_stats UPSERT (grids.center_geom 은 V1__init.sql L71 NOT NULL, 이미 존재):
        region        = ST_Covers(regions.boundary_geom, grids.center_geom) — gridId로 판정
        collected     = COUNT(user_grids JOIN grids WHERE 중심점이 그 행정동)
        total_count   = regions.total_grid_count
        progress_rate = ROUND(collected*100/total, 2)
```

**스키마 변경·마이그레이션·backfill·조회 API 전부 없다.** 산출물 = 계약 인터페이스 + recompute native SQL + 트리거 배선 2곳.

## 배경 · 목표

- **사용자/제품 관점**: "강남구 25% 수집"(Figma 근거, MVP 편입)을 보여주려면 사용자×행정동별 점령 격자 수가 집계돼 있어야 하는데, 캐시 테이블에 쓰는 주체가 없어 MSG-156이 읽을 값이 없다.
- **목표**:
  1. 점령/롤백 시 `region_stats`를 **정확하게(드리프트 없이)** 갱신하는 단일 진실 원천을 세운다.
  2. 격자→행정동 귀속을 **격자 중심점**으로 확정(격자당 1개, 이중 카운트 없음)하되 **저장 없이 계산 시 판정** — 스키마를 건드리지 않는다.
  3. Owner A(캐시 쓰기 로직 전부)와 Owner B(트리거 배선)의 경계를 **신규 계약 하나**(`RegionStatsCommandService`)로만 접합한다.
  4. 갱신 시점(a 동기 / b 배치 / c lazy)과 recompute-시점 geospatial의 ADR 정합을 확정한다(§D1).

## 성공 기준 (관찰 가능)

1. **첫 점령**(신규 `user_grids` row): 그 격자 **중심점**이 속한 행정동의 `region_stats` row가 생성/갱신되고, `collected_count` = 그 사용자가 그 행정동에서 점령한 격자 수와 정확히 일치.
2. **점령 롤백**(영상 전부 삭제 → `user_grids` row 삭제): `collected_count`가 감소한다. 마지막 격자였으면 `0`으로 **UPSERT**(row 삭제 아님 — §D5).
3. **재방문·롤백 없는 삭제**: 점령 집합 불변 → `collected_count` 불변(트리거 자체가 안 돎).
4. **경계 격자 단일 귀속**: 한 격자에 서로 다른 행정동 좌표의 영상이 여럿 올라가도, 그 격자는 **중심점 행정동에만 1** 카운트된다(이중 카운트 없음).
5. **해안/무귀속 격자 제외**: 중심점이 어느 행정동에도 안 속하는 격자의 점령은 어떤 `region_stats`도 바꾸지 않는다(조인에서 자연 제외).
6. `total_count` = 그 행정동 `regions.total_grid_count`, `progress_rate` = `ROUND(collected_count * 100 / total_count, 2)`(`0`이면 `0.00`).
7. **드리프트 없음**: 같은 이벤트가 (버그로) 두 번 refresh돼도 `collected_count`가 진값과 같다(멱등).
8. **스키마 변경 없음**(마이그레이션·`grids.region_code`·`videos` 변경 없음). 계약은 `RegionStatsCommandService` **신설**만, 나머지 4종 시그니처 불변.
9. 공유 로컬 DB 미오염(§테스트 격리). 전체 테스트 green.

## 결정 (Decisions)

### D1 — 갱신 시점 = **(a) 동기 recompute UPSERT**, 트리거 = 첫 점령 / 롤백

- **결정**: 점령/롤백과 **같은 트랜잭션**에서 `region_stats`를 갱신한다. 트리거는 점령 집합이 실제로 바뀌는 두 이벤트(**첫 점령**, **점령 롤백**)뿐 — 재방문·롤백 없는 삭제는 호출 안 함. 배치(b)·lazy(c) 반려.
- **근거**:
  1. **이벤트 희소·영향 최소**: 점령/롤백은 업로드·삭제당 최대 1회, 영향 범위가 단일 `(user_id, region_code)` 행. 핫패스 아님.
  2. **ADR 정합(핵심)**: recompute-시점 `ST_Covers`는 **사용자 트리거 쓰기 경로에서 1회** 도는 geospatial이다. ADR이 금한 것은 *조회/실시간 핫패스의 루프 geospatial*(뷰포트 렌더 등)이고, 이건 저빈도 쓰기 이벤트라 위반 아님(MSG-93 §D1과 동일 논리). v6 ADR(region-grid 비연결)도 **컬럼 연결이 아니라 계산 시 판정**이라 유지된다.
  3. **정확성**: 동기라 `updated_at` 지연 노출 없음, `@Transactional` 안이라 점령/롤백과 **원자적** 커밋.
- **배치(b)/lazy(c) 반려**: 스케줄러·TTL·동시성 복잡도를 이벤트 희소성이 정당화하지 않는다. 쓰기 시 1회 갱신이 MSG-156 읽기를 순수 SELECT로 만든다.
- **recompute(증분 아님)**: blind `+1/-1` 대신 영향 행정동의 진값을 재계산 → 드리프트·재실행 중복 원천 차단(성공 기준 7). 롤백 경로에선 `user_grids` row가 이미 삭제된 뒤 세므로 방향 무관 자동 정확.
- **비용 ceiling(명시)**: recompute의 카운트는 그 사용자가 그 행정동에서 점령한 격자마다 `ST_Covers` 1회다(그 행정동 폴리곤 대상). 사용자·행정동 스코프라 작지만 격자 중심 판정을 저장하지 않는 대가다. `ponytail: 저장 없는 계산-시 판정, 한 사용자의 한 행정동 점령 격자가 수백을 넘고 점령 이벤트가 잦아지면 그때 grids.region_code(구 안)로 캐시.`

### D2 — 분자 = **점령(`user_grids`)** 기준, 귀속 = **격자 중심점**(`grids.center_geom`, 계산 시 판정)

- **결정**: `collected_count` = `user_grids`(점령)를 `grids.center_geom`의 `ST_Covers` 판정으로 행정동별로 센 값. `videos`·`videos.region_code`는 분자에 쓰지 않는다.
- **근거**: PO 확정("격자의 행정동 = 중심점"). 점령은 격자 단위(`user_grids` 1 row = 1 격자)라 격자당 행정동 1개면 **경계 격자 이중 카운트가 원천 소멸**한다. 중심점 판정을 저장(=`grids.region_code`)하지 않고 recompute 때 `ST_Covers`로 구해 스키마를 안 건드린다(`grids.center_geom`은 V1에 이미 NOT NULL로 존재).
- **경계 격자**: 좌표가 서로 다른 행정동에 걸친 영상이 한 격자에 여럿 올라가도, 분자는 `videos`가 아니라 `user_grids`(격자)를 세고 귀속은 중심점 1개라 **정확히 1 카운트**(성공 기준 4).
- **해안/무귀속 격자**: 중심점을 덮는 행정동이 없으면 `ST_Covers` 조인이 row를 안 만들어 `region_stats` 무변경(성공 기준 5).

### D3 — refresh 시그니처 = **`refresh(long userId, String gridId)`**

- **결정**: 계약 메서드는 `region`이 아니라 **`gridId`**를 받는다.
- **근거**: 행정동 판정(`gridId`→`grids.center_geom`→`ST_Covers`)이 **recompute SQL 안에서** 이뤄지므로 **호출자(Owner B)는 region_code를 알 필요가 없다**. 첫 점령·롤백 훅 모두 `gridId`를 이미 안다(업로드는 `GridEncoder.encode` 결과, 삭제는 `deletedVideo.getGridId()`). Owner B에 geospatial·region 지식을 흘리지 않아 경계가 깨끗하다.
- 무귀속(해안) `gridId`면 recompute가 자연 no-op(§D2). 호출자 측 조건 분기 불필요.

### D4 — total_count 정본 = **`regions.total_grid_count`**, `region_stats.total_count`는 **비정규화 사본**

- **결정**: 분모 정본 = `regions.total_grid_count`(MSG-154). `region_stats.total_count`는 refresh 때 복사, `progress_rate` = `ROUND(collected_count * 100.0 / NULLIF(total_count,0), 2)`(`0`이면 `0.00`)를 **쓰기 시 물질화**.
- **근거**: `total_count`·`progress_rate`가 스키마상 `NOT NULL` 물질화 컬럼이라 안 채우면 거짓 캐시. `total_grid_count`는 정적 시드라 사본이 실질 드리프트 없음. MSG-156은 순수 SELECT.
- **드리프트 한계**: `regions` 재시딩 시 기존 사본은 그 행정동 다음 이벤트까지 낡음 — 정적 시드라 MVP 허용.
- **`progress_rate > 100` 가능성**: `total_grid_count` 면적 근사(MSG-154 D1) 때문에 100 초과 가능(`DECIMAL(5,2)` 오버플로 없음). 155는 **원값 저장**, 표시 clamp는 156(§미해결 Q1).

### D5 — 롤백/마지막 격자 이탈 시 = **`collected_count = 0`으로 UPSERT 유지** (DELETE 아님)

- **결정**: 행정동의 마지막 점령이 롤백돼 count가 0이 되어도 row를 **삭제하지 않고 0으로 UPSERT**.
- **근거**: (1) `updated_at` 이력 보존, (2) recompute 경로 단일화(모든 이벤트가 같은 UPSERT 한 문장 — 0 특례 분기 없음). MSG-156이 no-row도 0%로 폴백하므로 0-row와 no-row는 동치.

### D6 — Owner 경계·계약 = **공동(A 주도)**, recompute는 **Owner A 테이블만 조인**

- **결정**: recompute SQL은 `user_grids`·`grids`·`regions`를 조인하는데 **셋 다 Owner A 자산**이다(`user_grids` 엔티티 = `grid.entity.UserGrid`, MSG-78 D6·MSG-152 D4). 따라서 recompute는 Owner A의 `RegionRepository` native 쿼리로 **자기완결**하며 **크로스 도메인 테이블 접근이 없다**.
- **`UserGridQueryService.countCollectedGridsInRegion`(B 제공) 반려**: A가 자기 테이블만으로 계산하므로 B의 count 프리미티브가 불필요. MSG-152 §D10 예고분은 **계속 불구현**.
- **Owner 분담**:

## 도메인 로직

### `RegionStatsCommandService.refresh(userId, gridId)` (Owner A, 동기·멱등)

호출 시점(Owner B): (1) `saveVideo`에서 `!alreadyOccupied`(첫 점령), (2) `deleteVideo`에서 `deleteUserGridIfEmpty(...) == 1`(롤백). 둘 다 각 서비스 `@Transactional` 안 → 같은 트랜잭션.

**recompute UPSERT** — `RegionRepository`(native, region_stats 대상):
```sql
INSERT INTO region_stats (user_id, region_code, collected_count, total_count, progress_rate, updated_at)
SELECT
    :userId,
    tr.region_code,
    cnt.collected,
    r.total_grid_count,
    COALESCE(ROUND(cnt.collected * 100.0 / NULLIF(r.total_grid_count, 0), 2), 0.00),
    now()
FROM grids g
JOIN LATERAL (                                   -- 트리거 격자의 중심 행정동 1개
    SELECT r0.region_code, r0.boundary_geom
    FROM regions r0
    WHERE ST_Covers(r0.boundary_geom, g.center_geom)
    LIMIT 1
) tr ON TRUE
JOIN regions r ON r.region_code = tr.region_code
JOIN LATERAL (                                   -- 그 사용자가 그 행정동에서 점령한 격자 수
    SELECT COUNT(*) AS collected
    FROM user_grids ug
    JOIN grids g2 ON g2.grid_id = ug.grid_id
    WHERE ug.user_id = :userId AND ST_Covers(tr.boundary_geom, g2.center_geom)
) cnt ON TRUE
WHERE g.grid_id = :gridId
ON CONFLICT (user_id, region_code) DO UPDATE SET
    collected_count = EXCLUDED.collected_count,
    total_count     = EXCLUDED.total_count,
    progress_rate   = EXCLUDED.progress_rate,
    updated_at      = now()
```
- **트리거 격자의 행정동**은 `LATERAL … LIMIT 1`로 단일화(행정동 경계는 상호 배타 — 경계선 극소수 다중매칭 방지, MSG-93 동일). 중심점을 덮는 행정동이 없으면(해안) `tr`가 비어 SELECT가 통째로 empty → `region_stats` 무변경(§D2 자연 제외).
- **분자**는 그 사용자의 점령 격자 중 **중심점이 `tr` 행정동에 속하는 것**을 센다. 롤백 경로에선 대상 `user_grids` row가 이미 삭제된 뒤라 카운트가 자동으로 줄고, 마지막이면 0 → 0으로 UPSERT(§D5).
- `grids`·`regions` 모두 GEOGRAPHY라 `ST_Covers`가 `idx_regions_boundary`(GIST) 사용. LATERAL은 참조 형태 — 상관 서브쿼리 등 동치 형태는 구현자가 확정.

### 멘토 ADR 정합 (명시)

- recompute-시점 `ST_Covers`는 **점령/롤백 트리거의 쓰기 경로 1회** — 조회/실시간 핫패스 geospatial 금지 규칙과 무관(§D1). 조회(MSG-156)는 순수 SELECT라 geospatial 0.
- v6 ADR(region-grid 비연결) 유지 — 격자와 행정동을 **컬럼으로 잇지 않고** 필요 순간 중심점으로 계산한다.

- **Flyway 마이그레이션 없음. 스키마 변경 전무.** `region_stats`·`grids.center_geom`·`regions.total_grid_count`가 `V1__init.sql`·MSG-154에 이미 존재. `grids.region_code` 신설 안 함, `videos` 무변경.

## 테스트 시나리오 (JUnit5 + AssertJ · 한국어 백틱 메서드명 · 모듈 단위)

> **테스트 격리(MEMORY 'shared local DB' · MSG-154/93 §격리 원칙)**: DB 테스트는 **합성 fixture**
> (자기 유저 신규 생성 + 합성 `region_code = "TESTDONG01"` + 알려진 소형 폴리곤, 그 폴리곤 안/밖에 **중심점**이 오도록 잡은 합성 `grids`(center_geom 지정) + `user_grids`) + `@Transactional` 롤백만 쓴다.

> 시드는 `GridFixtures`(MSG 기존)·합성 region `ON CONFLICT DO NOTHING` 재사용.

### 모듈 1 — recompute UPSERT (`RegionRepository` native, DB 통합 · 합성 fixture)
- `점령한_격자의_중심점_행정동에_region_stats가_생성되고_collected_count가_1이다`
- `같은_행정동에_격자를_더_점령하면_collected_count가_점령격자수와_일치한다`

- `같은_이벤트를_두번_refresh해도_collected_count가_진값과_같다` (멱등)
- `다른_사용자의_점령은_내_collected_count에_섞이지_않는다` (사용자 격리)

## 미해결 질문 (Open Questions)

1. **`progress_rate > 100%` 표시 처리** — 근사 분모(MSG-154 D1) 때문에 100 초과 가능. 155는 원값 저장. 표시용 `LEAST(x, 100)` clamp를 **MSG-156**에서 할지 리뷰 확정(권고: 156 표시단 clamp, 155는 raw).
2. **`visitedRegionCount` vs 수집률의 노출 문구** — `visitedRegionCount`(MSG-152)는 **영상 좌표축**(방문 = 영상 이벤트 위치), 수집률 `collected_count`는 **격자 중심축**(수집 = 격자 귀속)이다. 의미상 자연스러운 분리지만, 두 지표를 한 화면에 보일 때 사용자 혼선이 없게 **노출 문구 정리는 MSG-156** 결정. 155는 격자 중심축으로 확정.

> **개정으로 소멸(정합 기록)**:
> - v6 ADR 되돌림 없음 — 컬럼 연결이 아니라 **계산 시 중심점 판정**이라 region-grid 비연결 ADR 정합.
> - `videos.region_code` 라벨러 의존 없음 — 분자가 `user_grids`+격자 중심이라 그 컬럼과 무관(라벨 배선 상태와 무관하게 동작).
> - 마이그레이션·backfill·재라벨 없음 — 저장 없는 계산-시 판정으로 해소.
> - 롤백 0-row vs DELETE — **0 UPSERT 유지**로 확정(§D5).
