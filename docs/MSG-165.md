# MSG-165 — region_stats recompute 동시성 회귀 테스트

**배경**: 같은 사용자가 같은 행정동의 서로 다른 격자를 거의 동시에 첫 점령하면, 두 recompute 가 서로의
미커밋 `user_grids` 를 못 봐 각자 낮은 값을 써 `collected_count` 가 lost update 되는 문제.

## 스코프 축소 (지라 "수정안 1~3"은 낡음)

수정안의 변형이 **MSG-155 에서 이미 구현·merge**됐다 — 프로덕션 코드는 손대지 않는다.
- `RegionRepository.acquireUserRegionStatsLock`: `pg_advisory_xact_lock(hashtextextended('region_stats:'||userId, 0))`.
- `RegionStatsCommandServiceImpl.refresh`: `@Transactional`(REQUIRED)로 호출자 점령 트랜잭션에 참여, 락 선취 후
  `refreshRegionStats` recompute 위임, 트랜잭션 종료 시 락 자동 해제.
- **per-user 락 선택 근거**: 경합은 "같은 사용자의 동시 점령/롤백"에서만 난다. 전역 락은 서로 다른 사용자까지
  불필요하게 직렬화하므로, 키를 사용자 단위로 좁혀 처리량을 지킨다. 락 대기 후 recompute 문장은 새 READ COMMITTED
  스냅샷으로 커밋된 진값을 센다.

따라서 남은 스코프 = **회귀 테스트 1건**. 테스트 실패 = 실제 회귀 → 고치지 말고 보고.

## 테스트 시나리오

`RegionStatsConcurrencyTest` — 두 스레드가 각자 TransactionTemplate 안에서 (자기 `user_grids` 점령 삽입 →
`RegionStatsCommandService.refresh`) 후 커밋. **반드시 락 있는 커맨드 경로**로 refresh(리포지토리 직접 호출은
락 우회). 배리어는 두 삽입 완료 직후·refresh 직전(두 미커밋 점령 공존 정렬). 최종 `collected_count = 2` 단언.

**회귀 재현(teeth) — 결정적 대기 프로토콜**: 배리어만으로는 부족하다. 로컬 PostGIS 가 빨라 먼저 진입한
트랜잭션이 상대 SELECT 전에 통째로 커밋해 락 없이도 늘 2 다(고정 sleep 없는 원안 실측 5/5 통과). 초안은 refresh 뒤
`HOLD_MS=500ms` 고정 지연을 뒀으나 **부하 심한 호스트에서 한 워커가 500ms 이상 디스케줄되면 확률적으로 통과**
(Codex P1). 그래서 고정 sleep 을 제거하고 **실제 락 경합을 관측하는 대기**로 교체했다:

각 워커는 refresh 리턴 직후 done 플래그를 set 하고, 커밋 전에 제3의 커넥션(JdbcTemplate, 트랜잭션 밖)으로 20ms
간격 폴링(전체 15s)한다 — 종료 조건은 (a) **내 백엔드 pid 가 다른 세션을 막고 있음**(`pg_blocking_pids` 를 내 pid
로 스코프 → 다른 트랙 오탐 없음) 또는 (b) **상대 워커의 done 플래그 set**. 홀더는 대기자가 자기 락을 물고 블록된
뒤에야 커밋하므로 대기자 SELECT 는 홀더 커밋 후(새 스냅샷) 실행돼 스케줄링과 무관하게 결정적으로 2 를 센다.
락이 깨지면 대기자가 advisory 가 아닌 **region_stats PK 충돌**에 블록되는데(원안의 advisory-키-전용 판정은 이때
(b) 도 안 떠 타임아웃했다), pid 기반 판정은 이 행 대기까지 "내 pid 가 막음"으로 통일해 잡아 홀더가 커밋 →
대기자가 자기 SELECT(=1)로 덮어써 최종 1 이 **결정적으로** 재현된다. 폴링 타임아웃 시엔 조용히 커밋하지 않고
진단과 함께 실패시킨다(모호 상태 은폐 금지). 실측: 락 우회 프로브 3/3 결정적 `expected 2 but was 1`, 실경로 2/2 green.
검증됨: 폴링 15s < `lock_timeout` 20s < join 30s.

## 공유 로컬 DB 격리

- `region_code` **99920 대역**(153 트랙 9993x·9994x 와 분리), 유저 이메일/닉네임 `m165` 접두, 좌표 서해 공해상.
- 커밋이 실제 발생 → `@AfterEach` 에서 자기 행만 FK 역순 대상 지정 삭제(TRUNCATE 금지, 실데이터 3,558건 불가침).
- **워커 생명주기(Codex P2)**: 워커 트랜잭션에 `SET LOCAL lock_timeout='20s'`(join 30s 보다 짧게)로 DB 대기를
  자체 종료시키고, join(`Future.get`) 실패 시 `ExecutorService.shutdownNow` + 종료 대기(bounded) 후에만
  teardown 이 돌게 try/finally 로 감쌌다 — 살아있는 워커 트랜잭션이 정리와 락 경합하거나 합성 행을 누수시키지 않게.
- 실행: `./gradlew test --tests '*RegionStatsConcurrencyTest'` (풀 스위트 금지).
