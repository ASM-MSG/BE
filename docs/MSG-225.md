## 개요

두루누비 걷기 코스 148개(`courses.json` 확정, 전부 DNWW)를 `missions`(COURSE)로 적재한다. 코스마다
① 지도 표시용 경로 = `missions.path`(GeoJSON LineString 폴리라인)와 ② 판정용 포토스팟 =
`mission_grids`(5~8곳, seq 1..N)를 **분리 저장**한다(FR-6) — path는 코스 전체 격자가 아니라 표시용
선이고, 판정은 스팟만 본다(완주 강요 방지). 무기간(start/end NULL) 상시 미션이라 과거 영상도 판정에
인정된다(FR-9).

실행 구조는 2단이다: **레포 밖 파이썬 파이프라인**(`spot_pipeline.py` 확장)이 GPX 파싱·선분 보간
(FR-7)·TourAPI 교차 스팟 선정(FR-8)을 담당해 완성 산출물 `courses-seed.json`을 만들고, **자바 시더**
(플래그 게이트 ApplicationRunner, MSG-224 미러)는 산출물 검증·적재만 한다(근거는 D2). 1회 생성 +
분기 수동 재생성 — 상시 배치 금지(FR-10). dedupe는 제목, 소유 식별은 `missions.source='DURUNUBI'`
(V13 컬럼 재사용). **DDL 신규 0 · 신규 API 0 · 계약 인터페이스 무변경.**

## 배경 · 목표

축제(MSG-224)가 한시 이벤트 축을 채웠다면, 이 티켓은 **상시 미션 재고**를 채운다 — 코스는 반영구
데이터라 지도가 비는 날이 없는 기본 콘텐츠 층이다. 두루누비 148코스 = 경로 총 ≈2,400km,
표시 경로가 통과하는 격자 ≈27,295개(실측: 남파랑길 3코스 14.7km = 166격자), 판정 스팟 ≈1,200행.

## 성공 기준

아래 "테스트 시나리오"가 이 기준의 검증 수단이다.

1. 플래그 off(기본) 기동·통합 테스트에서 러너가 아무것도 하지 않는다 — 평시 기동 무영향
   (PRD 비기능·운영)
2. 시드 실행 시 산출물의 코스가 COURSE 미션으로 적재된다 — `start_at`/`end_at` NULL(무기간, FR-9) ·
   `target_count=3`(시작안, D4) · `region_code` NULL · **`source='DURUNUBI'`** · `path`=산출물
   LineString 원문 · `mission_grids` 5~8행 seq 1..N (FR-6)
3. 같은 산출물로 재실행하면 신규 적재 0건 — 제목 dedupe 멱등 (PRD 데이터 정합, D6)
4. 시드된 path·스팟이 기존 활성 조회(MSG-222)의 PATH shape로 그대로 나온다 — line = path 원문
   passthrough(@JsonRawValue), spots = seq 오름차순 (적재 형식 ↔ 조회 계약 라운드트립)
5. 무기간 미션에 **기간 밖 과거 recorded_at 영상**이 판정에 인정된다 — 기존 판정 엔진(MSG-223)
   무수정으로 성립 (FR-9·FR-12)
6. 산출물 결함(형식 위반·유효 0건·파일 부재)은 예외로 조기 실패하고 전체 롤백 — 기존 미션 데이터
   무변경 (MSG-224 FR-5 원칙 승계)
7. 파이프라인 셀프체크: 남파랑길 3코스 통과 격자 166 재현(FR-7) · 148코스 전량 산출 · 스팟 격자가
   전부 경로 위(스냅 검증) · `.key` 비커밋
8. `./gradlew test` green

전체 수백 KB, gzip 후 수십 KB 수준으로 MVP 수용. 노출 반경·정렬 절감은 MSG-231 영역(PRD 비목표).

### D2. 실행 위치 결정 — 파이썬 파이프라인 산출, 자바는 적재만 (스펙 몫 판단)

**GPX 파싱·선분 보간·TourAPI 교차·스팟 선정은 레포 밖 파이썬 파이프라인(`spot_pipeline.py` 확장)이
담당하고, 자바 시더는 완성 산출물(`courses-seed.json`)만 검증·적재한다.** 근거:

- **1회성 + 분기 수동**(FR-10) — 앱 런타임에 넣을 이유가 없다. 축제 선례(`fetch/merge_festivals.py`
  → jsonl → 시더)와 동일 구조라 운영 절차도 대칭이다.
- **외부 API 호출** — TourAPI는 키 보안(`.key` 레포 밖 유지)·쿼터·레이트리밋 문제라 앱 기동 경로에
  두면 기동 실패 요인이 된다. 재생성마다 수천 콜(D4)이라 캐시·이어달리기도 파이프라인 몫.
- **36MB GPX** — 서버 반입·파싱 부담을 산출물(수 MB JSON 1개)로 치환한다. 시더는 결정적 입력만
  받아 테스트 가능성이 좋다(파서 순수 단위 테스트).

자바 시더가 GPX까지 파싱하는 안은 배제 — 위 세 성격 전부에 역행하고, 보간·스팟 선정 로직이 앱
코드에 들어와 1회성 작업이 상시 유지보수 대상이 된다.

### D3. FR-7 — 선분 보간과 통과 격자 (파이프라인)

GPX 인접 포인트 쌍마다 **선분을 ≤20m 간격으로 선형 보간**(양 끝점 포함)한 점렬을 만든다. 셀 최소
변이 ≈100m라 20m 간격이면 통과 셀을 사실상 전부 밟는다 — 통과 격자 집합 = 보간 점렬의 격자
집합이다(FR-7 "선분 보간" 문언 그대로).

- 검증 기준값: **남파랑길 3코스 = 166격자** 재현(티켓 실측), 전체 148코스 ≈ 27,295격자.
- 수용 한계: 20m 현보다 짧게 모서리만 스치는 셀은 놓칠 수 있다 — 소비처가 스팟 스냅 도메인(D4)뿐
  이라 영향 없음. 정확 통과 판정(supercover DDA)은 필요 근거가 생기면 교체.
- **통과 격자 집합은 DB에 저장하지 않는다** — 파이프라인 내부 산출(스팟 스냅 도메인)이다.
  `mission_grids`는 스팟 5~8행뿐(티켓 확정: "path는 코스 전체 격자가 아니라 표시용 폴리라인").

### D4. FR-8 — 스팟 자동 선정 (파이프라인, 착수분 확장)

착수분(D1) 위에 티켓 확정 절차의 미구현 단계를 채운다:

1. **500m 재샘플 → TourAPI 반경 400m POI** — 착수분 그대로 (반경 300~500m 범위 내, 12·14 타입만).
2. **최근접 코스 격자 스냅(신규)** — POI 좌표 → D3 보간 점렬의 최근접 점 → 그 점의 격자.
   POI가 코스에서 떨어져 있어도 스팟 격자는 항상 **경로 위**다 — 사용자는 코스를 걸으며 찍는데
   POI 자체 격자는 경로 밖일 수 있다(착수분 갭 해소).
3. **dedupe·간격 제약** — 구간 분할(구간당 1스팟)이 간격을 보장하고, 같은 격자는 1개만. dedupe로
   5개 미만이 되면 미충돌 기하 중간점으로 5까지 보충한다.
4. **폴백** — POI 없는 구간은 기하 중간점(시작점+끝점+균등 중간점), 착수분 그대로. 전 구간 폴백이면
   `method='geometric-fallback'`.
5. **seq** — 코스 진행거리(`nearDistM`) 오름차순 1..N. MSG-222 조회가 seq순으로 스팟 마커를 낸다.

`target_count=3` **시작안** — "스팟 N=5~8 중 3곳"(PRD 미해결 항목이 시작안 착수를 명시, 위키 결정
4항 "판정 쿼리는 하나" 그대로). 임의 확정이 아니라 기획 조정 전제다: 조정 시 `missions` UPDATE만
필요(스키마·코드 무변경), 미해결 질문에 승계 기록.

**운영 유의 — TourAPI 쿼터**: 148코스 × 평균 ~35샘플 ≈ 5천 콜. 코스별 POI 응답을 디스크 캐시
(`poi-cache/{crsIdx}.json`)해 재실행·일 쿼터 분할 이어달리기가 되게 한다(분기 재생성도 재사용).

### D5. `missions.path` 기록 형식 (스펙 몫 판단 — MSG-222 계약 대조)

**GeoJSON LineString 객체 1개**: `{"type": "LineString", "coordinates": [[lon, lat], ...]}`.

- **좌표 순서는 GeoJSON 표준 `[lon, lat]`** — 프로젝트 DTO들(lat, lon 순)과 반대이니 파이프라인·
  검증·FE 모두 주의. MSG-222가 path를 **원문 그대로**(@JsonRawValue) FE에 내보내므로 저장 형식이
  곧 와이어 형식이다 — 표준을 따라야 FE 지도 라이브러리가 그대로 먹는다.
- **좌표는 원 GPX를 Douglas–Peucker(ε=0.00015°≈15m)로 단순화 + 소수 5자리(≈1m) 반올림** —
  코스당 수백 점, 실 트레일에 붙는 매끈한 선. 통과 격자 중심 폴리라인(코스당 ≈184점)은 확대 시
  ~50m 계단 지그재그라 배제 — 크기 이득도 미미하다. ε은 산출물 검수(육안·크기)로 조정 가능.
- 대조 확인: `Mission.path`는 jsonb 원문 String 매핑(`@JdbcTypeCode(SqlTypes.JSON)`),
  `MissionShape.PathShape.line`이 raw passthrough — MSG-222 §설계 D7·`docs/MSG-222.md` §API 명세의
  `"line": { "type": "LineString", "coordinates": [[129.04,35.10],...] }` 예시와 정확히 합치.
  `chk_missions_path`(V6)는 COURSE만 path 허용 — 이 시더만 path를 쓴다.
- 시더는 산출물의 path 노드를 Jackson `JsonNode.toString()`으로 직렬화해 저장한다 — 파이프라인이
  5자리로 반올림해 두므로 재직렬화 표현 드리프트가 없다.

### D6. 산출물 형식과 적재 매핑 — `courses-seed.json`

파이프라인 최종 산출(예: `~/fillmap-data/durunubi/courses-seed.json`). 코스 148건 배열:

```json
[
 {
  "crsIdx": "T_CRS_MNG0000005118",
  "name": "남파랑길 3코스",
  "path": {"type": "LineString", "coordinates": [[129.03597, 35.09656], ...]},
  "spots": [
   {"seq": 1, "gridId": "39001_112198", "name": "국제시장 먹자골목", "method": "tourapi"},
   {"seq": 2, "gridId": "38997_112198", "name": "부산 자갈치 양곱창 골목", "method": "tourapi"}
  ]
 }
]
```

| 산출물 필드 | DB | 비고 |
|------|------|------|
| `name` | `missions.title` | dedupe 키(D6 하단). 200자 방어 절단(MSG-224 미러) |
| `path` | `missions.path` (jsonb 원문) | D5 형식 — 시더가 LineString·좌표≥2 검증 |
| `spots[].gridId` / `seq` | `mission_grids` (grid_id, seq) | 5~8행 · seq 1..N 연속 — 시더 검증 |
| (고정값) | `type='COURSE'` · `start_at`/`end_at` NULL · `target_count=3` · `region_code` NULL · `source='DURUNUBI'` | FR-9 무기간 · D4 시작안 · V13 재사용 |
| `crsIdx` | 미적재 | 산출물 추적·유니크 검증용 (missions에 컬럼 없음 — DDL 신규 금지. path 안 foreign member로 끼워넣기는 와이어 오염이라 배제) |
| `spots[].name` / `method` | 미적재 | 운영 검수용 — mission_grids·Spot DTO에 name 없음(MSG-222 계약) |

**dedupe 키 = 제목(`crsKorNm`), `source='DURUNUBI'` 한정.** 축제의 좌표+기간 키는 코스에 성립하지
않는다 — 기간이 NULL이고 단일 좌표가 없다. 제목은 노선명 접두("남파랑길 3코스")라 148개 내 유일
(파이프라인이 crsIdx·제목 유니크를 assert). 재실행 시 `findBySource('DURUNUBI')`(MSG-224 기존
메서드 재사용)의 제목 집합에 있으면 skip — INSERT-only 멱등. 타 소스(`FESTIVAL`·NULL 수동)는
대조에 넣지 않는다(MSG-224 D7 소유권 원칙과 동일 — 같은 제목의 수동 미션이 있어도 불가침·별건).

### D7. 시더 러너 — 플래그 게이트, INSERT-only (MSG-224 미러)

`CourseMissionSeeder implements ApplicationRunner` — `FestivalMissionSeeder` 구조 미러:

- **플래그**: `@Value("${fillmap.mission.course.seed.enabled:false}")` off면 early return. 산출물 경로
  `@Value("${fillmap.mission.course.seed.path:data/mission/courses-seed.json}")`. yml 무수정(기본값이
  곧 설정, 켤 때만 env/인자 override).
- **`@Order(40)`** — RegionSeeder 10 · ZoneSeeder 20 · FestivalMissionSeeder 30 이후(점유 실측 확인).
  의존은 없지만 결정적 순서.
- **`@Transactional` + 조기 실패**: 파일 부재·파싱 실패·유효 0건·검증 위반(LineString 아님·좌표<2·
  **좌표 원소가 [경도, 위도] 유한 숫자 2원소 배열이 아님**(2026-07-31 Codex 2R 파생 — path는
  @JsonRawValue 원문 passthrough라 깨진 GeoJSON이 그대로 FE에 나간다)·
  스팟 5~8 밖·seq 비연속·gridId 포맷 위반·**gridId 비정규형**(선행 0 등 — decode/재encode 왕복
  불일치는 판정 매칭 실패로 죽은 스팟이 된다)·**코스 내 gridId 중복**·crsIdx/제목 중복·
  **crsIdx/name 비문자열**(asString 관용 변환 차단 — 이상 2건은 2026-07-31 Codex 3R 파생,
  성민 판단: 수정 후 reviewer 마감)은
  `IllegalStateException` — 부분 적재 없이 전체 롤백, 기존 미션 무변경. 클럭 불요(날짜 판정 없음 —
  무기간). gridId 중복 검증은 파이프라인 계약 D4-3("같은 격자 1개")의 소비 측 방어다 — PK
  (mission_id, grid_id)라 중복 스팟은 조용히 행이 줄어 완료 불가능 미션을 만들 수 있다
  (2026-07-31 Codex 리뷰 파생).
- **정리 단계 없음** — 코스는 무기간이라 "종료 정리"(축제 D4) 자체가 없다. 두루누비에서 사라진
  코스도 삭제하지 않는다(반영구 데이터, 근거 티켓 없이 확장 금지).
- 저장은 JPA `save`/`saveAll` — 148미션 × (path 1 + 스팟 5~8행), 수동 러너라 배치 성능 무의미.

### D8. 무기간 판정 계약 — FR-9는 기존 엔진으로 성립 (코드 0줄)

`start_at`/`end_at` NULL만 기록하면 끝이다 — MSG-223 판정 SQL이 기간 조건을 `IS NULL OR` 형태로
갖고 있어(`findAwardCandidateIds`·`findCompleted`) 무기간 미션은 기간 조건이 자연 생략되고, 과거
`recorded_at` 영상(status ≠ DELETED, BLINDED 포함)이 그대로 집계된다(FR-12). 갤러리 업로드도 도감과
동일하게 인정(위키 결정). §D2 `AT TIME ZONE 'UTC'` 규칙은 기존 쿼리 소관 — 이 티켓은 쿼리 무수정.

**소급 일괄 발급은 하지 않는다**: 판정 트리거는 업로드 확정 이벤트뿐(PRD FR-11 문언·MSG-223 계약).
과거 영상만으로 이미 3스팟을 채운 사용자는 다음 스팟 격자 업로드 시점에 스탬프를 받는다 — 시드
직후 전 사용자 재판정 배치는 근거 요구사항이 없다(FR-18 부하 원칙과도 상충).

### D9. 운영 절차 — 1회 시드 + 분기 수동 재생성 (FR-10, 상시 배치 금지)

1. (분기 재생성 시) `~/fillmap-data/durunubi/`에서 코스 목록·GPX 재수집(`fetch_gpx.py`) 후 파이프라인
   전량 실행 → `courses-seed.json` 재산출. POI 캐시(D4)로 TourAPI 쿼터 내 분할 실행 가능
2. 산출물을 서버 `data/mission/courses-seed.json`으로 복사
3. `fillmap.mission.course.seed.enabled=true`로 앱 1회 기동 — 로그로 적재 n·dedupe 건너뜀 n 확인
4. **경로 개편 코스의 갱신 한계**: 제목 dedupe라 기존 미션의 path·스팟은 자동 갱신되지 않는다
   (`modifiedtime` 실측상 개편 실재). 미스탬프 미션은 수동 DELETE 후 재기동으로 재적재, 스탬프 걸린
   미션은 구버전 잔존 수용(스탬프 비회수 원칙·V6 FK NO ACTION이 하드삭제 차단). 자동 갱신이 필요해
   지면 별도 티켓 — 요구사항 신설이라 PRD부터
5. 분기 주기 관리(리마인더)는 운영 몫 — 코드에 스케줄러를 두지 않는다

조회 노출 지연은 MSG-222 캐시(1h, 인스턴스 내) 그대로 — 축제 D6과 동일 수용.
