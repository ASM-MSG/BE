# MSG-153: 개인 도감 갤러리 — 격자 목록 조회 API (`GET /api/collections/grids`)

**Owner**: 공동
— **Owner B**(usergrid): 갤러리 목록 `GET /api/collections/grids`(내 점령 격자 30개 + cover 썸네일). **Owner A**(region): 탐험률 단건 조회 `GET /api/regions/stats/by-point`(진입 초기값 = 현재 위치)·`GET /api/regions/stats/by-grid`(격자 클릭). **크로스오너 계약 인터페이스 변경 없음**(§계약 변경) — 탐험률을 region 쪽 엔드포인트로 몰아 Owner A가 자기완결하고, Owner B는 A의 자산(격자→행정동 귀속·region_stats)을 소비하지 않는다(접점 최소화). 두 도메인이 각자 자기 테이블만 읽는다.

> **개인 도감 3뷰(지도·갤러리·뱃지, Figma) 중 갤러리 뷰**다. ⚠️ **지도 뷰는 이 API가 아니다** — 지도 뷰 = 기존 `GET /api/grids`(뷰포트 색칠, MSG-73/90 구현됨) 재사용.
>
> **의존 전부 develop merge 완료 — 코드에 실존, import 가능**: `user_grids.cover_video_id`(MSG-72 재선정/87 cover)·`videos.thumbnail_url`·`idx_videos_user_created`(MSG-66) · 역지오코딩 `RegionQueryService.resolveByPoint`(MSG-93) · 수집률 캐시 `region_stats`·표시 clamp(MSG-155 write / 156 read) · 썸네일 presigned GET `presignThumbnailGet`(MSG-127) · 중심점 축 귀속 규칙 `refreshRegionStats`(MSG-155, `ORDER BY region_code LIMIT 1`).
>
> **PO 확정(2026-07-22)**: 격자 중심 UX + 현재 위치 기본값. ① 진입 = 최근 수집 격자 30개(RECENT 고정, 무커서) ② 탐험률 패널 초기값 = 현재 위치 lat/lon → 역지오코딩 → 그 행정동 내 탐험률(폴백: 권한 거부·no-match는 빈 상태) ③ 격자 클릭 = 그 격자 중심 행정동(155 D2 축)의 탐험률.
>
> **형제 경계**: MSG-152(`GET /api/collections/summary` 도감 요약 3지표 — 본 티켓과 같은 usergrid 패키지·같은 Owner B, 갤러리 목록은 여기서 추가) / MSG-93(`resolveByPoint` 재사용) / MSG-155·156(`region_stats` write/read, 탐험률 clamp 정책 재사용) / MSG-127(썸네일 presign 패턴·`GridVideoController`) / MSG-90(`OccupiedGrid` 뷰포트 목록 — 지도 축, 본 티켓은 갤러리 축).

## 개요

개인 도감 **갤러리 뷰**를 채우는 조회 API 묶음이다. 세 상호작용을 각각 엔드포인트로 낸다.

```
① 갤러리 진입   GET /api/collections/grids            (Owner B, usergrid)
                 → 내 점령 격자 최근 30개 {gridId, gridY/gridX, firstCollectedAt,
                   lastUploadedAt, videoCount, coverVideoId, coverThumbnailUrl}
                   RECENT = first_collected_at DESC, 무커서·무페이지네이션(§D3)

② 탐험률 초기값  GET /api/regions/stats/by-point?lat&lon (Owner A, region)
                 → 현재 위치 행정동 1건의 수집률 {region + 탐험률} (no-match = 200+null)

③ 격자 클릭     GET /api/regions/stats/by-grid?gridId    (Owner A, region)
                 → 그 격자 중심점이 속한 행정동 1건의 수집률 {region + 탐험률}
```

②③은 **같은 응답 DTO(`RegionStatResponseDto` 단건)**를 공유한다(§D1). 격자→행정동 귀속은 **전부 격자 중심점 축**(155/93과 동일한 `ST_Covers` + `ORDER BY region_code LIMIT 1`)으로 통일해, 목록에 붙는 라벨과 탐험률이 어긋날 여지를 없앤다(§D2). **스키마 변경·마이그레이션·신규 엔티티 없음.**

## 배경 · 목표

- **사용자/제품 관점**: 도감 화면 갤러리 탭은 "내가 수집한 장소들"을 최근 순 썸네일 격자로 보여준다. 상단 탐험률 패널은 "지금 내가 선 행정동을 얼마나 채웠나"를 즉시 띄우고, 격자를 탭하면 그 격자가 속한 행정동의 탐험률을 보여준다. 지금은 이 목록·단건 탐험률을 낼 API가 없다(요약 3지표는 MSG-152가 냈지만 격자 목록·행정동별 단건 탐험률은 없음).
- **목표**:
  1. 내 점령 격자를 **최근 수집순 30개** 목록으로 낸다(cover 썸네일 포함, MSG-127 presign 재사용).
  2. **좌표 1점·격자 1개 → 그 행정동의 탐험률**을 단건으로 낸다(진입 초기값·격자 클릭 두 입력, 한 응답 모양).
  3. 격자→행정동 귀속을 **중심점 축 하나로 통일**해 탐험률과 라벨이 어긋나지 않게 한다(⚠️ 티켓의 축 불일치 우려 해소).
  4. **접점 최소화**: 탐험률을 region 도메인 자기완결로 두어 크로스오너 계약을 새로 만들지 않는다.

## 성공 기준 (관찰 가능)

1. `GET /api/collections/grids`(인증) → 내 점령 격자를 **`first_collected_at` 내림차순 최대 30개** 리스트로 반환. 각 항목에 gridId·gridY·gridX·firstCollectedAt·lastUploadedAt·videoCount·coverVideoId·coverThumbnailUrl.
2. 점령이 31개 이상이면 **가장 최근 수집 30개만** 반환(정렬된 상위 30, 조용한 절단 아님 — §D3).
3. `cover_video_id`가 null이거나 cover 영상이 READY 이전(썸네일 key 없음)이면 **coverThumbnailUrl = null**(DoD cover null 케이스).
4. 점령 0건 사용자는 에러 없이 **200 + `[]`**.
5. `GET /api/regions/stats/by-point?lat&lon`(인증) → 현재 위치 행정동 1건의 `{regionCode, regionName, parentCode, collectedCount, totalCount, progressRate, updatedAt}`. 그 행정동에 수집이 없으면 **0%로 합성**해 반환(§D6).
6. by-point 좌표가 어떤 행정동에도 안 속하면(바다·국외) **200 + null**(93 패턴). 서비스 범위 밖 좌표는 **6400**(§D6).
7. `GET /api/regions/stats/by-grid?gridId`(인증) → 그 격자 **중심점**이 속한 행정동 1건의 수집률(DoD 격자 클릭 탐험률 포함). 귀속 규칙이 155 `refreshRegionStats`와 같아 탐험률·라벨이 일치.
8. 격자→행정동 귀속에 쓰는 geospatial은 **요청당 단건 point-in-polygon 1회**(②는 현재 위치, ③은 격자 center — 둘 다 `resolveByPoint`). 갤러리 목록(①)은 **geospatial 0**(순수 equi 조회).
9. 크로스오너 계약 4종 시그니처 불변. 스키마 변경·마이그레이션 없음. 공유 로컬 DB 미오염, 전체 테스트 green.

## 결정 (Decisions)

### D1 — 탐험률 조회 형태 = **② BE 1-call, region 쪽 엔드포인트(Owner A 자기완결)**. by-point/by-grid 두 입력·한 응답 DTO

- **결정**: 탐험률은 **BE가 한 번에** 낸다. 진입 초기값은 `GET /api/regions/stats/by-point?lat&lon`, 격자 클릭은 `GET /api/regions/stats/by-grid?gridId` — **둘 다 region 도메인 엔드포인트**이고 **같은 응답 DTO**(`RegionStatResponseDto` 단건, nullable body)를 낸다. 156 `GET /api/regions/stats`에 `regionCode` 단건 파라미터를 더하는 ①(FE 2-call)은 채택하지 않는다.
- **근거**:
  1. **격자 클릭은 ①로 안 된다.** gridId → 행정동은 **격자 중심점 축**(155)이라 FE가 재현할 수 없다(FE는 중심점 판정 규칙·`ORDER BY region_code LIMIT 1`을 모른다). ①로 억지로 하려면 FE가 gridId를 center로 디코드→`reverse-geocode`→`stats?regionCode` 3-call을 돌며 BE 전용 축 규칙을 흉내 내야 해 취약하다.
  2. **응답 모양 통일**(PO 확정): 진입(좌표 입력)·클릭(gridId 입력)이 **같은 `{region + 탐험률}`**을 받는다. BE가 두 입력을 각자 흡수하고 한 DTO로 통일하면 FE 분기가 준다.
  3. **접점 최소화**: 탐험률 소스(region_stats)·귀속(regions·중심점)은 전부 **Owner A 자산**이라 region 엔드포인트가 자기완결한다. Owner B(도감)가 A의 자산을 소비할 필요가 없어 **크로스오너 계약을 새로 안 만든다**(§계약 변경·§D5).
- **기각**: ① 2-call — 클릭 축을 FE가 못 재현(위), round trip 증가, 축 일치 보증이 FE로 샘.

### D2 — 격자→행정동 귀속 축 = **격자 중심점 축 단일화** + 목록 라벨 생략(Alt ③)

- **결정**: 이 티켓의 **모든** 격자→행정동 귀속은 **격자 중심점 축**(`resolveByPoint(center)` = `ST_Covers(boundary, center) ORDER BY region_code LIMIT 1`, 155·93과 동일)으로 통일한다. **갤러리 목록(①)에는 격자별 행정동 라벨을 넣지 않는다**(Alt ③) — 행정동은 격자 클릭(③) 때만 단건 판정한다.
- **근거**:
  1. **탐험률이 중심점 축이다(155).** 라벨을 다른 축으로 붙이면 티켓 ⚠️처럼 "라벨은 역삼1동인데 탐험률은 역삼2동에 계산"되는 불일치가 난다. 축을 중심점 하나로 통일하면 by-grid의 귀속(=`resolveByPoint(center)`)이 155 `refreshRegionStats`의 중심점 귀속과 **바이트 단위로 같은 규칙**이라 한 격자가 두 행정동에 겹치지 않는다.
  2. **목록에 중심점 라벨을 넣으면 조회 경로에 30 geospatial**이 들어가 "조회/핫패스 geospatial 금지" ADR(155/156 확립)을 정면으로 위반한다. Alt ③(목록 라벨 생략)이면 목록은 **순수 equi 조회(geospatial 0)**로 남고, 중심점 판정은 **격자 클릭 1건·현재 위치 1건**의 단건으로만 일어난다 — 93 D1이 이미 예외로 허용한 "저빈도·사용자 트리거·단건 point-in-polygon"에 정확히 해당한다.
  3. **영상 좌표 축(`videos.region_code`)은 지금 전부 NULL**(MSG-66 D4 라벨러 유예, `saveVideo` 미기입)이라 라벨 원천으로 쓸 수조차 없다 — Alt ①은 실무적으로도 죽어 있다.
- **기각**: **① 영상 좌표 축 재사용** — 전부 NULL + 탐험률과 축 불일치. **② 목록 30건 중심점 판정** — 조회 경로 30 geospatial, ADR 위반. 갤러리 셀 라벨이 정말 필요해지면 그때 별도 티켓에서 ADR 예외를 명시하고 30 판정(또는 155가 점령 시 라벨을 `user_grids`에 비정규화)으로 추가한다.
- **PO "격자 클릭 시 소속 행정동"** = ③ by-grid가 `resolveByPoint(center)`로 단건 판정 — 155·93과 같은 규칙이라 귀속 불일치 0.

### D3 — RECENT 정렬 = **`user_grids.first_collected_at DESC`**(타이브레이크 `grid_id DESC`), **30 고정·무커서**

- **결정**: 목록 정렬은 `first_collected_at DESC, grid_id DESC`, **LIMIT 30 고정**. cursor·offset 페이지네이션·"더 보기" 없음.
- **근거**:
  1. **"수집 = 점령 = 첫 업로드"**(glossary). "최근 **수집**한 격자"는 최초 점령 시각(`first_collected_at`) 기준이다 — 재방문(`last_uploaded_at` 갱신)은 새 수집이 아니므로 갤러리 순서를 흔들면 안 된다.
  2. **30은 의도된 "최근" UX**(PO 확정)이지 안전 상한이 아니다. 정렬된 상위 30이라 156 D2가 없앤 `LIMIT 1000`(무정렬 유효 데이터 조용한 절단)과 성격이 다르다 — 여기 31번째는 "최근 뷰에 없는 게 정상"이다. 전체 도감 브라우즈는 범위 밖(별도 티켓).
- **기각**: `last_uploaded_at DESC`(활동순) — "수집"이 아니라 "방문/활동" 기준이라 glossary 용어와 어긋나고, 재방문마다 갤러리가 재정렬돼 "언제 수집했나" 축이 무너진다.
- **정렬 인덱스**: `user_grids`엔 `first_collected_at` 전용 인덱스가 없다(PK `(user_id, grid_id)`만). `WHERE user_id=? ORDER BY first_collected_at DESC LIMIT 30`은 그 사용자 점령 행(사용자당 유한)만 정렬한다 — MVP엔 충분. `ponytail: 무인덱스 정렬, 한 사용자 점령 수가 커져 정렬이 실측 느리면 V4 로 idx_user_grids_user_collected(user_id, first_collected_at DESC) 추가.`

### D4 — `coverThumbnailUrl` = **presigned GET URL**(MSG-127 재사용), presign 로직 **공유 컴포넌트로 추출**

- **결정**: `coverThumbnailUrl`은 cover 영상 `thumbnail_url`(S3 key)을 MSG-127 `presignThumbnailGet`으로 발급한 **presigned GET URL**. `cover_video_id`가 null이거나 cover 영상 썸네일 key가 null(READY 이전)이면 **null**. presign 로직은 `VideoServiceImpl`의 private 메서드를 **공유 `@Component`로 추출**(예: `video/support/ThumbnailUrlPresigner`)해 video·usergrid 두 곳(둘 다 Owner B)이 쓴다.
- **근거**:
  1. **버킷 private** → key 그대로는 열람 불가, 요청 시 서명이 유일한 열람 수단(MSG-127과 동일).
  2. **30개 일괄 발급 비용 = 무시 가능**: presign은 **로컬 서명 연산(S3 호출 아님)** — MSG-127이 "항목마다 발급해도 N+1 없음"으로 이미 못박았다. 30개도 로컬 연산 30회일 뿐.
  3. **추출은 MSG-127이 예약한 트리거**: 그 티켓 ponytail 노트가 "S3 관심사 2번째 소비처가 생기면 분리"라 했고, 갤러리 목록이 정확히 2번째다. 중복 붙여넣기 대신 예약된 추출을 실행한다(둘 다 Owner B라 크로스오너 아님).
- TTL은 MSG-127 `THUMBNAIL_PRESIGN_TTL`(10분) 그대로.

### D5 — Owner = **공동, 크로스오너 계약 신설 없음**. B=목록(usergrid), A=탐험률(region)

- **결정**: 작업이 두 도메인에 걸쳐 **공동**. **Owner B**는 `user_grids`·`videos`만 native로 읽어 목록을 내고(gridY/gridX는 `GridEncoder.decode`로 산출 — `grids` 테이블 조인조차 안 함), **Owner A**는 `regions`·`region_stats`(+`GridEncoder.center` 순수 유틸)만 읽어 탐험률을 낸다. **어느 쪽도 상대 도메인 테이블/자산을 소비하지 않는다** → 크로스오너 계약 인터페이스 신설 0.
- **근거**:
  1. **자연 경계**: 목록은 도감(user_grids·videos = Owner B), 탐험률은 행정동 귀속·집계(regions·region_stats = Owner A). 각자 자기 테이블만 만진다.
  2. **접점 최소화**(§D1·D2 귀결): 탐험률을 region 엔드포인트로 몰아 B가 A를 안 부른다. `resolveByPoint`도 A 내부(RegionStatsQueryServiceImpl → RegionQueryService, 같은 region 패키지)에서만 쓰여 크로스오너 호출이 아니다.
  3. **usergrid의 `user_grids`/`videos` native read는 MSG-152가 확립한 패턴** — 신규 결합 아님. gridY/gridX를 `grids` 조인이 아니라 `GridEncoder.decode`로 뽑아 Owner A 테이블(`grids`) 접근마저 없앤다.
- **계약 표기**: `UserGridQueryService`에 **B-내부 read 메서드**(`getCollectionGrids`)가 1개 는다 — A가 소비하지 않는 비계약면 확장이라 non-breaking이지만, 규칙상 계약 인터페이스 시그니처 변화이므로 §계약 변경에 명시(A 확인은 형식적).

### D6 — 단건 탐험률 반환 = `RegionStatResponseDto`(단건, nullable body). region_stats 없으면 **0% 합성**, no-match=200+null, invalid coord=6400

- **결정**: by-point/by-grid는 **156 `RegionStatResponseDto`를 단건으로 재사용**한다(리스트 아님). 해소된 행정동에 `region_stats` 행이 있으면 그 값(표시 100 clamp — 156 D4), 없으면 `{collectedCount:0, totalCount: regions.total_grid_count, progressRate:0.00, updatedAt:null}`로 **합성**한다. 행정동 자체가 안 잡히면(바다·국외) **200 + null**(93 패턴). by-point의 서비스 범위 밖·좌표 누락은 **6400**(`resolveByPoint` 검증 재사용). **신규 에러 코드 없음.**
- **근거**:
  1. **matched-but-uncollected는 정상 0%**: 내가 선 행정동에 아직 수집이 없어도 "역삼1동 0%"는 유효한 초기값이다(null 아님). `region_stats` 행이 없을 뿐이라 LEFT JOIN + `regions.total_grid_count` 폴백으로 0%를 합성한다.
  2. **no-match만 빈 상태**: PO 폴백(권한 거부·바다·해외 = 빈 상태)은 **행정동이 없을 때**다 → 93처럼 200+null. 권한 거부는 FE가 좌표를 못 얻어 **호출 자체를 안 하는** 상태라 BE 관심 밖(FE가 빈 패널 렌더).
  3. **by-grid는 거의 항상 행이 있다**: 그 격자를 점령할 때 155가 중심점 행정동의 `region_stats`를 이미 썼고, by-grid도 같은 중심점으로 해소하므로 **구성상 같은 행정동 = 행 존재**. LEFT JOIN 합성은 방어적(155 미실행 등)일 뿐.
- **"그 격자의 정보 + 탐험률 함께 반환"**: by-grid는 `{region + 탐험률}`만 낸다 — "격자 정보"는 FE가 갤러리 목록 항목으로 이미 쥐고 있어 클라이언트에서 합성한다(재전송 불필요). `ponytail: gridId echo 도 생략, FE 가 목록 항목과 매칭. 매칭 키가 필요해지면 응답에 gridId 한 필드 추가.`

## 도메인 로직

### ① 갤러리 목록 (Owner B — `UserGridRepository` native + `UserGridQueryServiceImpl`)

```sql
SELECT
    ug.grid_id            AS "gridId",
    ug.first_collected_at AS "firstCollectedAt",
    ug.last_uploaded_at   AS "lastUploadedAt",
    ug.video_count        AS "videoCount",
    ug.cover_video_id     AS "coverVideoId",
    v.thumbnail_url       AS "coverThumbnailKey"   -- S3 key, presign 은 서비스에서
FROM user_grids ug
LEFT JOIN videos v ON v.id = ug.cover_video_id
WHERE ug.user_id = :userId
ORDER BY ug.first_collected_at DESC, ug.grid_id DESC
LIMIT 30
```
- **geospatial 0**(성공 기준 8): equi/LEFT JOIN + PK 조회뿐. `grids` 테이블도 안 만진다.
- **gridY/gridX**: 서비스가 `GridEncoder.decode(gridId)`로 산출(§D5) — `grids` 조인 불필요, gridId가 곧 인덱스라 수학적으로 정확.
- **coverThumbnailUrl**: 서비스가 `coverThumbnailKey`를 `ThumbnailUrlPresigner.presign(key)`(§D4)로 발급(null→null). 프로젝션 → `CollectionGridView`(gridY/gridX·presigned URL 채움) → 컨트롤러 `CollectionGridResponseDto.from`.
- **cover 영상 status**: `cover_video_id`는 재선정(MSG-72)이 ACTIVE만 가리키도록 유지하므로 status 필터 안 건다(불변식 신뢰, MSG-127 cover 선정과 동일).

### ②③ 단건 탐험률 (Owner A — `RegionStatsQueryServiceImpl`, `resolveByPoint` 재사용)

```java
// ② by-point
List<> findStatByPoint(userId, lat, lon):
    RegionView rv = regionQueryService.resolveByPoint(lat, lon)   // 좌표검증(6400)+단건 ST_Covers+no-match
        .orElse(null);
    if (rv == null) return null;                                   // no-match → 200+null
    return regionRepository.findStatByRegion(userId, rv.regionCode()); // region_stats equi + 0% 합성

// ③ by-grid
findStatByGrid(userId, gridId):
    GridPoint c = GridEncoder.center(gridId);                      // 중심점 = 155 축과 동일
    RegionView rv = regionQueryService.resolveByPoint(c.lat(), c.lon()).orElse(null);
    if (rv == null) return null;
    return regionRepository.findStatByRegion(userId, rv.regionCode());
```

**단건 stats 조회** — `RegionRepository`(native, **geospatial 0**):
```sql
SELECT
    r.region_code                              AS "regionCode",
    r.region_name                              AS "regionName",
    r.parent_code                              AS "parentCode",
    COALESCE(rs.collected_count, 0)            AS "collectedCount",
    COALESCE(rs.total_count, r.total_grid_count) AS "totalCount",
    LEAST(COALESCE(rs.progress_rate, 0.00), 100.00) AS "progressRate",  -- 0% 합성 + 156 D4 clamp (정정: 아래 이력)
    rs.updated_at                              AS "updatedAt"           -- 행 없으면 null
FROM regions r
LEFT JOIN region_stats rs ON rs.region_code = r.region_code AND rs.user_id = :userId
WHERE r.region_code = :regionCode
```
- **정정 이력 (2026-07-22, 구현 중 발견)**: 최초안은 `COALESCE(LEAST(rs.progress_rate, 100.00), 0.00)`이었으나 PostgreSQL `LEAST`는 NULL 인자를 **무시**하므로(`LEAST(NULL, 100.00) = 100.00`) 미수집 행정동이 100%로 합성되는 버그 — D6("0% 합성")과 정면 배치. `LEAST(COALESCE(...), 100.00)` 순서로 정정(테스트 `수집이_없는_행정동은_0퍼센트로_합성`이 검출).
- 귀속 geospatial은 `resolveByPoint` 안의 **단건 ST_Covers 1회**뿐(②는 현재 위치, ③은 격자 center) — 93 D1이 허용한 저빈도 단건 예외. 이 SELECT는 순수 equi.
- **축 일치 보증**: ③의 `resolveByPoint(center)`는 155 `refreshRegionStats`의 `ST_Covers(boundary, center) ORDER BY region_code LIMIT 1`과 같은 점·같은 규칙이라 귀속이 항상 일치(§D2).

### 조회 경로 ADR 정합
- 목록(①)은 geospatial 0. 단건(②③)은 요청당 point-in-polygon 1회(93 D1 예외) — 뷰포트급 루프 geospatial 아님. "조회/핫패스 geospatial 금지" 준수.

## 계약 변경

**크로스오너 계약 4종(`GridQueryService`·`HotZoneService`·`UserGridQueryService`·`UserOidcCommandService`) 중 A↔B 소비 시그니처는 불변.** 신설 계약 인터페이스 0(§D5).

- **`UserGridQueryService`에 메서드 1개 추가**(규칙상 계약 인터페이스 변화라 명시): `List<CollectionGridView> getCollectionGrids(long userId)`. **B 내부 read**(`CollectionController`만 소비, Owner A는 소비 안 함) → non-breaking. MSG-152가 세운 "개인 도감 read 서비스"에 갤러리 목록을 얹는 것이라 응집적. Owner A 확인은 **형식적**(A가 이 메서드를 쓰지 않음).
- `RegionStatsQueryService`(region 내부 read, 156 §D5로 **크로스오너 아님**)에 `findStatByPoint`·`findStatByGrid` 추가 — Owner A 자기완결, 상대 팀 확인 불필요.
- **신규 에러 코드 없음**: 목록은 도메인 실패 없음(152 D8과 동일), 단건은 6400(재사용)·no-match 200+null. `usergrid` 도메인 에러 대역은 여전히 미사용(생기면 5xxx 등 미사용 대역 — 이 티켓은 불필요).

## 테스트 시나리오 (JUnit5 + AssertJ · 한국어 백틱 메서드명 · 모듈 단위)

> **테스트 격리(MEMORY 'shared local DB' · 93/152/154/155/156 §격리 원칙)**: **합성 fixture만** 쓴다 —
> 자기 유저 신규 생성 + 합성 격자/영상(usergrid 축) + 합성 `region_code`(999 sido 대역, 실존하지 않음) + 소형 boundary 폴리곤 + `region_stats` **합성 row 직접 시드** + `@Transactional` 롤백.
